bug0: void treated as an empty Structure

Spec §2.2.2.6: void is semantic:none — no cell. Unit is an empty Structure
(`(): empty`). They are not the same. Confusing them would make an empty
Structure interchangeable with int / a missing cell.

Hosted trans now rejects a void local as a declarable cell:

    void: cell

trans exits 1: `void is not an empty Structure; it has no cell`.
A real empty Structure is a live arena object: graph header prefix + 0
payload (`LmLmxStructure *`, interned `lm_lmx_desc_Name`), not a dummy
`unsigned char lm_lmx_empty_structure` byte.

Destructor callbacks still receive `@: void object` (C `void *`) from the
own-stack. They recover a typed pointer by:

    entry: cast: (LmTransCallableProjectionCacheEntry) object

The same form is used for trans symbol/descriptor/field/relation, table
column/cell/row, and parser indent-stack destructors. That emits a pointer
cast (`T *`) when the type is reference-base. Mix pages (no
reference-base) still cannot use that converter; Mix stays on the old
projection until struct_refactoring Phase 9.1.

Confirming tests

    tests/trans_invalid_void_as_empty_structure.lm2
        trans rejects `void: cell` (exit 1). void is a primitive with
        semantic:none, no cell — not a declarable empty Structure.

    tests/trans_structure_graph_empty.lm2
        empty named Structure is an arena object; identity survives
        `return`; two instances are distinct.

    tests/trans_anonymous_structure_empty.lm2
        two `():` sites are distinct arena objects.
