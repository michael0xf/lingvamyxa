=====================================================

Purpose
-------
This file describes what Translator-L1 **actually does today**: accept /
reject rules, C99 lowering behaviour, and the two build routes below.
It is not a syntax textbook (see Lingvamyxa_spec.txt) and not a wishlist
(see L1_language_and_translator_spec.txt for the broader draft contract).

0. Product shape (fact)
-----------------------
Translator-L1 is a compile-time, syntax-directed lowerer from wrapperless
`.lm1` (and a temporary explicit-`L1:` `.lm2` compatibility route) to one
ANSI C99 translation unit per invocation.

It is **not** L2: no Lmx ontology, Message arena, runtime merge,
implements() predicate, hosted Namespace/descriptor tables, or
receiver.function / receiver.statement dispatch tables.

Similar receiver names do not make the two translators interchangeable.
L1's direct C member lowering is not the contract for resolving L2 paths
through an Lmx graph. L2 helper code written in .lm1 is still L1 input.

L1 prefix `@` is C address-of of that L1 binding (`tests/l1/expr_deref_read.lm1`,
`expr_deref_assign.lm1`: `p: @ value` → `&value`). L1 has no Lmx graph
payload and no own-field cache. L2 declared/through `@` matches this
C-parameter rule (Lingvamyxa_spec.txt 11.3.1). L2 own-field `@` names the
classified graph payload, not a cache, and does not replace this L1 profile.

P0 parser (parser.lm1 + p0.h + own.lm1) is reused; Translator-L1 owns
precedence / grouping / C image after the flat P0 field stream.

Build roots (current layout; staging is temporary isolation):
  l1src\            — WIP L1 sources (truth for ongoing work)
  lm1\build\        — tracked generated C for portable bootstrap
  stg\l1_baseline\  — independent build root with a frozen L1 copy
  stg\l1_baseline\l2src\ — live L2 kernel development written in L1

There is no root l2src\ in this layout. Root L1 changes do not automatically
reach the baseline compiler; tests and build outputs belong to their own
build root. Moving the L2 tree later is a separate decision.

The accepted second-translator pipeline is L2 → L1 → C. L2 is initially
implemented in L1; the target is L2-authored kernel sources and self-build.
L1 remains for its own intermediate translator, tests and generated
intermediate output, not as the permanent source language of the L2 kernel.
An expanded root L1 must pass self-build before promotion into the L2
build baseline; promotion must preserve the live L2 sources.


1. What the translator accepts
------------------------------
1.1 Source selection
  - Primary: file whose final extension is `.lm1` (case-insensitive).
    The P0 document root **is** the unit body: no outer `L1:` / `end: L1`.
  - Compatibility: `.lm2` only when an explicit `L1:` body is present
    (temporary bridge for the new translator; not L1 surface syntax).
  - Other extensions: rejected (`l1trans expects a .lm1 or .lm2 source`).
  - Empty / missing L1 body: rejected (`empty implicit L1 body` /
    `missing L1 body`).

  Header source units. IMPLEMENTED as of 8db63ee, by direct invocation only -
  see the scope note at the end of this entry, which is narrower than the
  feature sounds.

      source           name.h.lm1
      generated header name.lm1.h        (in the build output directory)

    The final extension stays `.lm1`, so the rule above is unchanged and the
    extension dispatch does not move. The `.h.` infix on the SOURCE selects
    header output mode. The `.lm1.` infix on the GENERATED file keeps its
    existing meaning - it marks an output, exactly as `name.lm1.c` does.

    The body is ordinary L1 with no wrapper receiver, by the same principle
    that makes a `.lm1` document root the unit body: no `h:` and no `L1:`.

    Body content admitted: `struct:`, `enum:`, `fnptr:`, `type:` scalar
    aliases, the `prototype:` WRAPPER form with `fn:`/`sub:` inside, a
    bodiless unit-level `fn:`/`sub:`, object-like `define:`, function-like
    `define:` (header units only; compact `NAME(params)` plus replacement),
    `include:`, and `[]` / `[][]` struct fields without initializer. Field
    spelling inside `struct:` is ordinary L1 declaration spelling, unchanged.

    Emission order: includes and defines in source order, then `type:`
    aliases, then ALL struct forward typedefs, then enums, then struct
    definitions and fnptr typedefs in a JOINT dependency order, then
    prototypes, then bodiless fn/sub. Forward struct declarations suffice
    for pointer references. Actual by-value fields and typedef dependencies
    must precede use; a by-value cycle is diagnosed by name rather than
    reordered into something that happens to compile. Scalar `type:` aliases
    are not joint-order dependencies. Covered by the H1 fixtures including
    hdr_alias / hdr_flmacro / p0.h.lm1; not a claim beyond that set.

    Remaining implementation debt, not language decisions: an inline
    prototype is silently ignored; lowercase unknown heads; fnptr-to-fnptr
    coverage.

    Guard: `LM_H_` plus an escape over the UTF-8 bytes of the source path
    relative to the unit root, normalized first and suffix included -
    `[A-Za-z0-9]` kept, `_` as `_5F`, anything else as `_` plus two hex digits.
    The escape is injective, so no collision check is needed. A path escaping
    the unit root is an error. Unit root defaults to the current directory;
    `--unit-root DIR` overrides it and is additive - two-argument invocation is
    unchanged.

    Rejected with a diagnostic naming the construct, publishing nothing:
    `union`, an executable body, leftover unit items that would otherwise be
    dropped (`unsupported header unit form`), and function-like `define:`
    in ordinary `.lm1` / `ifndef-default:`. Header units admit function-like
    `define:` as of 3f0e09d. No P0 syntax was added; live parser/bootstrap
    consumers still include handwritten `p0.h`.

    A rejected alternative is recorded so it is not revived: source
    `name.lm1.h` with a compound-suffix classifier. It would have required
    changing the final-extension rule and would have broken the invariant
    that `.lm1.` marks an output rather than a source.

    SCOPE. Direct invocation is implemented. 3f0e09d landed the first
    125700 source slice: `l1src/p0.h.lm1` as L1 declaration source, plus
    `type:` aliases and header-unit function-like `define:` so that
    inventory is not dropped. 489d3f5 landed `predef:` of a header source
    from an ordinary `.lm1` unit. cc4f511 keeps the generated include
    identity mirrored by the unit-root-relative source path
    (`tests/l1/hdr_dir_a/core.h.lm1` -> `#include "tests/l1/hdr_dir_a/core.lm1.h"`),
    so same-basename headers in different directories do not collide.
    Header-to-header `predef:` and header cycles are implemented
    (hdr_diamond_root, hdr_cycle_*). Imported struct/fnptr names from a
    valid included header count as already emitted for by-value
    dependency checks (5604bd8, hdr_diamond/holder.h.lm1); genuine local
    by-value cycles still fail. Repeated predef of one header is
    de-duplicated; a true diamond is root -> two headers -> common.
    7c2a8e2: buildCore header pass writes tracked `lm1/build/l1src/p0.lm1.h`;
    generate_all does not translate `*.h.lm1` to `.c`; live parser/own/
    parser_text `include:` `l1src/p0.lm1.h`; bootstrap compiles with
    `-I lm1/build`. Isolated POSIX next/check and STG promotion are still
    not claimed. System/vendor includes, qt_app, and mixa headers stay out
    of scope. Design inventory remains L1_header_units_draft.txt.

1.2 Unit-level items (l1_unit_item_ok)
  Top-level frames allowed in an implicit `.lm1` unit:
    include, import, predef, os, ifdef, define / ifndef-default,
    prototype, external, fn, sub, end, type,
    struct, enum, fnptr, union,
    declarations headed by @, @@, const, a known type name, c.array,
    or a head starting with `[]`.

1.3 Keywords / statement heads handled in lowering (l1_is_keyword + emit)
  fn, sub, external, include, import, predef, os, prototype,
  return, end, if, else, while, for, break, continue,
  switch, case, default, goto, throw, catch, finally, throws,
  plus L1/L2/L3 as reserved level names (not user identifiers).

  `do` is **not** implemented and is not reintroduced.

1.4 Declarations and types (implemented spelling)
  Known type atoms (l1_is_type_name / l1_write_type_spelling):
    int, void, char, size_t, unsigned, long, short, const, FILE, uchar,
    float, double, ulong → `unsigned long`,
    u8/u16/u32/u64 → uintN_t, i8/i16/i32/i64 → intN_t,
    plus several LmP0* typedef names used by the parser port.
  `uchar` is emitted unchanged, not rewritten to `unsigned char`:
  include a header defining it (cast_uchar_alias_ok uses l1src/p0.lm1.h).
  Fixed-width C names likewise require their C declarations/headers.
  Pointer forms: `@:` / `@@:` (and deeper `@` chains in tests).
  In expression position, a `@:` / `@@:` frame whose body is a type
  spelling lowers through `l1_emit_type_token` (`char *` / `char **`).
  `c.sizeof(@: char)` therefore emits `sizeof(char *)`, not
  `sizeof(&char)`. Unary `@ x` remains address-of (`sizeof(@ x)` →
  `sizeof(&x)`). Tests: sizeof_ptr_type.lm1, sizeof_addr.lm1.
  Compact `c.foo(...)` is one P0 ATOM. A nested L1 receiver inside
  that atom is rejected (`compact c. call cannot contain a nested
  L1 receiver`) when `:` is not inside a string/character literal
  and is not a C ternary colon matched to `?` at the same paren
  depth. `c.sizeof((cast: (unsigned) 0))` is that form; it is not
  lowered into C. Colons in ordinary compact C stay accepted:
  `c.sizeof(("x:y"))`, `c.sizeof(("cast:"))`, `c.sizeof((':'))`,
  `c.sizeof((1 ? 2 : 3))` / `c.sizeof((1 ? a : b))`. Other compact
  calls without a nested receiver still emit after stripping `c.`
  and mapping `\` (`c.sizeof(x\field)` → `sizeof(x->field)`).
  Vertical `c.sizeof:` with an empty colon is P0 error 32, not this
  diagnostic. Tests: invalid_sizeof_cast_compact.lm1,
  sizeof_str_colon.lm1, sizeof_char_colon.lm1, sizeof_ternary.lm1.
  Array forms:
    - `[]: T name N …` one-dimensional extent + initializer (decl-repeat
      and scalar suites). Consecutive type-name atoms are gathered as
      the element type, same rule as casts/pointer parameters:
      `[]: unsigned short arr 2` → `unsigned short arr[2]`, not
      `unsigned short[arr]`. Array parameters `[]: unsigned short
      values` gather the same way. Single-token aliases (`[]: int`,
      `[]: uchar`) unchanged. Scalar `unsigned short: v` remains
      unsupported (`unsupported statement atom`). Test:
      array_multiword.lm1.
    - `[][]: int matrix 2 2` declares a rectangular two-dimensional
      C array (array_2d.lm1). This is one contiguous block, not an
      array of separately allocated rows. Broader declaration forms
      remain bounded by the fixtures; see draft 10.15.
    - Bootstrap `c.array:` / `const: … c.array:` (run_c_array.ps1).
  Declaration repeat: `int: x, 5; y, 10` and paren / pointer / `[]`
  repeats (run_decl_repeat.ps1). Explicit type override is per-item.
  Identifiers: optional outer backticks strip to the C name
  (run_ident.ps1); quoted string backticks stay data.
  `const` on declarations / parameters / c.array elements as covered
  by scalar and c_array suites.
  `immutable:` compile-time grouping receiver (not L2 RuntimeImmutable).
  Each declaration in its vertical (or compact) body is emitted as the
  existing L1 `const:` qualifier would emit that declaration. Pointer
  depth matches `const: @(T p)` → `const T *p` (referent, not a const
  slot): rebinding `p` is allowed, writing through `*p` is not.
  Nested `immutable:` / `const:` / `c.array:` unwrap to one C `const`
  (`const const` is not emitted). Siblings outside the body stay
  mutable. `[]:` / `[][]:` use `l1_emit_bracket_array` (not a type-
  spelling data_decl). Repeated names reuse the ordinary block inherit
  loop so tails and initializer order survive. `end:immutable` is
  validated; a mismatched `end:` is an error. Unsupported children
  (control flow, assignments, `fn`/`sub`) diagnose
  `immutable does not qualify this form`. Does not distribute over
  parameter lists (that ambiguity stays OPEN). Compact
  `@(int p) @ cell` as two sibling fields is not a pointer declaration
  with initializer; spell `@: int p @ cell` so the initializer stays
  in the declaration frame. Example:

    immutable:
        int: a 2
        const: @(char s) "hi"
        immutable: int: d 5
    int: e 6

  emits `const int a = 2; const char * s = "hi"; const int d = 5; int e = 6;`.
  Write-negatives fail gcc with `read-only variable` / `read-only`
  (not discarded-qualifiers). Header-field grouping: `immutable:`
  inside a `struct:` body emits `const` fields; siblings stay mutable
  (hdr_immutable.h.lm1 + initialized/runnable C consumer). Header
  pointer fields follow the same referent contract: `immutable: @: char
  name` → `const char * name` (slot may be rebound; contents are
  const). Nested header coverage: hdr_immutable_nested.h.lm1 (by-value
  Inner before Outer despite source order; nested immutable sibling
  stays qualified; const-wrapper not last in the block). Tests also:
  immutable_group.lm1, immutable_array.lm1, immutable_repeat.lm1,
  immutable_nested_const.lm1, immutable_ptr.lm1, immutable_end.lm1,
  immutable_file.lm1, immutable_order.lm1, invalid_immutable_if.lm1,
  invalid_immutable_write.lm1, invalid_immutable_array_write.lm1,
  invalid_immutable_ptr_write.lm1, invalid_immutable_end.lm1.
  Core adoption (actual `immutable:` use, not tests only):
  l1src/l1trans.lm1 (usage / --unit-root strings), l1src/printTree.lm1
  (usage string), l1src/build_l1.lm1 (gcc flag table). Reviewed and
  left mutable: parser.lm1 / own.lm1 allocator and parse state;
  p0.h.lm1 struct fields (counts, pointers, flags); make.lm1 /
  finalize.lm1 / buildCore.lm1 command buffers, env lookups and
  counters; libc_abi.lm1 / add.lm1 (parameter lists only — immutable
  does not distribute over parameters). Current l1src is translated
  from the tracked portable C bootstrap (`gcc lm1/build/l1trans.lm1.c`),
  not from the historical lm2 gen0 seed. STG final promotion and label
  syntax remain pending.
  `prototype:` and `external:` (external body must contain fn/sub).
  `sub:` — function without return-type slot (diagnostics distinguish
  it from `fn`). An empty sub is a definition, not just a prototype:

    sub: sample_entry ()
    end: sample_entry

  This gen1+ regression is exercised by empty_sub_ok.lm1.
  Function close admits `end:<name>` (canonical), `end:fn`/`end:sub`
  (receiver/head), a terminal `return:` trailer, or `---` as a
  multi-level tail cutter. Bare `end` is separately forbidden. Empty
  `end:` is a current-P0 syntax error (general empty-colon rule
  below), not a complete special case. Wrong target/arity remain
  diagnostics. Tests: fn_close_*.lm1, invalid_fn_end_wrong.lm1,
  invalid_fn_end_empty.lm1.

1.4.1 Colon vs nullary (current P0 syntax)
  A colon Frame with no argument fields after complete inline/vertical
  body assembly is a P0 syntax error, independent of receiver name.
  L1 inherits this from the current parser; it is not a translator-only
  workaround.

  Bare `f` is an identifier. Compact `f()` is an allowed empty compact
  Frame. `()` is an allowed empty bounded Structure. `f:` plus a
  nonempty vertical body is not empty. Empty same-line tail is not
  emptiness when vertical children exist. Exact valid spelling:

    fn: test () int
    return:
    . 5 + 5

  A colon Frame whose body contains an explicit `()` has a Structure
  field, not zero P0 fields.
  Colon-empty specialized trailers (`return:`, `end:`) are the same
  P0 error. Bare `return` / `break` / `continue` remain admitted in
  their existing contexts. Bare `end` stays separately forbidden.
  Quoted or commented ':' is not an executable Frame. Historical
  620db86 P0 still accepts `tests/empty_colon_frames.lmx`; that is
  versioned old-P0 acceptance, not current admission and not a port
  regression. Frozen STG P0 is not silently edited; root first, then
  a narrow coordinated promotion so L2 consumes the same rule.

1.5 Control and expressions (covered by runners)
  if / else, while, for (C-style three-slot header as in for_loop.lm1;
  compact hosted for-sugar is established in the draft; L1 for-init
  rejects unsupported forms).
  break, continue.
  switch / case / default with end: matching; cases lower with a null
  statement after the label so a following declaration is C99-legal;
  no implicit break between cases (fall-through is C-like).
  Ordinary zero-argument calls in statement position: visible 0-arg
  fn/sub as bare identifier `done` or compact `done()`. Both emit
  `done();`. They are not C labels. `goto: done` still emits
  `goto done;` (transfer). Empty `done:` remains P0 error 32
  (generic empty colon), not a label declaration. L1 C99 currently
  has no admitted source spelling for a goto *target* under that
  empty-colon rule; do not invent `done:()` or bare-name-to-label
  detection. Visibility/arity/throw lookup is a source-sized table
  (grows; not a fixed 32-entry cap), filled by a declaration prepass
  so a later or forward 0-arg name matches compact `f()`. A bare
  name of a visible nonzero-arity fn stays `unsupported statement
  atom`; compact `f(...)` is still a call. Tests: control_nullary.lm1,
  control_nullary_many.lm1, invalid_nullary_arity.lm1; obsolete
  control_goto.lm1 is the empty-colon negative. `goto: L1` is still
  `reserved L1 name`.
  Labels + goto (C99 labels) as previously documented; empty-colon
  `name:` is not a legal label form on current P0.
  throw / catch / finally / throws:
    - static `l1_throw_code` + `long l1_throw_payload[8]` channel
      (not a union);
    - catch pads via goto labels; handled catch clears the code;
    - payload arity ≤ 8; accepted types: int, unsigned, long, short,
      size_t, char. Other types, including uchar, float and pointers,
      are rejected (`unsupported throw payload type`);
    - main cannot declare throws; uncaught throw must be in throws set;
    - throwing call only as statement or entire assignment RHS.
  Expressions: nested calls, binary/unary ops, parentheses, casts
  (`cast: (T) e` and related), prefix `\` dereference, prefix/postfix
  ++/-- , indexing, field-follow, string forms (quoted, triple, fence)
  as exercised by run_expr.ps1. Infix / relational context, bare `=`
  in the hosted/L1 operator path emits C `==` (see emit sites writing
  "=="). Shift operators covered by shift_ops.lm1.
  `os: win: / default:` selects a Windows branch on this host
  (os_select.lm1).

  Multiword cast targets are supported in the reviewed root compiler:
    (cast: (unsigned char) ch)
    (cast: (unsigned long) 42)
  See cast_multiword_ok.lm1; cast_ptr_uchar_ok.lm1 covers pointer casts.
  These fixes are not in the old hosted gen0 or the frozen baseline.

1.6 Modules / import / include / define / ifdef
  include: string header → C `#include <…>` or `#include "…"` (decoded
  P0 string; never `#include "<stdio.h>"`).
  import / predef: string path(s); diamond and repeat OK; cycles and
  missing files diagnosed; bare-directory import covered by
  run_import_bare.ps1 (incl. paths with spaces).
  define: object-like macros (empty / token / string / char / arithmetic
  replacement); ifndef-default preserves command-line -D including 0.
  ifdef: condition / default branches, nesting, unit and function
  contexts, matching end:; undefined FLAG and -DFLAG=0 take default;
  -DFLAG=1 takes first branch (run_ifdef.ps1).
  Function-like macros in ordinary `.lm1` units, hosted table commands,
  and define inside function body are outside the current ordinary-unit
  define checkpoint. Header units admit function-like `define:`
  (`hdr_flmacro.h.lm1`, `p0.h.lm1` `LM_UNUSED`).


2. What the translator rejects (by fact of diagnostics)
-------------------------------------------------------
Representative diagnostics from l1trans.lm1 (non-exhaustive; full set is
the unique l1_error string list in that file):

  Profile / structure
    unsupported L1 form; unsupported statement atom; unsupported
    expression node; unsupported type; unsupported initializer;
    unsupported for-init; implicit L1 expects a statement frame;
    empty implicit L1 body; expects a .lm1 or .lm2 source; missing L1
    body; reserved L1 name (C / L1 / L2 / L3 heads as identifiers or
    explicit level frames inside `.lm1`, e.g. invalid_lm1_explicit_l1,
    invalid_control_goto_l1); nested / wrong-level fixtures under
    invalid_lm1_*, invalid_nested_l1.lm2, invalid_no_l1.lm2.

  Declarations
    missing / empty type or name; unknown type name (unrecognised
    Capitalized declaration head, including c.Capitalized); array
    missing extent; c.array shape
    errors; repeated-declaration reset / disabled / missing-extent;
    const missing type; pointer / array parameter shape errors;
    external without fn.

  Control / throw
    switch without body; duplicate default; case/default outside
    switch; case expects an expression; end target mismatch;
    goto arity/name errors; throw/catch/finally/throws rule set as in
    run_control.ps1 negatives.

  Import / define / ifdef
    import cycle / cannot read / path issues; define / ifndef-default
    name and token errors; ifdef branch/end/default placement errors.

Failed translations must not publish a new output `.c` or overwrite an
existing output (negative/preserve-output checks in the runners).
The unknown-head guard is not a complete C type checker.


3. Lowering model (C99 image)
-----------------------------
Direct, local mapping — maximize straight ANSI C99:

  Frame head → construct (fn → function def, if → if, …).
  Declarators → C declarators; `@` depth → `*`; `[]` / c.array →
  rectangular C arrays (contiguous row-major; not L2 Array ontology;
  not rank-1 flatten; not ragged row pointers) for the shapes that
  currently lower.
  Prefix `@x` → `&x` of that L1 binding (matches L2 parameter `@`;
  not L2 own-field payload `@`, Lingvamyxa_spec.txt 11.3.1).
  Prefix `\p` → `*p`; field-follow `p\field` → `p->field`.
  Ordinary aggregate traversal is by address: no Valued aggregates,
  no ordinary `.` member access, and no contextual choice of `.` or `->`.
  Explicit C projection `c.value.field` emits `value.field`; it is
  distinct from the reserved receiver `C:` and from ordinary `\`.
  include → `#include`.
  define → `#define` object-like; ifdef → `#if` / `#elif` / `#else`
  family as emitted by the current path.
  import/predef → parse and inline/merge imported L1 units into the
  translation (cycle-checked); exact multi-TU emit policy is OPEN
  (draft 10.8) — current CLI writes one output path per run.
  throw/catch/finally → internal static channel + gotos/labels, not
  C++ exceptions and not setjmp in the checked fixtures.
  Strings: deterministic C string/character literals from P0 spans;
  fences keep provenance across imports; full ordinary-string
  recanonicalization and byte-blob decls are **not** claimed
  (README / draft 10.19).

Strict consumer compile flags used by new-gen runners:
  -std=c99 -Wall -Wextra -Wpedantic plus
  -Werror=incompatible-pointer-types -Werror=discarded-qualifiers
  -Werror=implicit-function-declaration -Werror=implicit-int
  (control suite also enables int↔pointer cast errors).

From tests/l1/array_2d.lm1 (inside main):

  [][]: int matrix 2 2
      []: 1 2
      []: 3 4
  matrix[1][1]: 9

The fixture checks both dimensions with sizeof and reads/writes elements.


4. Self-build / generations (fact)
----------------------------------
4.1 Published-C bootstrap and native staged self-build

From the repository root, buildCore.lm0.bat (Windows) or
buildCore.lm0.sh (POSIX) compiles the tracked lm1/build/*.lm1.c snapshot
into build/lm0 tools: l1trans, make, finalize and buildCore. This bootstrap
does not require the old hosted translator or its parser/own archives.
It does require a C99 compiler; the root Windows script also uses CMake
for directory creation (LM_CC / LM_CMAKE select the tools).

Run build/lm0/buildCore.lm0.exe (suffixless on POSIX) for native self-build:
  - translate l1src and regenerate the seven published C sources;
  - build replacement tools under build/lm0/next;
  - run the next builder with --next, producing next/check;
  - run the selected staged tests and defer installation to finalize.

The seven sources regenerated by this route are buildCore, finalize,
l1trans, make, own, parser and printTree. Other tracked C files in
lm1/build (such as trans and REST examples) are not in that set.
Only the first four tool sources named above are direct bat/sh inputs;
own, parser and printTree belong to the later staged build. All seven
are published snapshots, not disposable outputs to omit from that release.
The implementation is l1src/buildCore.lm1 + finalize.lm1. Staged builds
also produce local parser/own libraries; root bootstrap scripts no longer
overwrite the old hosted archives in build/lm0 (d2dc0b3).
However, native finalize installs its new parser/own archives and printTree
into build/lm0. Preserve the independent hosted parser oracle separately;
restore the pinned hosted-ABI prerequisites before returning to run_seed.
Do not mistake the newly installed L1 archives/oracle for the old hosted ones.
The optional --full Qt/CMake route is separate from the basic L1 gate.

4.2 Hosted seed and generation regression route

This is a second route, not a prerequisite of the published-C bootstrap:

  1) tests\l1\run_seed.ps1
       stage-0: build\lm0\trans.lm0.exe on lm2\l1trans.lm2 → seed C,
       link with libparser/libown → published build\l1trans\gen0\l1trans.exe
       after translating/compiling/running tests\l1\integer_add.lm1.
       Does not treat a pre-existing gen0 exe as success.

  2) tests\l1\run_gen.ps1
       gcc tracked lm1/build/l1trans.lm1.c → boot exe (no preexisting
       L1 binary); boot → gen1 → gen2 → gen3; requires gen1 C == gen2 C
       == gen3 C; L1 builder selftest; bootstrap gen3 tools; re-runs
       smoke + parser with L1_GEN=gen2. Hosted gen0 from run_seed is
       not used to parse current l1src.

Layout:
  build\l1trans\gen0|gen1|gen2|gen3\   executables
  build\obj\l1trans\gen<N>\            generated C / objects
  build\l1trans\logs\                  seed/gen/suite logs
  build\l1trans\oracles\               printTree.lm0 dumps

Real L1 source of the translator: l1src\l1trans.lm1.
lm2\l1trans.lm2 is only the explicit stage-0 mirror.
port_*.py are manual migration helpers, not part of native self-build.

Hosted-route prerequisites: gcc; PowerShell;
build\lm0\trans.lm0.exe + libparser/libown; lm2 registry/predef files;
lm1\ includes for the seed gcc line; printTree.lm0.exe for parser oracle.
The archives must match the old hosted ABI, not the new standalone L1
parser/own ABI. A clean Git checkout does not supply all these hosted
binaries. The baseline keeps a local oldchain copy for its own gate.

gen0 is built from lm2/l1trans.lm2, not l1src/l1trans.lm1. It therefore
does not acquire new root fixes automatically. run_smoke explicitly skips
the new unknown-type, size_t, empty-sub and cast fixtures on gen0; gen1+
runs them. A gen0 skip is not evidence of implementation support.

Gate vs standalone suites:
  Driven by run_gen (with L1_GEN=gen2 for smoke/parser): run_smoke,
  run_parser (plus the gen fixed-point itself).
  Standalone (documented, not automatic run_gen gate): run_expr,
  run_ifdef, run_define, run_scalar, run_decl_repeat, run_ident,
  run_c_array; also present: run_control, run_import_bare.

4.3 Frozen-baseline gate and verification scope

stg/l1_baseline/gate.ps1 runs in that separate root: its C bootstrap,
run_seed, run_gen, all eleven L1 suites and l2src/run_lmx.ps1 on both
gen0 and gen2. After 9638523 it tests the promoted 840c414 translator
slice plus that root's current L2 code. It still needs hosted
prerequisites (oldchain libs, pinned trans.lm0/printTree.lm0). It does
not run native next/check/finalize.

Source-only published-C bootstrap → native buildCore --tests full →
next/check → second live self-build + deferred finalize was proven in
isolated copies of the root tree (Windows and Ubuntu WSL;
20260908-093900 / 095100). That path is not part of this hosted gate.

The ecf010e staged snapshot already includes the OS-specific
l1_replace_file helper. Claims of bootstrap, hosted fixed point and
full-suite success must identify which route, build root and revision
were actually checked.

PARTIAL / LIMITED

  (draft 10.15).
  decl_repeat for arrays: 1-D `[]:` only (README).
  String lowering: fences/quotes/triples covered; full recanonicalization
  and byte-blob decls not claimed.
  Module emit: one output C path per CLI run; multi-TU / init-before-main
  mechanics OPEN (10.8).
  Conditional-import policy outside ifdef checkpoint.
  Header units: direct invocation, including `type:` aliases and
  function-like `define:` in header units (3f0e09d). Ordinary-unit
  `predef:` of a `*.h.lm1` source emits one include of the generated
  header, mirrored by source path, and registers its type names
  (489d3f5, cc4f511; hdr_predef_consumer, hdr_dir_both,
  hdr_diamond_root). Repeated predef is de-duplication, not diamond
  coverage. `l1src/p0.h.lm1` exists as L1 source; live parser/bootstrap
  still include handwritten `p0.h` only where tests name it. 7c2a8e2
  added the buildCore header pass and tracked `lm1/build/l1src/p0.lm1.h`;
  live parser/own/parser_text include that generated header. Isolated
  POSIX next/check and STG promotion are not claimed.
  Parameter declarations, two confirmed defects, BOTH FIXED in c8ceb67 and no
  longer reproducible; retained here only as the record of what they were:
    - a multiword type after `@:` yields a mangled type and DROPS the
      parameter name. `@: unsigned char p` emits `unsigned * char`; the same
      for `unsigned long` and `const char`. A single-token alias is fine:
      `@: uchar p` emits `uchar * p`. The emitter takes one type atom and
      treats the next as the name. Same shape as the cast defect already
      fixed in l1_emit_cast, which gathers consecutive type-name atoms.
      `[]:` declarations had the same one-type-atom hole
      (`[]: unsigned short arr 2` → `unsigned short[arr] = {2};`,
      EXIT 0, invalid C); l1_emit_bracket_array and `[]` parameters
      now gather consecutive type-name atoms (array_multiword.lm1).
    - a qualifier parameter that is not last silently loses the rest of the
      list. `(const: @: char text; unsigned: fg)` emits
      `(const char * text)`. This one is NOT a parse defect: printTree shows
      the list holds one field and `unsigned: fg` is the second field of the
      `const:` body, because the `;` closes the nested `@:` frame rather than
      the qualifier. The tree is correct per P0; the emitter drops the tail.
      The paren form `const: @(char text); unsigned: fg` is unaffected.
      Emitting the tail as further parameters would silently change what the
      source means, so the fix is a diagnostic, not a wider parse.
  Platform and clean-checkout coverage depend on the build route (§4).
  Full draft-contract coverage is not claimed.
