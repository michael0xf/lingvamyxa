Lingvamyxa L1 Language and Translator — Draft 1
==============================================

Status: Draft 1, working language contract. Architectural basis:
accepted Revision B (work_chat/grok/outbox/20260906-161525.txt) plus
the user decisions recorded in work_chat/grok/inbox/.

This is a draft normative assignment, not yet an amendment of
Lingvamyxa_spec.txt. Where the two disagree about L2, the published
Lingvamyxa_spec.txt and struct_refactoring_version_2.txt win.

Translator-L1 development is under way in `main`. Baseline commit
620db86 is the read-only syntax/C-like template only; it is not a
Translator-L2 architecture source.

Words MUST / MUST NOT / SHOULD / MAY are normative for L1 and
Translator-L1. Items marked OPEN in section 10 are not decided; a
slice MAY lag a contract feature without removing it (section 0).

Closed decisions (do not reopen)
--------------------------------
  - Parser/P0 is reused.
  - L1 lowers directly to equivalent ANSI C99.
  - Established receivers and modules remain in L1. L1 is a full
    language, not a disposable subset.
  - Final extension `.lm1` selects this language. The file root is its
    L1 body; no outer `L1:` / `end: L1` is written. Do not introduce
    `.l1` or replace L1 source with raw `C`.
  - Receiver `C` is an isolated last-resort hatch. Ordinary
    translator / runtime / bootstrap MUST NOT contain it and MUST NOT
    depend on raw-C payload.
  - Two separate translators: Translator-L1 and Translator-L2.
  - Translator-L2 backend route is non-semantic: MAY emit L1 text,
    MAY use a shared L1 emitter/IR API, MAY emit C99 directly. Same
    L2 input ⇒ equivalent L2 semantics and ABI. None of these MAY
    reuse the hosted trans_l1_* semantic core as foundation.
  - Do not lock “L2 must go through L1”.
  - Seed/self-host (was OPEN 10.6): Translator-L1 is **not** written
    by hand as raw C. Suitable C-like sources are moved with minimal
    semantic change to wrapperless `.lm1` and form the self-host spine.
    The explicit `.lm2` seed mirror is only the stage-0 bridge.
  - Array physical model (restored language invariant, not a new
    invention): rectangular rank-N C array, one contiguous backing
    block in C row-major order. Not L2 Array ontology. Not rank-1
    flattening. Not a ragged row-object tree.
  - `include:` decodes the P0 string atom, then emits a C `#include`
    form (`<stdio.h>` or `"local.h"`). Never `#include "<stdio.h>"`.

Spellings marked OPEN or PROPOSED are not decisions. Established
spellings are cited from current sources and from the Claude/Cursos
audits named below.

1. Target-language contract of L1
════════════════════════════════════════════════════════════════

1.1 Character

L1 is a Lingvamyxa source profile. Surface syntax builds generic
Structures. Receivers consume those Structures and assign meaning.
For L1 that meaning is ANSI C99: translation units, types, objects,
functions, expressions, control, linkage.

L1 is not L2: it has no Lmx ontology, no Message arena, no runtime
merge, no reserved `node` argument, no all_methods_array, no
implements() as L2 predicate, no hosted Namespace/descriptor/class
tables.

L1 is not “C keywords in colon form”. Receiver is the structural
mechanism (1.3). Modules are part of the language (1.4).

1.2 Profile spelling: `.lm1`

An `.lm1` source is one implicit L1 unit. Its P0 document root is the
unit body; it has no outer level Frame. Final-extension matching is
case-insensitive and is not inferred from a receiver in the file.

Translator-L1 MUST reject explicit `L1:`, `L2:` and `L3:` level Frames
inside an `.lm1` unit, including nested bodies, and MUST reject unsupported
top-level material instead of silently emitting an empty unit. The current
self-host/bootstrap profile also rejects `C:`; only a separately enabled future
hatch may admit it under 1.9. The temporary explicit-`L1:` `.lm2` route is a
backward-compatibility path of the new translator, not L1 source syntax or the
old stage-0 seed route. Other extensions do not select either route.

L1 need not formalize every declaration category as one namespace. Nevertheless,
`C`, `L1`, `L2` and `L3` are reserved across all L1 name categories: source may
not declare, shadow or reuse any of them as a variable, function, module,
receiver, macro/condition or other user-defined name. A reserved receiver that
an enabled profile admits is the only use of that spelling.

`tests/l1/lm1_unit.lm1` is the minimal source shape:

    external:
        fn: main () int
            return: 0
        end: main
    end: external

Hosted trans.lm0 today dumps `L1:` string atoms as C text. That is
legacy behaviour of the old translator, not L1 language. Five test
files still use the dump (section 7.3). They stay hosted-trans tests.

Translator-L2 separately consumes `.lm2` / `.lm3` roots. Mixed level
siblings do not turn an `.lm1` file into a multi-profile container.

1.3 Receivers

A receiver is not a parser keyword
(Lingvamyxa_parser_P0_receiver_abi.txt). P0 builds a Frame:

    head  = receiver spelling (LmP0Text)
    body  = argument Structure
    trailer = end:/return:/until:/…

Semantic roles (for `fn`: name, args, ret, body) are assigned by the
**compile-time** consumer of that Frame, not by P0.

L1 keeps this structural Frame/receiver/module skeleton. It MUST NOT
grow a generic **runtime** receiver protocol, Lmx dispatch,
Message routing, or hosted Namespace/descriptor/registry ontology.

For Draft 1 / first Translator-L1, a receiver is a **compile-time
syntax-directed construct** (prelude head, or a name exported by an
imported L1 module as an ordinary declaration). Translator-L1 matches
the Frame head and emits the C99 image in this file. That is not a
proof that L1 requires a dynamically extensible runtime receiver
environment, nor that every receiver is an arbitrary user-supplied
lowering function.

A Frame whose head is unbound after prelude + `import:`/`predef:` of
the unit is a diagnostic. That is “unbound in this unit”.

How (or whether) L1 later lets a program **author a new receiver
lowering** is OPEN (10.3) and is **not** required to start S1. Do not
treat hosted `receiver.function` / `receiver.statement` tables as L1
ontology.

Prelude receivers with **established source spellings** (current
lm2 sources, spec, trans_registry.lm2 namespace table). All belong
to the L1 **contract** unless the user excludes one:

    fn, sub, return, external,
    include, import, predef, define, ifndef-default, ifdef, os,
    if, else, while, for, break, continue,
    goto (labels + `goto:`),
    cast,
    throw, catch, finally, assert

Cursos map (work_chat/cursos/outbox/20260906-161525.txt):

    no `module:` token; a module is a file
    import:  / predef:  path-list of string atoms; optional end:
    include: ≥1 string header atoms
    external: wraps exactly one fn/sub; end: external

L2-profile heads (`table`, `join`, `merge`, `L2`, `L3`, `implements`
as L2 predicate, Mix) are **not** L1 meaning. In an L1 unit they are
unbound or explicitly rejected.

C aggregates (struct/union/enum/typedef) MUST exist in L1 semantics
(C99 types). The **head words** `struct:` / `typedef:` are OPEN
(10.4). Do not treat them as decided. Hosted `Point:` named-Structure
and `c.struct:` are not adopted as L1 spelling by this draft.

1.3.1 Low-level surface forms (syntax-directed C99)

These established Lingvamyxa surface forms stay in L1 because they
map **locally** to C99. They are not a runtime protocol.

`@` — pointer / address (two P0 contexts; do not unify into Lmx):

    Declaration (established in lm2 sources):
        @: T name      →  T *name
        @@: T name     →  T **name
        const: @: T p  →  const T *p
    Unary on a value (hosted L2; L3 forbids it,
    trans_l1_expr.lm2:5372 “raw address-of @ is not available in L3”):
        @ x            →  &x
    OPEN (narrow): whether L1 keeps unary `@` as `&`. Do not invent
    a third “address object” kind.

`\` — prefix dereference or field-follow, according to position:

    Prefix `\p` → C `*p`, `\\pp` → `**pp`, with C99 precedence.
    Assignment heads follow the same rule: `\slot: 1` → `*(slot) = 1`.
    See `tests/l1/expr_deref_assign.lm1`, ported from the frozen
    `tests/trans_deref_assignment_target.lm2` regression.

    Field-follow in body atoms (P0 splits to "a" "\\" "b"):

    Syntax-directed C99 member access, not an Lmx path protocol.
    Field-follow `p\field` emits C `p->field`. No Valued aggregates
    or ordinary `.` member access, including in L1: traversal is by
    address, not an implicit aggregate-by-value route. The
    translator does not choose `.` versus `->` from contextual types.
    Explicit C projection `c.value.field` emits `value.field` and is
    distinct from ordinary field-follow and the reserved receiver `C:`.
    This settles the former question 10.9; see L1_spec.txt for current
    implementation evidence and the root/frozen-baseline distinction.

    Frame **head** `a\b:` keeps `\` inside the head spelling (1.8).

Strings and comments (Claude 162853; P0 keeps exact source
bytes/spans; Translator-L1 emits deterministic C99, no L2 string
ontology, no receiver `C`):

    `"..."`  ATOM including quotes. C99 escapes in source. Unescaped
             newline is parse error 19. No adjacent concatenation
             (`"x" "y"` = two atoms). Decode C99, re-emit as **one
             canonical C99 string literal** when used as an
             expression string value. Payload bytes MUST NOT gain a
             terminal newline for formatting.

    `'x'`    C99 character constant (integer), not a string.

    `"""`/`'''`  ATOM including delimiters. Payload raw (backslash
             is a byte). Physical newlines kept, including a newline
             immediately before the closer. Quote-run shortening per
             spec. Decode: strip 3+3 quotes only.

    `===`    ATOM. Column-0 `=` fences 3..80; fence lines not payload.
             Parser strips **exactly one** line terminator before the
             closing fence. Triple-quoted does **not**. L1 MUST follow
             that parser contract; MUST NOT add a terminal newline to
             the **value**. (Emitting an extra `\n` into a generated
             *file* is not changing the string value.)

    Expression string value (all of `"..."`, `"""`, `===` in expr
    position): one canonical C99 representation — a string literal
    with full escaping of `"`, `\`, newline, CR, NUL (`\0` / `\xHH`).
    A **byte-blob declaration** (explicit length, NULs) is a separate
    low-level form. Exact declaration spelling OPEN (10.19) if not
    established on the GOOD baseline.

    `#` line comments and `***` blocks: **not** P0 nodes, not runtime
    values. MAY be dropped in C output. If kept, source-trivia copy
    from neighbouring spans (`/* */`, escape `*/`) — not an AST.

    `%` disabled: INACTIVE placeholder, no value, emit nothing
    (optional trivia comment only).

1.4 Modules

Mandatory language, not an optional extra.

    A program is one or more L1 units.
    `import:` makes the imported unit’s declarations and exported
    receivers available (spec 19.23.2 analogue: does not copy a
    runtime namespace).
    `predef:` is a hoisted import (established: declarations visible
    before later top-level items).
    `include:` is `#include` of a C header (1.6).
    `external:` marks external C linkage of one fn/sub.

OPEN are only **mechanics** (10.8): .c-per-unit vs concatenation,
header generation, path identity, init-before-main. The language has
multi-unit regardless.

Atom `unit` / `unit.payload` is L4/registry in the hosted translator
(Cursos). It is not adopted as an L1 filesystem module. OPEN whether
L1 mentions it at all.

1.5 Types, objects, functions (C99 image)

L1 types **are** C99 types: void; the standard integer and floating
types; `_Bool`; pointers; arrays; function types; struct/union/enum;
qualifiers; typedef.

Established **direct** declarator shapes (Claude
work_chat/claude/outbox/20260906-162454.txt; P0 then C99). These
are L1 surface, not hosted tables:

    T: name                      T name;
    T: name init                 T name = init;   (init = remaining
                                                   fields; not a MIX `{`)
    const: <declaration>         wraps the inner declarator
    @: T name   /  @(T name)     char *name;      (same P0: F"@" S(2))
    @@: T name                   T **name;
    @: T                         T *   (nameless type/return: F"@" S(1))
    const: @: T name             hosted convention const T *name
                                 (not T *const — OPEN 10.13)
    fn: name (params) ret body   definition (4 fields; body is last S)
    fn: name (params) ret        prototype (3 fields, no body)
    prototype + fn: …            established atom `prototype` wrapping
                                 a 3-field fn (same prototype meaning)
    sub: name (params) body      void procedure (no ret slot)
    external: + one fn/sub       C external linkage
    (T: n) / T(n) in param list  typed parameter
    ;;                           POSITIONAL_SKIP

Declaration vs later assignment (established, keep):

    int: x 1     declaration + initializer
    x: 2         assignment to existing x

`fn` / `sub` parameters are typed Structures. MUST NOT inject
LmMessageThread. Empty param list `()` is P0 S(0) → C `void` in
the parameter list for a definition (C99).

Return descriptor slot is polymorphic in P0 (bounded S(1) `int`,
bare atom `void`, Frame `@: char`, …). Translator-L1 MUST accept
those established shapes and reduce them to one C type. Protocol
returns such as `iterator(Text)` are L2, not L1.

Established `main`:

    fn: main () int
    fn: main (int: argc; @@: char argv) int

→ `int main(void)` / `int main(int argc, char **argv)`.

Arrays: Translator-L1 MUST NOT port L2 Array module/runtime/ontology
(`lm2/mix/Array*` and hosted ArrayReference meaning). `[]:` and
bootstrap-compatible `c.array` lower syntax-directed to ordinary
ANSI C99 array / array parameter / indexing. Rank N and extents
d0..dN-1 are preserved: this is **not** semantic rank-1 flattening.
The C image is a rectangular array `T a[D0][D1]...` with one
contiguous backing block in C row-major order, not `T a[D0*D1]` and
not ragged `T *rows[D0]`. Nested `[]` denotes logical dimensions, not
a tree of separately allocated rows. Elements are C cells, not Lmx
nodes. Ordinary new L1 SHOULD use a non-`c.` `[]` Frame (exact head
OPEN 10.14). Bootstrap-compatible L1 MAY still lower established
`c.array: []: T name [N]` to `T name[N]` so make.lm2 does not need a
mass rewrite (10.5/10.14). Multidimensional **declaration spelling**
and array-of-pointer binding remain OPEN (10.15); if a spelling is
accepted, layout is row-major/C-compatible contiguous.

Function-pointer **types** have C99 meaning in L1 (`T (*p)(args)`).
Hosted `functionPointerType` tables MUST NOT be the L1 mechanism.
Exact direct spelling is OPEN (10.16).

Variadic functions/calls have C99 meaning in L1. There is **no**
established direct `...` spelling in current L1-like surface
(hosted uses `c.fprintf`). Spelling is OPEN (10.17). MUST NOT
claim that variadic is possible only through `c.`.

Abstract parameters `(int; char)` vs named `(int: n)`: P0 does not
distinguish a bare type atom from a value. OPEN (10.18): require
names in S1, or treat a known-type lone atom as an abstract
declarator.

`@(T name)` and `@: T name` are the same P0. Both remain accepted
inputs; no new head.

1.6 Expressions, control, operators

P0 delivers a **flat** field stream. Operator precedence,
associativity, index grouping, `==` gluing, if/else adjacency,
declarator binding, and cast-vs-group are **Translator-L1**
normalization (section 1.8). Language meaning of the normalized
tree is C99.

Established control spellings: `if`/`else`/`while`/`for`/`return`/
`break`/`continue`. `for:` is an early direct L1 construct, not an
L2 Array iterator: hosted compact for-header
`for: int(i, 1) (i <= n) i++` (tests/trans_for_loop.lm2,
tests/t1.lmx, tests/l1/for_loop.lm1) is established sugar →
C99 `for (int i = 1; i <= n; i++)`.

`return` as a body Frame and `return` as a trailer are the same
statement (Claude 20260906-161112).

`switch` / `do` / `throw` / `catch` / `goto`: in the **contract**.
Slices MAY lag. Exclusion from L1 requires a user decision.

Infix `=` in expressions is C `==` in the hosted operator table
(trans_registry.lm2). Assignment is `name:`. L1 MUST keep that
established split unless the user changes it.

1.7 Foreign C library (normal path)

Normal L1 uses ANSI C libraries by:

  1. `include:` of the header
     (established: include: "<stdio.h>", tests/trans_include_receiver.lm2,
     tests/l1/include_printf.lm1).
     P0 keeps the source delimiters: the atom for `"<stdio.h>"` includes
     the quotes. Translator-L1 MUST decode that string value, then emit
     the C include form of the value: `#include <stdio.h>` for an angle
     header (no extra quotes) or `#include "local.h"` for a quoted local
     header. MUST NOT emit `#include "<stdio.h>"`.
  2. L1 declarations of the functions (established prototype `fn:`
     without body; hosted pattern in lm2/libc_abi.lm2)
  3. ordinary call Frames after those declarations are in the unit
     environment (same unit or `import:` / `predef:` of a prelude
     module that declares the library)

That is the writing style. A prelude module that declares libc is
ordinary L1.

`c.name` (c.printf, c.sizeof, c.fprintf):

  - Lexer form is established (lm_p0_starts_c_surface_atom,
    parser.lm2:2646; spec §6.6.6 for **L2** C-surface).
  - Hosted trans strips `c.` and pastes C (lm_trans_strip_c_prefix).
  - New L1 code: include + declared/imported names, not `c.printf`.
  - Bootstrap-compatible L1 MAY accept `c.name` as a dumb
    compile-time spelling (10.5), if the GOOD-baseline census
    confirms the current-main frequency. Not receiver `C`.

1.8 Parser/P0 contract (from Claude 20260906-160312 and 161112)

P0 is generic. Translator-L1 MUST treat the following as parser
contract, not as trans-registry ontology.

Entry (parser_abi.lm2; generated C also passes
LmMessageThread* on managed ABI — Translator-L1 MUST match the
linked parser.lm1.c convention, not invent a second parser):

    lm_p0_parse_string / lm_p0_parse_bytes / lm_p0_parse_file
    lm_p0_document_root / lm_p0_document_diagnostic
    lm_p0_document_destroy
    optional accessors lm_p0_node_frame / _node_atom / …
    optional lm_p0_dump_alloc / lm_p0_free

Root: LmP0Document holds a copy of source bytes; LmP0Text.data and
LmP0Span.offset index that buffer until destroy.

Nodes:

    LmP0Node      kind, flags, span, as
    kind          STRUCTURE=1 FRAME=2 ATOM=3 DISABLED=4
    flags         INACTIVE, MIX, POSITIONAL_SKIP
    LmP0Structure first_field, last_field, field_count, trailer
    LmP0Field     value, next
    LmP0Frame     head, flags, body, trailer
    LmP0Trailer   spelling, flags, body
    LmP0Text      {data, length}  slice, NOT NUL-terminated
    LmP0Span      line, column, offset, length (byte offset)

Walk: first_field / next / value / kind / as.atom|frame|structure /
frame.head. No public field iterator in fn.external; layout is ABI.

P0 does **not** interpret receiver names. Mix `{...}` is a flagged
node; ordinary L1 MAY ignore Mix-flagged nodes.

Expressions arrive as generic P0 atoms, Frames and Structures, **not**
as a C AST. Translator-L1 builds operator/index/declarator structure
from that generic stream. The parser MUST NOT be changed for the first
vertical in order to pre-build C expressions.

P0 is already unambiguous for:

  - nesting of statements via indent → Structure fields
  - Frame head/body/trailer identity
  - typed declaration shape: T(name) and (T: name) → Frame head=type
    with name atom; const wraps; `;;` → POSITIONAL_SKIP
  - literals: numbers (sign glued when allow_signed_number), char,
    string, L-prefix, exact quoted identifiers — raw spelling in the
    atom
  - field separators comma/semicolon; closers --- / end:
  - name(...) is always a Frame; (...) is always an anonymous Structure
  - `c.`-surface chunks (`c.printf`, `c.a.b`) as one atom in compact
    split (parser.lm2:2646–2729)

Bootstrap compact-token pairs that P0 keeps **whole**
(lm_p0_scan_builtin_compact_atom_piece, parser.lm2:2757–2767):

    !=  <=  >=  &&  ||  ++  --

Bootstrap compact-token sequences that P0 does **not** keep whole
(each character is its own atom unless reconstructed):

    ==   →  "=" "="
    <<   →  "<" "<"
    >>   →  ">" ">"
    ->   →  "-" ">"
    assignment combinations += -= *= /= %= &= |= ^= <<= >>=

Reconstruction of those sequences is allowed **only** when P0 spans
are exactly adjacent in source bytes:

    span[i].offset + span[i].length == span[i+1].offset

MUST NOT invent or delete whitespace after the fact. If a space
separates the characters, they remain separate tokens.

Different P0 contexts (same characters, different trees):

  - Frame **head** (chunk immediately followed by `:` or `(`): the
    chunk is kept whole. `System\out\println:` → head spelling
    includes `\`. Operators in a head are not split.
  - Body / argument **atoms**: compact-split applies. `text\length`
    → "text" "\\" "length".
  - `[` at the **start of a field** (and not after `)`) → bounded
    STRUCTURE, not a pair of "[" "]" atoms (parser.lm2:3571–3600).
  - `[` **after an operand** → bare atoms "[" … "]" with the interior
    parsed as fields of the **same** Structure (parser.lm2:2874–2888).
  - Signed numeric atoms: `allow_signed_number` is true at the start
    of each field and after some separators; `-1` as a whole field is
    one NUMBER atom; `x-1` is "x" "-" "1". Translator-L1 reads this;
    it MUST NOT re-glue signs across a span gap.

Translator-L1 MUST locally normalize (not P0, not a parser fork):

  - operator precedence, associativity, arity over the flat field
    stream of each Structure
  - adjacent-span reconstruction of the split multi-character
    operators listed above
  - index nodes from post-operand "[" "]"
  - field-follow `\` as a body atom (and, if needed for uniformity,
    splitting a head that contains `\`)
  - `@` as atom vs Frame head → pointer/address operator
  - if/else (and catch/finally) as adjacent sibling fields, not a
    single P0 node
  - `return` Frame vs `return` trailer
  - for-header slots: init, condition Structure, loose post atoms,
    body = last field
  - C declarators (`int * p`, arrays, function pointers)
  - `(T)expr` vs grouping `(expr)` — same P0 shape

The following are **OPEN implementation/language choices**, not
decisions of this draft (Claude 20260906-161922 listed them as
forks; do not treat as accepted):

  - member access is no longer open: see the address-based rule in 1.3
    and closed item 10.9; `c.` is an explicit C exception
  - whether L1 includes C ternary `?:` (P0 `:` is a level-A stop)
  - whether to extend parser registry table `p0.compact-token` so
    that `==` `<<` `>>` `->` arrive whole from P0, versus keeping
    reconstruction in Translator-L1
  - whether L1 accepts leading `[` as a bounded STRUCTURE (array
    type / index sugar) in addition to post-operand "[" "]"

Parser fixtures for this contract (Claude; exact P0 shape **and**
byte span of each atom, not only exit code):

    tests/short_form_body_after_inline_return.lmx
    tests/t1.lmx (factorial + for)
    tests/if_else_compact_probe.lmx
    tests/compact_operator_split.lmx
    tests/operator_atoms.lmx
    tests/parser_c_char_literals.lmx
    tests/parser_signed_number_call.lmx
    tests/index_brackets_nested.lmx
    optional: tests/return_inside_block_body_not_trailer.lmx

Three described-but-missing operator fixtures (not created here):
op_multichar_reconstruct, field_follow_vs_head,
signed_number_positions. OPEN whether to add them before S2.

Parser-only gate (printTree.lm0 on tests/*.lmx except trans_*;
invalid_* must fail) remains the P0 acceptance, independent of
Translator-L1.

Link set for a consumer of P0: parser.lm1.c + own.lm1.c + the
thread-provider shim the current parser ABI requires. MUST NOT link
trans_*.lm2, parser_registry, table*, namespace, descriptor.

1.9 Receiver `C` (hatch only)

Last-resort opaque C99 payload inside an L1 unit.

MUST NOT appear in ordinary L1 programs, Translator-L1 sources,
runtime, or bootstrap.
MUST NOT be how missing L1 sugar is filled.
MUST NOT be an L2 backend.
MAY exist as an isolated contract and at most one conformance slice
**after** a working normal L1 (section 3.3 S8).
P0 has no verbatim node kind; a hatch body is a block-string ATOM
(Claude). That is hatch mechanics, not L1 design.


════════════════════════════════════════════════════════════════
2. Translator-L1 architecture
════════════════════════════════════════════════════════════════

2.1 Role

Read L1 source (section 1), using P0 (1.8), emit ANSI C99 whose
behaviour matches section 1. Do not implement L2.

2.2 Passes

    1. P0 parse
    2. Validate the implicit `.lm1` body; ignore Mix-flagged nodes
       unless a later L1 Mix profile exists (none in this draft)
    3. Compose module graph (import/predef) and receiver environment
    4. Normalize operators/index/declarators (1.8)
    5. C-scope checking (C99 rules, compile-time only)
    6. Emit C99, deterministic

4.2 Shared with L1

4.3 Backend profiles (all allowed; equivalent)

    P-L1text   emit L1 source, run Translator-L1
    P-L1ir     call Translator-L1 emitter API
    P-C99      emit C99 directly

Same L2 input ⇒ same L2 semantics and ABI. Direct C99 does not
license smuggling hosted trans_l1_* core. Receiver `C` is not a
profile.

4.4 When

A second, separate program, written against the published
Lingvamyxa_spec.txt and struct_refactoring_version_2.txt. Which
route of 4.3 it takes — through L1 text, through a shared emitter
API, or straight to C99 — is an implementation choice, not a
semantic one. MUST NOT start by editing lm2/trans_l1_*.lm2.

4.5 `fn:` in L2 ≠ `fn:` in L1

L2 methods get reserved `node`, hidden dynamic arguments, and a
method record. Translator-L2 owns that. Translator-L1 MUST NOT.

4.6 Array backing (restored invariant, not a new invention)

The rectangular one-block invariant was long-established on 620db86
(one rectangular backing block; multidimensional layout is dimensions,
not a tree of row allocations). Later Revision-2 draft text that
marked contiguous-versus-another-representation as OPEN was a
documentation regression; the published specification now carries the
restored wording and is canonical:

    struct_refactoring_version_2.txt §3.6
        "Array referents: typed descriptor pools"
    Lingvamyxa_spec.txt §6.5 and §12.2
        Array reference → descriptor → element backing

Do not restate that text here. What Translator-L2 must not contradict:

  - An Array reference addresses a two-value record `{len, ptr}` in
    one of the N typed service pools. The pool's address range
    identifies the array type; the record carries no type tag.
  - An Lmx Structure field MAY hold that descriptor pointer in its
    own `data`. The field remains an ordinary Structure occurrence:
    it does **not** become an Array header, and the array's elements
    get no containment `node`.
  - The record has exactly two values. Do not add rank, shape,
    stride, name or `node` to it. Multidimensional indexing comes
    from the array type and the indexing context, as in C.
  - `ptr` addresses the element backing: one contiguous rectangular
    block, C row-major, rank and extents preserved; not a tree of
    separately allocated rows, not per-element allocations.
  - Descriptor entries, pool blocks and backing belong to the owning
    Message arena. The same address-range rule serves the primitive
    service pools (whose entries hold values) and
    `all_methods_array {addr, sig}`.
  - The pool of descriptors and the language array it describes are
    two different arrays, with two different lengths and two
    different address ranges. Do not conflate them.

Descriptor field placement/units, resize and view ABI are
implementation detail; they MUST NOT break the one-block invariant or
grow the two-value record. Do not port the old `lm2/mix/Array*`
module as Translator-L2.

These service pools are **L2** substrate. Translator-L1 has none of
them: an L1 array is a plain C99 array (section 1.5).

        Translator-L1.
  10.12 Whether leading `[` as a bounded STRUCTURE is an L1 form.
  10.13 `const: @: T x` → `const T *x` vs `T * const x`.
        Hosted convention is the former; latter spelling OPEN.
  10.14 Array **declaration spelling**: bootstrap MAY keep
        `c.array: []: T name [N]` as a dumb C-array spelling
        (59 one-dimensional `c.array` sites in the 620db86 closure).
        Ordinary new L1 still prefers a non-`c.` `[]` form (exact
        head OPEN). Physical model is **closed**: rectangular
        rank-preserving C array, one contiguous row-major block.
        Not L2 Array ontology. Not rank-1 flattening.
  10.15 Multidimensional **declaration spelling** and
        array-of-pointer declarators remain OPEN. If a
        multidimensional form is accepted, layout is C row-major
        `T a[D0][D1]...`, not a ragged row tree and not a collapsed
        `T a[D0*D1]`. The physical one-block invariant is closed.
  10.16 Direct spelling of a function-pointer type (C99 semantics
        in; hosted functionPointerType table out).
  10.17 Direct spelling of C99 variadic `...` (semantics in;
        not “only via c.”).
  10.18 Named vs abstract parameters (`int: n` vs bare `int`).
  10.19 Explicit byte-blob declaration form (vs expression string
        literal). Census on GOOD baseline before choosing.
