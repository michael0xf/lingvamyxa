Cursos (Cursor / Composer) file-drop chat
=========================================

Root (this machine):

    C:\Nyasha_Planet\lingvamyxa\work_chat\cursos\

    inbox\      user -> cursos  (new request)
    outbox\     cursos -> user  (reply)
    seen\       cursos marks a request as taken (same filename)

Sibling channel (Grok, not yours):

    C:\Nyasha_Planet\lingvamyxa\work_chat\grok\

Simple work stays here. Hard work: ask the user to drop it in Grok's
inbox (subscription cost split — yearly vs monthly — not a skill ranking).

Encoding: UTF-8. Newlines: CR LF or LF, both fine.

Filename (id)
-------------

    YYYYMMDD-HHMMSS.txt

Local time, 24-hour. If two files would share a second:

    YYYYMMDD-HHMMSS-mmm.txt

Example: 20260906-143201.txt

No spaces. No path in the name. Same basename in inbox, outbox and seen.

Request body (inbox)
--------------------

The whole file is the user message. No header required.

Optional first line, if you want a type tag:

    # cursos-chat-v1

Anything after that is still the request. If the first line is not that tag,
the entire file is the request.

Reply body (outbox)
-------------------

Same basename as the request. The whole file is the cursos answer
(markdown/text). Do not require a header. Write the file only when the
answer is complete (write to a temp name in outbox, then rename).

    inbox\20260906-143201.txt     request
    outbox\20260906-143201.txt    reply
    seen\20260906-143201.txt      empty marker: this id is done or in flight

Lifecycle
---------

1. User creates a new file in inbox\ with a datetime name.
2. Cursos notices a file in inbox\ whose basename is not in seen\ and not
   yet in outbox\.
3. Cursos writes seen\<basename> immediately (claim), so a second watcher
   does not take it.
4. Cursos reads the inbox file as the user request, does the work (or asks
   to delegate hard work to Grok).
5. Cursos writes outbox\<basename> (temp + rename).
6. Leave the inbox file in place. Do not delete user files.

A request is new iff it is a *.txt in inbox\ and seen\<basename> does not exist.

Watcher
-------

Do not wake the agent every N seconds on an empty inbox.

Watch inbox\ for a newly created *.txt (ReadDirectoryChanges / fswatch /
a loop that only prints when a new unseen basename appears). Emit one line
per new file, then handle that file in one turn. Write the answer only to
outbox\, plus a short note in the chat that the id was answered.

This protocol is not Codex IPC. It is a drop directory on this machine.
