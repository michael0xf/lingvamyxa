Задание для Cursor / Composer (cursos) на этой машине
======================================================

Ты Cursor Agent (Composer / Auto). Рабочий корень Lingvamyxa: каталог
репозитория на этой машине (ожидается C:\Nyasha_Planet\lingvamyxa).
Файл-чат:

    C:\Nyasha_Planet\lingvamyxa\work_chat\cursos\

Прочитай PROTOCOL.txt в том же каталоге и следуй ему. Это не гипотеза:
это твой канал с пользователем через inbox/outbox.

Разделение с Grok (тарифы, не «кто умнее»)
------------------------------------------

На этой машине параллельно есть канал Grok:

    C:\Nyasha_Planet\lingvamyxa\work_chat\grok\

Брать себе простые задачи: правки текста, мелкий рефакторинг, поиск по
коду, ответы по структуре репо, короткие правки, рутина.

Сложные задачи (глубокий рефакторинг, неочевидная архитектура, длинные
мультифайловые разборы, тяжёлая отладка) — просить пользователя
делегировать Grok-у через его inbox, а не тащить всё на себя.

Причина: разные тарифы подписки (у тебя год, у Grok месяц), а не
«кто глупее». Экономим дорогие ходы Grok на то, где они дают больше
отдачи; простую работу закрываем здесь.

Если просьба явно сложная — в outbox можно коротко написать, что лучше
бросить то же в work_chat\grok\inbox\, и предложить формулировку.
Если просьба простая — делай сам до конца.

Старт
-----

1. Создай inbox, outbox и seen, если их ещё нет.
2. Включи вотчер inbox: событие только когда появляется новый *.txt,
   которого нет в seen. Не буди ход каждые 10 секунд на пустом inbox.
   На Windows достаточно PowerShell с LastWrite/именем, который печатает
   одну строку NEW <basename> только для невиденного файла.
3. Покажи в чате, что вотчер жив и пути верные.

На каждом NEW <basename>
------------------------

1. Если seen\<basename> уже есть — игнор.
2. Запиши seen\<basename> (claim).
3. Прочитай inbox\<basename> как просьбу пользователя (UTF-8).
4. Оцени сложность: простая — делай в репозитории; сложная — в outbox
   попроси делегировать Grok (см. блок выше), без молчания.
5. Запиши полный ответ в outbox\<basename> (сначала .tmp, потом rename).
6. В чат — одна строка: answered <basename>.

Правила
-------

- Не удаляй файлы пользователя в inbox.
- Не правь ./lm2, пока просьба в inbox это явно не велит.
- Не крути Codex и не жди живого IPC: только эти три каталога.
- Не лезь в work_chat\grok\ как в свой inbox — у Grok свой канал.
- Если просьба опасная/неясная — всё равно напиши отказ или вопрос
  в outbox\<basename>, не молчи.
- Сессия кончилась — вотчер кончился. Пользователь запустит тебя снова.

Формат имени: YYYYMMDD-HHMMSS.txt (при столкновении YYYYMMDD-HHMMSS-mmm.txt).
Тело inbox = просьба. Тело outbox = ответ.
