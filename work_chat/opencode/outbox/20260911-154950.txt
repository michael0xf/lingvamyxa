Reference mapping (ClearShell.java ~198-280 and ~7634-8120, AudioServiceBinder.java):
the binder owns its audio device, a playlist state machine (positions, mode,
loop, next/prev with wrap) and an end-of-track callback. The port keeps the
playlist/state machine in a PORTABLE controller (MixaAudio, one instance owns
one device) behind a function-pointer device vtable, and on Windows rides the
system MCI layer (winmm). End-of-track is not signalled to us (no MCINOTIFY in
this slice); mixa_audio_poll() queries 'status mode' and advances instead -
documented in mixa_audio.txt, not hidden. next/prev move ONE position and
reset to the file start (the binder's internal one-second bump is not carried
into the controller; the desktop buttons mean "skip"), wrap only when is_loop
is set, and candidates are probed (missing files skipped as ERR_MISSING, dirs
and unknown extensions as ERR_UNSUPPORTED).

Common API (works with any device): create/set_list/start/play/stop/
seek_to/position/duration/progress/is_playing/poll/cur_file/cur_state/pos/
count/next_file/prev_file/play_next/play_prev/is_audio_path/destroy. Modes
IDLE->LOADED->PLAYING->LOADED->ENDED. Status codes OK/END/ERR_ARG/ERR_STATE/
ERR_MISSING/ERR_UNSUPPORTED/ERR_NOMEM/ERR_IO/ERR_BACKEND. Backend = win32 MCI:
open "<path>" type waveaudio|mpegvideo alias mixa<N>, milliseconds time format,
length/position/mode status, play/seek/stop/close. Support matrix (explicit):
WAV guaranteed (waveaudio MCI driver); MP3 via mpegvideo MCI type and thus a
system MP3 renderer - load fails honestly with ERR_BACKEND where none exists.
