МОНИТОР Grok/OpenCode/Codex — политика nudge
============================================

Письма пользователю: только кратко по-русски (cursor/outbox + monitor/outbox).

Inbox-nudge агенту — ТОЛЬКО при подтверждённом симптоме (не профилактически):

1) Idle без блокера:
   - ACK / план / отчёт вместо реализации
   - повторный prioritize вместо кода
   - ожидание другого агента как stall
   - ложный claim (git/файлы не подтверждают)
   - тихий outbox без прогресса и без реального блокера

2) Test-overload / затянутый прогон (НОВОЕ):
   - огромные suites / много smoke corpora / огромные fixture runs
   - долгий test-command с малым прогрессом
   - повтор полного набора без нужды
   - outbox/тикеты только про «гоняю много тестов» без сужения scope

При подтверждении test-overload — короткий inbox note (язык канала: EN для grok/opencode peer):
  - напишите результаты в outbox и спросите что делать дальше
  - оптимизируйте: если прогон тянется — обсудите ускорение (убрать лишние повторы, сузить suite, focused subset)

Codex делит канал work_chat/grok (отдельного канала нет).
