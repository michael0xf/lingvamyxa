Lingvamyxa lm1 direct ABI inventory
====================================

Purpose
-------

This file lists the remaining direct lm1/*.lm1.* source entities and the
receiver/table families needed to move them into lm2/lm4 without preserving the
old headers as a special language layer.

The target rule is:

    L4 tables hold ABI/data facts.
    L2 receivers consume their own namespace/card facts and print ANSI C.
    Static helper implementations become generated C units after L4 node-cells
    can store non-atom payloads safely.


Current direct lm1 files
------------------------

lm1/own.lm1.h
    C public ABI for the ownership/memory library.

lm1/parser.lm1.h
    C public ABI for P0 parser structures and parser functions.

lm1/l4_loader.lm1.h
    Shared L4 loader data declarations plus header-only static helper
    implementation.

lm1/trans_legacy.lm1.c
    Temporary compare-mode oracle for translator registry migration.


Entity families
---------------

1. Include/prelude requirements

    Examples:

        #include <stddef.h>
        #include "own.lm1.h"
        #include "parser.lm1.h"
        #include <stdio.h>
        #include <stdlib.h>
        #include <string.h>

    Current receiver coverage:

        include

    Needed work:

        Keep using include as the receiver. The data should come from the
        receiver card/include table instead of hardcoded C headers.


2. Header guard / public header wrapper

    Examples:

        #ifndef LM_OWN_LM1_H
        #define LM_OWN_LM1_H
        #ifndef LM_P0_H
        #define LM_P0_H
        #ifndef LM_L4_LOADER_H
        #define LM_L4_LOADER_H

    Current receiver coverage:

        none

    Possible receiver:

        guard

    Notes:

        If we stop generating standalone .h files, header guards become mostly
        unnecessary. If we still want generated public headers, guard can be a
        small receiver that wraps an emitted unit.


3. C++ extern wrapper

    Examples:

        #ifdef __cplusplus
        extern "C" {
        #endif

        #ifdef __cplusplus
        }
        #endif

    Current receiver coverage:

        none

    Possible receiver:

        extern_c

    Notes:

        This is only needed for generated public headers intended for C++ users.
        It is not needed for private generated .c translation units.


4. Primitive typedef aliases

    Examples:

        typedef int LmP0NodeKind;
        typedef unsigned LmP0FrameFlags;
        typedef unsigned LmP0NodeFlags;
        typedef unsigned LmP0TrailerFlags;
        typedef int LmOwnEdgeKind;

    Current receiver coverage:

        partial: constant can print numeric names, layout can print structs.

    Needed receiver:

        alias

    Table facts should say:

        alias name
        target class / target C spelling


5. Function pointer typedef aliases

    Examples:

        typedef void (*LmOwnDestroyFields)(void *object);
        typedef void (*LmOwnDelete)(void *object);
        typedef int (*LmL4PushRow)(...);
        typedef int (*LmL4PushCell)(...);
        typedef int (*LmL4NoteKey)(...);
        typedef int (*LmL4PushColumnMetadata)(...);

    Current receiver coverage:

        none

    Needed receiver:

        callable_alias

    Notes:

        This should share descriptor data with descriptor-only fn forms. The
        emitted ANSI C surface is only one backend projection.


6. Forward / opaque typedefs

    Examples:

        typedef struct LmP0Node LmP0Node;
        typedef struct LmP0Field LmP0Field;
        typedef struct LmP0Trailer LmP0Trailer;
        typedef struct LmP0Document LmP0Document;
        typedef struct LmOwnArena LmOwnArena;

    Current receiver coverage:

        none

    Needed receiver:

        forward

    Notes:

        This is separate from layout because a class can be named and used
        before its fields are emitted.


7. Struct layouts

    Examples:

        LmOwnPtrStack
        LmOwnValueStack
        LmOwnAllocationDescriptor
        LmOwnLazyEdge
        LmOwnArena
        LmP0Text
        LmP0Span
        LmP0Diagnostic
        LmP0Structure
        LmP0Trailer
        LmP0Frame
        LmP0Node
        LmP0Field
        LmL4Column
        LmL4Loader

    Current receiver coverage:

        layout

    Needed additions:

        Recursive/forward references.
        Named struct body without typedef form.
        Array fields, for example char message[256].
        Function-pointer fields.
        Embedded union fields.
        Possibly bit/flag metadata, though C output can stay ordinary fields.


8. Union layouts

    Example:

        union {
            LmP0Structure structure;
            LmP0Frame frame;
            LmP0Text atom;
        } as;

    Current receiver coverage:

        none

    Needed receiver:

        union_layout

    Notes:

        This can be a layout sub-profile. It should still be described as table
        data, not as a new source-level struct/union syntax.
