Lingvamyxa lm1 direct ABI inventory
====================================

Purpose
-------

This note records the old direct `lm1/*.lm1.*` ABI layer and the current
replacement.

The current rule is:

    L4 registry files and L2 predef modules hold ABI/data facts.
    L2 sources explicitly import or predefine the needed ABI sources.
    L2 prelude receivers consume the active namespace and print ANSI C.
    `lm1/build/*.lm1.c` is the portable generated L1 snapshot kept in Git.
    Root `lm1/*.lm1.*` public headers are no longer a source dependency.


Retired direct lm1 files
------------------------

The old root files were:

    lm1/own.lm1.h
    lm1/parser.lm1.h
    lm1/l4_loader.lm1.h
    lm1/trans_legacy.lm1.c

Their ABI role is now represented by registry source modules and receiver output:

    lm4/own_abi.lm4
    lm2/parser_abi.lm2
    lm2/l4_loader_abi.lm2
    lm4/core.lm4
    lm4/trans_registry.lm4
    lm4/parser_registry.lm4

`trans_legacy.lm1.c` was a temporary compare-mode oracle and is not part of
the current build path.


Current prelude receiver families
---------------------------------

These receivers are used by sources to request ABI/prelude output explicitly:

    include
    alias
    forward
    constant
    fn
    layout
    prototype
    unit

For example, a source that needs the parser ABI loads the ABI tables and then
calls the receivers:

    import: "lm4/own_abi.lm4"
    predef: "lm2/parser_abi.lm2"
    include
    alias
    forward
    constant
    fn
    layout
    prototype

The receiver calls are ordinary source-level requests. They do not include a
root `lm1/*.lm1.h` file. They inspect the active namespace/relation cache and
emit the ANSI C prelude needed by the generated C unit.


Current generated snapshot
--------------------------

The kept L1 source snapshot lives under:

    lm1/build/

Those generated `.lm1.c` files are still source artifacts for bootstrap and
cross-platform build. They are distinct from the retired root ABI headers.
