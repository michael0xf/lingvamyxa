0. Two graphs, one L3 Thread arena
Два графа, одна арена L3 Thread
---------------------------------

EN: Representation work is `struct_refactoring.txt`. This file is where
chunks live and how a Thread reclaims them. They meet at: a constructor
allocates in the current L3 Thread's arena; size comes from the descriptor;
collection walks StructureReference slots as value edges.

Value graph (Structure):
    Arena chunk = own-descriptor prefix + flat payload. A StructureReference
    slot is a pointer to another such chunk. Slots may share a referent;
    cycles are allowed. `x\foo` is descriptor → newest occurrence → slot,
    not `->` on a per-name typedef.

Array:
    Not this graph. One array descriptor + one rectangular `d0×d1×…` backing.
    Index is an offset. A row of StructureReference elements enters the
    Structure graph in those chunks. Mix hop addresses (`ℕ₀` path) are a
    placement tree, not this graph. Mix LMX is ordinary LMX: not automatically
    an L3 Thread, and not automatically in a Message arena. Mix may use no
    arena or a private arena. Cursors may be L3 Threads (spec §19.29.2.1).
    P0 / used-tree of Consumer stay trees.

Lifetime inside one L3 Thread:
    Reachability in that Thread's Structure graph. End-turn collection
    walks live roots (thread root, published refs) and StructureReference
    slots. There is no second source-level "owner graph" of OWNED /
    BORROWED / LAZY_OWNED / EXTERNAL / TRANSFERRED edges. Those names are
    bootstrap/runtime residue in `libown` and spec §19.29, not L3 ontology.

    Do not add `own:`, `borrow:`, `move:` as language receivers. Assignment
    and `return` are the same reference in this Thread. An explicit `copy`
    (when it exists) is an ordinary value operation: a second graph with a
    new identity, not "establish ownership in a target arena". L2 `@` / raw
    views pin against compaction; they are machine addresses, not borrow
    edges.

    "Own descriptor" on a Structure chunk is the type-description prefix,
    not an ownership object. Parser "owner level" is source nesting. Keep
    those words. Drop memory-owner as a source concept.

L3 Thread physical picture:
    Message Thread is the L2/L3 runtime family (§19.28.2.2). L3 does not
    name arenas. Inside one L3 Thread there is one execution thread: a pool
    may run later turns on another worker, but never two callbacks of the
    same actor at once (§19.28.11.1). That removes a mutator race on the
    arena. It does not make every program point a collection safe point.

    Default: one arena per L3 Thread — the Message Thread root. That is
    the only unscoped allocation for the actor. Ordinary Structure/Array
    chunks live there. L3 does not name this arena. Module/descriptor
    Structures that outlive a turn live on this root (or on the process
    root Message Thread), not in disposable turn storage.

    The arena is not one pre-sized slab. Capacity is not a parameter anyone
    guesses. Physically it is a bump pointer plus a list of backing blocks
    (LLVM `BumpPtrAllocator`, C++ `monotonic_buffer_resource`, game frame
    allocators — the same machine):

        allocate: if the request fits in the current block, bump;
                  if the current block is full, malloc/mmap another block
                  (policy: at least the request, otherwise a default/doubling
                  size) and bump there;
                  if the request is larger than the default block, give it
                  a dedicated block of that size.

    Existing pointers stay valid: objects in older blocks do not move.
    Structure chunks already point at each other by StructureReference;
    they never needed one contiguous range. An Array rectangle *does* need
    one contiguous backing — that is one allocation, which may be its own
    block. "In this arena" is membership in the block list (or an allocation
    descriptor), not `base <= p < base+size` on a single slab.

    A full block is not a user-facing error and not a language exception.
    The only allocation failure is the host refusing another block (true
    OS OOM). Do not relocate the graph because a block filled.

    Compaction is part of the one end-turn collection (spec §19.29.4),
    after outbox commit. Not after handler return, not in the allocator,
    not on ordinary `return`. A full block still just appends another
    block.

    Why not compact in the allocator when memory is short: one thread
    removes the race, not the C stack. Hosted locals and `@` / views are
    roots the arena graph does not list. Mid-sausage almost everything is
    still reachable, so a copy keeps the garbage you wanted to drop. If
    the bump block is full and nothing has been cut, in-place compact
    reclaims nothing — the answer is a new chunk. Copying also needs that
    new chunk; do the growth without the move. Compact-on-OOM becomes
    possible only if activation records live in the graph and C does not
    cache arena pointers across an allocation. That is not the current
    hosted lowering.

    Nested arenas are not part of the L3 default. One growing block-list
    arena plus one end-turn collection already drops sausage garbage.
    Frame/handler/parser do not get their own arenas.

    Isolation is the Message, not an owner. An L3 Thread is a Message
    launched in its own execution thread (spec §19.28.5). Sending constructs
    an inactive Message from a template (or by filling that Message's
    arena). In-process consume splices that arena onto the receiver and
    discards the inactive Message (join). Alternatively the Message is
    activated as its own Thread. Cross-process delivery serializes into a
    new Message. Join needs a closed graph: no refs into the sender, no
    refs from the receiver into the payload until after the splice.

    `retry` is a collection pass on this same arena from the surviving
    roots, not a nested-arena destroy.

RU: Представление — `struct_refactoring.txt`. Этот файл — владение, сбор
и где лежат куски. Стык: конструктор выделяет в текущей арене; размер —
из дескриптора; сбор ходит по слотам StructureReference как по рёбрам
значения.

Граф значений (Structure):
    Кусок = префикс своего дескриптора + ровный payload. Слот-ссылка —
    указатель на такой же кусок. Слоты могут делить референт; циклы
    разрешены. `x\foo` — свой дескриптор → новейшая occurrence → слот,
    не `->` в typedef на имя.

Array:
    Не этот граф. Один дескриптор массива + прямоугольник `d0×d1×…`.
    Индекс — смещение. Ряд StructureReference входит в граф Structure
    уже в тех кусках. Адреса Mix (`путь ℕ₀`) — дерево размещения, не
    этот граф. Mix — не Message; курсоры — L3 Thread (§19.29.2.1). P0 и
    used-tree у Consumer остаются деревьями.

Жизнь внутри одного L3 Thread:
    Достижимость в графе Structure этого потока. Сбор на end-turn идёт
    от живых корней и слотов-ссылок. Второго исходного «графа владельцев»
    с рёбрами OWNED / BORROWED / LAZY_OWNED / EXTERNAL / TRANSFERRED нет.
    Эти имена — остаток bootstrap/`libown` и §19.29, не онтология L3.

    Не добавлять приёмники `own:`, `borrow:`, `move:`. Привязка и `return`
    — та же ссылка в этом потоке. Явный `copy` — обычная операция над
    значением (второй граф, новая идентичность), не «владение в целевой
    арене». L2 `@` пинит против компакта; это машинный адрес, не borrow.

    «Свой дескриптор» у куска Structure — префикс описания, не объект
    владения. «Owner level» в парсере — вложенность исходника. Слова
    оставить. Memory-owner из языка убрать.

Физика L3 Thread:
    Message Thread — семейство рантайма L2/L3 (§19.28.2.2). L3 арены не
    именует. Внутри одного L3 Thread — один поток исполнения: пул может
    сменить воркера между ходами, но не два callback одного актора сразу
    (§19.28.11.1). Гонки мутаторов на арене нет. Это не делает каждую
    точку программы safe point сбора.

    Дефолт: одна арена на L3 Thread — корень Message Thread. Это
    единственный бесхозный malloc актора. Обычные куски Structure/Array
    живут там. L3 эту арену не именует. Дескрипторы, которые переживают
    ход, — на этом корне (или на корневом Message Thread процесса).

    Арена — не одна плита угаданного размера. Ёмкость не параметр.
    Физически: bump-указатель и список блоков backing (тот же механизм,
    что LLVM `BumpPtrAllocator` / C++ `monotonic_buffer_resource`):

        allocate: запрос влезает в текущий блок — bump;
                  блок полон — malloc/mmap следующего (не меньше запроса,
                  иначе размер по политике/удвоению) и bump туда;
                  запрос больше блока по умолчанию — отдельный блок
                  под этот размер.

    Старые указатели живы: объекты в прошлых блоках не едут. Куски
    Structure и так ссылаются друг на друга; один сплошной диапазон им
    не нужен. Прямоугольник Array — одно непрерывное выделение, ему
    можно отдать отдельный блок. «В этой арене» — членство в списке
    блоков, не `base <= p < base+size` одной плиты.

    Полный блок — не ошибка языка. Отказ allocate — только когда хост
    не даёт следующий блок (настоящий OOM ОС). Граф из-за полного блока
    не переезжает.

    Компактирование: только когда вложенная работа хода/handler/frame
    вернулась в корень L3 Thread (сбор на end-turn). C-кадры сосиски уже
    сняты; живые корни — граф владельцев. Обход графа Structure от них,
    мусор сосиски выбросить, выживших при желании скопировать в меньшее
    число блоков и переписать слоты, пустые блоки отдать хосту. Так
    список блоков не растёт без предела от хода к ходу. Это не способ
    угадать размер в середине хода — там просто дописывается блок.
    Обычный `return` не компактирует и не копирует.

    Почему не компактировать в аллокаторе, когда памяти мало: один поток
    снимает гонку, не C-стек. Hosted-локали и `@` / view — корни, которых
    нет в графе арены. В середине сосиски почти всё ещё достижимо, копия
    утащит тот мусор, который хотели выбросить. Если bump-блок полон и
    срезов не было, compact на месте не освободит ничего — нужен новый
    кусок. Копирующий сбор тоже просит этот кусок; рост — без переноса.
    Compact-on-OOM — только если кадры живут в графе и C не кэширует
    указатели арены через allocation. Нынешний hosted lowering таким
    не является.

    Вложенных арен в дефолте L3 нет. Одна растущая арена и сбор на
    выбранных safe point уже выбрасывают мусор сосиски обходом живых
    корней. Frame/handler/parser своих арен не получают.

    Изоляция — Message, не owner. L3 Thread — Message, запущенный в своём
    потоке исполнения (спека §19.28.5). Отправка строит неактивный Message
    из шаблона. In-process consume склеивает его арену к получателю и
    выбрасывает неактивный Message (join). Либо Message активируют как
    свой Thread. Через процесс — сериализация в новый Message. Join
    требует замкнутый граф: нет ссылок в отправителя и нет ссылок
    получателя в payload до склейки.

    `retry` — обход этой же арены от выживших корней, не destroy
    вложенной арены.


1. Spec contract / Контракт спецификации
----------------------------------------

EN: Ordinary non-primitive values are only StructureReference and
ArrayReference. Each referent is materialized once in an arena. There is no
source-level stack / heap / static object category. Local bindings hold
references. Binding, argument passing, field update and `return` never copy
the aggregate. `return` publishes the exact existing reference: no allocate,
clone, promote, compact or identity change on the return path.

Construction uses the executing L3 Thread's arena. L3 has no arena argument
and no owner object. Lexical scope is not permission to free. End-turn
collection drops what is unreachable from that Thread's roots.

Cross-thread payload is a Message: full LMX in an inactive L3 Thread.
Not copy-plus-owner-transfer of a branch, and not `own`/`move`/`borrow`.
Collection is local to one Message Thread, not a global GC. L2 may expose
raw addresses, unchecked index, allocators, atomics. L3 excludes those
machine operations but is not a sandbox.

Spec §19.29 still describes owner graphs and proposed `own`/`borrow`/`move`
receivers. This plan does not implement them. A later spec pass should
replace that vocabulary with Thread + reachability + Message.

RU: Обычные не-примитивы — только StructureReference и ArrayReference.
Референт один раз материализуется в арене. Категорий stack/heap/static у
исходника нет. Локальные слоты хранят ссылки. Привязка, аргумент, поле и
`return` не копируют агрегат. `return` публикует ту же ссылку: без выделения,
клона, promote, компакта и смены адреса.

Конструкция — в арене исполняющегося L3 Thread. В L3 нет аргумента-арены
и нет объекта owner. Лексический конец блока не освобождает. Сбор на
end-turn бросает недостижимое от корней этого потока.

Полезная нагрузка через границу — Message: полный LMX в неактивном
L3 Thread. Не copy+transfer ветки и не `own`/`move`/`borrow`. Сбор
локален одному Message Thread. L2 может показывать сырые адреса. L3 их
не показывает.

§19.29 ещё описывает граф владельцев и приёмники `own`/`borrow`/`move`.
Этот план их не реализует. Позже спеку стоит перевести на Thread +
достижимость + Message.


2. Already in the project / Уже есть в проекте
----------------------------------------------

EN:

  Runtime (`libown` / `LmOwnArena` / `LmMessageThread`):
    one `root_owner` per actor; generated programs attach an unpooled root
    and drive its turn loop; pool actors share the same arena/collection ABI;
    the arena follows the actor if a later turn runs on another worker;
    at most one active entry callback per actor;
    `lm_own_arena_new_zero`, array alloc, allocation descriptors, lazy edges,
    freeze, absorb; `lm_own_tree_cut` at every end-turn;
    actor destruction releases the whole root arena;
    edge kinds BORROWED / OWNED / LAZY_OWNED / EXTERNAL exist in the ABI;
    pthread / Win32 / single host providers.

  What is still unscoped:
    `lm_own_arena_new` mallocs the arena shell; extra arenas hang on
    `arena_head` as sibling shells, not regions of the root;
    arena metadata stacks (`allocations` / descriptors / lazy edges) are
    `lm_own_new_zero`; Mix pages and `items` use `lm_own_new_zero` / `c.free`;
    trans/parser/table/registry compiler internals (`lm_own_new_zero` of
    P0 nodes, namespaces, jobs, descriptor tables) are L2 bootstrap, not
    ordinary user Structure/Array. Generated callable-binder `lm_result` /
    `lm_env` now go through `lm_own_arena_new_zero` of the Message arena
    (same as hoisted closures).

  Hosted chunks (struct_refactoring.txt first delivery, Phases 1–6 / 8):
    named Structure is a graph header (`LmLmxStructure *` / `lm_lmx_layout_*`)
    with own-descriptor prefix, not `typedef struct ThatName`; empty named
    Structure is prefix + 0 payload; nested StructureReference and `[]`
    fields are slots; rank-N ordinary `[]` is one rectangle (`T *` + cell
    product), not a `T **` ladder. Hosted field-follow still emits C `->`.
    Mix / own / table-class and per-name typedef tests stay on the old
    projection until that file's Phase 9.1.

  Trans lowering:
    local and direct module named/anonymous Structures, `fm` results, admitted
    Arrays and unmarked runtime Tables in managed Message Thread context go
    through `lm_own_arena_new_zero` in the root owner;
    module-level value sites use source-ordered helpers and private static
    *reference slots* (not static aggregates);
    descriptor/`merge:` declarations allocate no objects;
    `return` of a Structure/Array is a pointer forward in the hosted C profile.

  Spec already records this as a *coarse* bootstrap: one root arena that
  outlives every ordinary function return; tree-cut currently promotes lazy
  edges and does not reclaim general unreachable root objects. That coarse
  retain-until-thread-death profile is valid. The remaining lie is unscoped
  shells and Mix/own typedef-sized chunks, not "only one arena" and not
  language-test named Structures.

    `return` Structure/Array в hosted C — проброс указателя.

  Спека уже называет это грубым bootstrap: одна root-арена переживает любой
  обычный return; tree-cut сейчас только promote lazy-рёбер. Грубый профиль

  `sizeof(T)`, не «арена одна» и не языковые named Structure.


3. Gaps vs spec / Дыры относительно спеки
-----------------------------------------

EN (priority order):

  G0. Language-test named Structures now have descriptor prefix + payload
      slots (struct_refactoring first delivery). Precise collection can
      walk those slots once end-turn reclaim exists (G4). Remaining old
      projection: Mix / own / table-class, and hosted C still emits `->`.
      Do not duplicate representation phases here; constructors of new
      Structures must allocate in the current Message Thread arena.

  G1. Unscoped allocation still in use.
      `lm_own_new_zero` / `c.free` remain for bootstrap helpers, arena
      shells, arena metadata stacks, and Mix pages (`lm2/mix`).
      Spec: ordinary Structure/Array materialization belongs to the
      Message arena. Mix LMX is ordinary LMX — own arena or none, not an
      automatic L3 Thread. Cursors may be L3 Threads. One-header Mix is
      struct_refactoring Phase 9.1.

  G2. void vs empty Structure is split for language tests.
      See `bug0_void.txt`. `void: cell` trans-rejects (no cell). Unit
      (`(): empty`) and empty named Structure are arena objects: descriptor
      prefix + empty payload. Destructor callbacks recover `@: void` with
      `cast: (T) object` (pointer cast on reference-base types). Mix pages
      still lack that converter until Phase 9.1.

  G3. Extra arena shells are sibling mallocs.
      The L3 default is one thread arena (bump + block list). Extra
      `lm_own_arena_new` shells on `arena_head` are the defect. Do not
      replace them with nested turn/handler/frame arenas. Those inner
      owners are not required once end-turn collection walks this one
      arena. Sibling mallocs go away; nested arenas do not come in.

  G4. `lm_own_tree_cut` does not reclaim.
      End-turn is a safe point that promotes lazy-owned edges. It does
      not walk owner roots + StructureReference slots, drop unreachable
      sausage objects, or compact survivors into the root. Need descriptor-
      prefixed chunks (G0 / struct Phase 3) before a precise walk; cycles
      need a mark, not a tree walk of slots. Shared descriptors are roots,
      not owned by each instance. First conformance may still retain until
      thread death; reclaim/compact at end-turn is the next precise step,
      not compact-in-allocator.

  G5. Do not implement source `own` / `borrow` / `move`.
      Spec §19.29 proposes them; this plan drops them from L3. An optional
      later `copy` is an ordinary deep-copy receiver (new identity), not an
      ownership operator. Runtime lazy-edge / absorb helpers stay private
      to `libown` until that C ABI is retired.

  G6. Cross-thread refs must not exist, rather than "borrow escape".
      A Message is another L3 Thread. The sender must not retain a
      StructureReference into it. Incoming payload is that Thread's graph,
      not a borrowed view of the mailbox. L2 `@` that outlives end-turn
      compact is a pin/diagnostic on the machine profile, not `own:`.

  G7. Message is not yet an inactive L3 Thread.
      `send:` copies already-serialized LMX bytes into FIFO storage.
      The target picture: construct the payload in a new inactive Message
      Thread's arena; enqueue that Thread; dispatch activates it. `reply` /
      `await` / `schedule` are not implemented. Do not add whole-branch
      owner-transfer as a source operation.

  G8. Array views vs copies.
      Spec §6.5 / §19.29.1: L3 slice/reshape is an ArrayReference in this
      Message's graph; L2 raw view is a machine address that pins against
      compaction. Ordinary rank-N `[]` is already one rectangle (struct
      Phase 8). Remaining: view lifetime vs backing, no implicit copy on
      `return` of a view, L3 checked vs L2 unchecked index
      (`receiver.l3.exclude` still incomplete per §1.4). Mix/own arrays
      may still be the old ladder until Phase 9.1.

  G9. L2 machine surface incomplete.
      Exact semantics of `@`, prefix `\`, field-follow, raw store, address
      arithmetic and unchecked index are still listed as profile work (§18.2).
      No generic `mem:` / `freemem:` / shared-block / low-level thread
      profile. Mix hop addresses are a placement tree, not this L2
      cell-address machine; Mix tree has no Message arena; cursors are
      L3 Threads. An `@` taken inside nested work pins that
      object against compaction at end-turn until the address dies.

  G10. Control-exit collection passes.
       `return` / `throw` / `catch` / `assert` / `stop` lower, but retry,
       labelled break/continue, `redo`, and a frame/cleanup stack for nested
       Message Thread calls are not implemented. Those points, when they
       exist, run the same one-arena walk from the surviving roots. They
       do not allocate a nested arena. Memory pressure is growth and/or
       end-turn collection, not compact-in-allocator.

  G11. Interning / immutable store.
       Optional optimization (§19.29.9). Not required for first conformance.
       Mix tags/cursors and parser P0 trees are natural later clients.
       Must not change `return` identity.

  G12. Precise-owner ABI (§19.29.12.4).
       `LmOwnerArena` / `LmOwnerBranch` / type-ops is design, not current
       C ABI. Current ABI stays `LmOwnArena`. Do not pretend the old names
       `LmArena`/`LmBranch` are live. Do not introduce `LmOwnerArena` until
       this one thread arena actually cuts and, if the profile asks,
       compacts at end-turn.

RU (тот же порядок):

  G0. Языковые named Structure уже с префиксом дескриптора и слотами
      (первая поставка struct_refactoring). Точный сбор — когда появится
      G4. Старая проекция: Mix / own / table-class; hosted C всё ещё `->`.
      Фазы представления сюда не дублировать. Конструкторы — в арене
      текущего Message Thread.

  G1. Бесхозные аллокации.
      `lm_own_new_zero` / `c.free` в хелперах, шапках арен, стеках метаданных
      и Mix. Mix LMX — обыкновенный LMX (своя арена или без); не
      автоматически L3 Thread. Курсоры могут быть L3 Thread. Одна шапка
      Mix — фаза 9.1 другого файла.

  G2. void и пустая Structure разведены в языковых тестах.
      `void: cell` — ошибка trans. Unit — префикс + 0 payload. Деструкторы
      trans/parser/table — `cast: (T) object`. Mix — до 9.1.

  G3. Шапки арен — соседние malloc.
      Дефолт L3 — одна арена потока (bump + список блоков). Список
      `arena_head` — дефект. Не менять его на вложенные арены хода/
      handler/frame: при сборе на end-turn они не нужны.

  G4. `lm_own_tree_cut` не собирает.
      End-turn — safe point с promote lazy. Нет обхода корней + слотов
      ссылок, нет сброса мусора сосиски, нет компакта выживших в корень.

      Держать до смерти потока — законно для первой соответственности.

  G6. Ссылок через границу потока нет, а не «утечка borrow». Message —
      другой L3 Thread.

  G7. Message ещё не неактивный L3 Thread. `send:` копирует байты LMX.
      Не добавлять owner-transfer ветки.

  G8. View против copy у Array. Обычный rank-N `[]` уже прямоугольник
      (фаза 8 представления). Лесенка может остаться у Mix/own до 9.1.

  G9. Машинная поверхность L2. Mix-адреса — дерево размещения без арены
      Message; курсоры — L3 Thread. `@` пинит объект против компакта на
      end-turn.

  G10. Сбор на выходе управления — тот же обход одной арены от выживших
       корней, не вложенная арена. Давление памяти — рост и/или end-turn.

  G11. Intern / immutable store — позже.

  G12. Precise-owner ABI — дизайн. Живой ABI — `LmOwnArena`.

Phase B — borrow, exact return, diagnostics
Фаза B — borrow, точный return, диагностика

  EN:
    1. Do not lower message-frame fields as BORROWED-into-another-owner.
       After send, the sender has no StructureReference into the Message
       Thread. A slice/view in L3 is an ArrayReference in this Thread's

    2. Diagnose an L2 `@` / raw view that would survive end-turn compact
       of its referent. That is a machine-address pin, not a missing `own`.
    3. Keep `return` allocation-free and compaction-free; add tests that a
       locally constructed Structure address is unchanged after return
       (already the coarse-root behavior). Never a hidden copy, never a

Phase C — optional explicit `copy` (not ownership)
Фаза C — опциональный явный `copy` (не владение)

  EN:
    If a profile wants a second identity of a live graph, register `copy:`
    as an ordinary L2/L3 receiver that materializes a new Structure/Array

Phase D — end-turn reclaim on the one Message arena
Фаза D — сбор на end-turn в одной арене Message

  EN:
    Prerequisite: StructureReference slots exist (struct_refactoring Phase 3)
    so the walk can see value edges. Cycles use a mark.

    1. Keep the L3 default: one Message Thread arena as a bump + block list.
       A full block appends another block. Do not guess a capacity. Do not
       fail allocate unless the host refuses the next block. Do not move
       because a block filled.
    2. Once per turn, at end-turn after outbox: walk live Message roots
       and StructureReference slots; pin objects whose L2 `@` still exists;
       mark unreachable objects; release them, or copy survivors into
       fewer blocks and rewrite slots. Shared descriptors stay roots.
       Not after handler return, not on `return` / `retry`.
    3. No nested arena to destroy.
    4. Mix LMX is ordinary LMX, not an L3 Thread by default. It may have no
       arena or a private arena; do not force Mix pages into a Message
       arena. Do not make Mix an L3 Message: concurrent cursors would block
       on one turn. A Message in Mix is a blob. Cursors may be L3 Threads.
    5. Keep collection Message-Thread-local. One execution thread inside
       the actor is why the walk needs no mutator handshake.
       Never stop-the-world for other Message Threads.

  RU:
    Сначала слоты StructureReference (фаза 3 представления). Циклы — mark.

    1. Одна арена Message Thread: bump + список блоков. Блок кончился —
       следующий блок. Ёмкость не угадывать. Allocate не падает, пока хост
       даёт блок. Из-за полного блока не переезжать.
    2. Один раз за ход, на end-turn после outbox: обход живых корней и
       слотов-ссылок; pin по живому L2 `@`; мусор снять или скопировать
       выживших в меньшее число блоков. Не после возврата handler, не на
       `return` / `retry`.
    3. Вложенной арены нет.
    4. Дерево Mix — сырые слоты. Не делать Mix L3 Message: курсоры
       заблокируются на одном ходе. LMX Mix со Structure, но граф не
       Message. Курсоры — L3 Thread.
    5. Сбор только внутри Message Thread. Один поток исполнения актора —
       без handshake мутаторов. Чужие Message Thread не стопать.

6. What not to do / Чего не делать
----------------------------------

EN:
    Do not derive Structure/Array lifetime from C automatic/static duration.
    Do not hide a copy or a compact inside `return` to make locals "safe".
    Do not relocate the Structure graph because a backing block filled.
    Do not give the arena a guessed capacity and error when it overflows.
    Do not add nested turn/handler/frame arenas on top of the one L3
    Thread block list.
    Do not implement source `own:`, `borrow:`, `move:`, or an owner object.
    Do not treat a Message as a borrowed subgraph of the sender.
    Do not compact in the allocator because "there is only one thread";
    one thread is the mutator rule, not a stack map.
    Do not tree-walk value slots for reclaim; the Structure graph has cycles.
    Do not conflate Structure graph, Mix placement tree, P0 tree, or
    used-tree of Consumer.
    Do not treat Registry/Table membership as an allocator.
    Do not install a process-global GC or stop-the-world scan.
    Do not migrate Mix / own / table-class onto the one-header model from
    this plan (struct_refactoring Phase 9.1).
    Do not implement `LmOwnerArena` names until `LmOwnArena` collection is
    real; the spec forbids presenting those names as the current ABI.
    Do not "fix" language sources in `./lm2` trans/parser from a Mix-only
    change set while another machine owns that checkout — except through
    the agreed git mainline.

RU:
    Не выводить жизнь Structure/Array из automatic/static C.
    Не прятать копию или компакт в `return`.
    Не переезжать граф Structure из-за полного блока backing.
    Не угадывать ёмкость арены и не падать, когда она «кончилась».
    Не навешивать вложенные арены хода/handler/frame на список блоков
    L3 Thread.
    Не делать исходные `own:`, `borrow:`, `move:` и объект owner.
    Не считать Message заимствованным подграфом отправителя.
    Не компактировать в аллокаторе из-за «потока один»; один поток —
    правило мутатора, не карта стека.
    Не обходить слоты значений как дерево: в графе Structure есть циклы.
    Не смешивать граф Structure, дерево размещения Mix, P0 и used-tree.
    Не делать членство в Registry/Table аллокатором.
    Не ставить процессный GC и stop-the-world.
    Не переносить Mix/own на одну шапку из этого плана.
    Не внедрять имена `LmOwnerArena`, пока сбор `LmOwnArena` не настоящий.
    Не править trans/parser в `./lm2` «заодно с Mix», пока этот checkout
    пилят на другой машине — только через согласованный main.
