The design doc's own falsifier for A1-A3, cited directly: "Red for each:
  the balance test's two-cycle live count (ld --wrap) with the record's
  allocation counted as heap. It is red while any such record comes
  from malloc, and green once the arena's blocks are the only heap
  allocations" (bb082d37:1968-1970). The wrap-based pattern this refers
  to lives in l2src/tests/lmx_msg_blocks_selftest.lm1, which defines
  __wrap_free (line 17) and reports a frees=%d count (line 205);
  run_model_scenario36.ps1's own comment (127-130) names this file's

  --wrap=NAME for each such name found in its own translated C, so a
  missing hook reds the link rather than passing unnoticed. This is the
  acceptance mechanism A1-A3's own landing measures against (malloc
  count for these records goes to 0, arena-block count carries it
  instead), not a fixed numeric pin to list in advance -- the design
  doc's own words describe it as measured at landing ("red while... green
  once"), not as a number already known today.
