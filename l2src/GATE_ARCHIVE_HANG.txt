Hypotheses the plan separates
  H1  git archive itself stalls intermittently on this repository (object store, packs, worktree metadata).
  H2  the stall needs the PowerShell native call as the runner makes it (inherited console handles or stdin under
      cmd /c powershell > log 2>&1, EAP Stop), not git alone.
  H3  it needs concurrent git activity on the shared store (a checkout, commit or push in another worktree).
  H4  the output file cannot be created (something holding build\...\core.zip's directory), seen as git waiting
      before the file exists.

Proposed change: bound the archive step at 120 s (not applied, not run)
  Normal archive time is about a second; the whole gate takes 22-51 s, so 120 s cannot fail a working run.
  The change runs git as a child with its own stdout and stderr files, kills the process tree at 120 s and fails
  the gate with a named line instead of holding the chain. Process.Handle is read right after the start so
  ExitCode stays valid after the process exits (Start-Process -PassThru otherwise loses it in PowerShell 5.1).
