Hypotheses the plan separates

  H2  the stall needs the PowerShell native call as the runner makes it (inherited console handles or stdin under

  H4  the output file cannot be created (something holding build\...\core.zip's directory), seen as git waiting
      before the file exists.

The change: bound the archive step at 120 s (APPLIED, not proposed: claude-0c/archive-timeout 3f131768,
merged into d6/lock-s6 5685a48d and landed with S6-1; proven red against a stub git and green against the
real one before the merge)
  Normal archive time is about a second; the whole gate takes 22-51 s, so 120 s cannot fail a working run.
  The change runs git as a child with its own stdout and stderr files, kills the process tree at 120 s and fails
  the gate with a named line instead of holding the chain. Process.Handle is read right after the start so
  ExitCode stays valid after the process exits (Start-Process -PassThru otherwise loses it in PowerShell 5.1).

=== What the isolation measured (2026-09-15, freeze window 21:53:40-22:21) ===

The void rule, as narrowed by the coordinator during the run and recorded here by his words: "the void test
covers what sessions write: refs/heads, refs/tags, refs/remotes and worktree HEADs; refs/codex/turn-diffs/
checkpoints rotate on the tool's own schedule and are excluded from the void, but every rotation inside a
stage is logged with its time against the run it fell in, as concurrent git activity in the shared store,
because a rotation is a real ref write and, if a hang ever appears, its window is the first thing to check."
Why it was needed: the first stage C was voided by one such rotation at 22:05:34 whose before and after named
the same object (c012ed7a) - no content changed. The snapshots hold 165 refs/heads, 19 refs/tags, 169
refs/remotes, 44 worktree HEADs and 2 codex refs, so the old all-refs test made every long stage a coin flip.
Stage C was counted as clean under this rule AFTER it had been voided under the old one; that ordering is
stated here deliberately rather than hidden. isolate_archive_hang.ps1 implements it in Get-HangRefState,
Get-HangCodexRefs and Write-HangCodexRotations, the last mapping a rotation to the run whose window contains
it by decoding the 13-digit epoch-ms the tool puts in the ref path - not by polling refs per run, which would
inject stage D's own variable.
