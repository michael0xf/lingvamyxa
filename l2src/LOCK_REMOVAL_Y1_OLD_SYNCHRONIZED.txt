--- What the translator emitted: the C shape

For `synchronized: @lock <body>`:

    void *__sync_N = (void *)(<lock-expression>);
    lm_synchronized_enter(__sync_N);
    {
        <body, as an ordinary statement list>
    }
    lm_synchronized_leave(__sync_N);   /* fall-through */

and, at every early exit inside <body> (return, break, continue), the same
lm_synchronized_leave(__sync_N) call is re-emitted just before that exit's
own C control transfer, via the cleanup-stack walk (lm_trans_emit_cleanups_until),
so the block is not a plain C brace pair but a per-exit-path duplicated
release, matching a structured try/finally shape rather than a single
guaranteed-once cleanup. Reentrancy: none tracked by the emitted code
itself -- __sync_N is a bare void* holding whatever the lock-expression
evaluated to; no generation counter, no owning-thread field, no depth field
in the emitted C, only in the two ad hoc test/Mix stand-ins for enter/leave
themselves (and even there, the depth field enforces nothing: it counts,
it does not block).

What it locked on: exactly the evaluated `<lock-expression>` value, cast to
void*, passed opaquely to enter/leave -- the translator never inspects or
requires anything about that value (no type check tying it to a monitor
type); "the object" in the spec's sense is whatever expression the caller
wrote.

--- How far it was implemented

Parsed: yes, but not specially -- synchronized is an ordinary P0 receiver
head with a one-argument positional-name signature (trans_registry.lm2:793),
parsed by the same general receiver grammar as fn/sub/thread; P0 itself
does nothing synchronized-specific.

Emitted: yes, completely, including the harder part -- correct cleanup
insertion on every structured-exit path (return, including value-returns
with correct value-capture-before-release ordering; break; continue) via
the shared cleanup-stack machinery also used by `finally`.

Runtime-implemented: no. grep across the whole old tree (source and the
generated lm1/build/trans.lm1.c and trans_library.lm1.c) finds
lm_synchronized_enter/lm_synchronized_leave called and referenced, but
defined nowhere as a real runtime primitive -- no header, no .c file, no
generated C function body anywhere provides them. The only two definitions
in the entire tree are the local, non-thread-safe test/Mix.lm2 stand-ins
described above, each private to its own translation unit. Any other
program using `synchronized` would translate and compile but fail to link.
lm_resolve_lock_handle, the resolution helper the current spec's own
illustrative ANSI C names (see below), does not exist anywhere in this
tree either.

Tested: only the translator's own cleanup-ordering correctness (the one
test file, four structured-exit cases), never real mutual exclusion, never
reentrancy, never any concurrent or multi-thread access.

--- Where it fell short of the spec's receiver description (Lingvamyxa_spec.txt
    on main, section 20.5.7, `synchronized`, lines 15045-15125)

1. "The runtime hook must implement the selected monitor policy, including
   Java-style reentrant entry for the same thread when that profile is
   selected" (spec:15111-15112). Not implemented at all, anywhere, in any
   form -- no monitor, no policy selection, no reentrant-entry tracking.
   The only two functions bearing these names in the whole tree are
   non-atomic depth counters with no locking semantics.

2. The spec's own illustrative ANSI C (spec:15090-15091) resolves the lock
   handle through a named helper first: `Lmx *lock_handle =
   lm_resolve_lock_handle(containing_structure, /* object */);` before
   calling enter. The old tree's actual emission skips straight from the
   evaluated expression to a bare `(void *)(...)` cast -- no
   lm_resolve_lock_handle or equivalent resolution step exists anywhere in
   this tree (checked by name).

3. The spec ties safe value-return handling to "the fixed
   status-plus-typed-outputs ABI (21.13.4)" (spec:15118). That section
   number and that phrase do not appear anywhere in the old tree's own copy
   of Lingvamyxa_spec.txt -- this ABI postdates the old tree entirely. The
   STRUCTURAL requirement it is used to justify (value made safe before
   monitors release) does appear to already hold in the old tree's own
   terms -- lm_trans_emit_return_statement captures the return value into a
   temporary before calling lm_trans_emit_cleanups_until -- but that match
   is coincidental to a simpler, unnamed mechanism, not an implementation
   of the ABI the current spec cites; recorded as a partial correspondence,
   not a full one, since the ABI it is measured against did not exist yet.

4. No code or test anywhere in the tree exercises `synchronized` under
   actual concurrency (multiple threads, or even multiple fibers/turns
   contending for the same lock expression) -- consistent with finding 1,
   since there is no real monitor to contend over. The spec's own
   framing of `synchronized` as belonging to "the Message mechanism" and
   coordinating through Messages (20.5.7's second paragraph, echoing
   19.28.R2.2) has no counterpart in the old tree at all: Mix.lm2's usage
   predates the Message model entirely (it locks page/node structures in a
   flat page-table design, not Messages), and the test file's usage is
   single-threaded by construction.
