Citation (section and quoted phrase, never a bare line)
  Spec line numbers drift: each verbatim entry Mikhail approves is appended and shifts everything below it.
  The ticket's "spec 12885-12891" was 19.29.7's opening at the hour it was written, and by the next fetch
  the paragraph meant had moved (the coordinator's rule from now, mine included: cite the section and a
  quoted phrase with the commit read, so the reader re-finds it by grep after the file moves).
  The three rulings this removal rests on, read at origin/main 077ee6fd (Lingvamyxa_spec.txt, 16213 lines):
    refs      19.29.7 Message Boundary (heading at 12889), the phrase "there is no count of holders"
              (12909): a capability is the target's mailbox handle, and a closing Message's mailbox is
              settled into its parent with the rest of its storage, "so a late send lands in a mailbox the
              parent owns and is refused there, on the parent's lane, with a status to the sender; there is
              no count of holders" (agreed with Mikhail 2026-09-15, "davay tak"). No count of holders is
              exactly LmxMsg.refs and endp_retain/endp_release going.
    slots/n   19.28 Message Thread and Runtime Operators (Revision 2) (heading at 11480), the phrase "the
              slot list served only the L1 delete loop and its address lookup and goes without replacement;
              the retire queue goes (a closed child's storage is its parent's settle write)" (11635-11637)
              -- Mikhail's confirmed "da" on the runtime-level structures the L1 implementation kept under
              its executor's lock.
    release   19.29.6 Running Message (L3 Thread) (heading at 12630), the phrase "reclaimed, arena and slot"
              (12755): a successful orphan "is settled at its end-turn and reclaimed, arena and slot, by the
              settling lane at the root's next maintenance point", with the parent's dispose that "releases
              the child's slot". This is the accounting scenario36's rt\n pins currently express.
  The design says the same in LOCK_REMOVAL_DESIGN.txt (d6/lock-removal) 1244, 1249-1250 and 1277: slots and
  n are the runtime-wide allocation list through LmxMsg.alloc_next, and they "wait for S6, which removes
  refs, because until then runtime_delete needs them".

Method
  Each gate's runner and the test files it builds, at baa8ec23; git grep over those for the removed names:
  endp_retain, endp_release, endp_refs, lmx_msg_slots, slots_n, slots_at, run_port_msg_slots, and, as
  literals because they carry the L1 field-follow backslash, \refs, rt\n, rt\slots and \alloc_next.
  endp_refs was MISSING from the first version of this list (b5 caught it, 2026-09-15, while building
  sonnet/s6-2-test-inventory against 16335e9b): the first pattern set named the two mutators and not the
  accessor, so the two gates that assert refs were understated by 15 lines. Corrected here, and the lesson
  is the pattern itself: grep a removed symbol's whole family (lmx_msg_endp_*), not the names the ticket
  happens to list. No gate's verdict changed - both were already "asserts" - but the edit is larger.
  Field greps were run
  through PowerShell: a backslash pattern through the Bash tool silently matches nothing here, which would
  have reported every rt\n row as clean.
  Then a second sweep the first pass did not cover: every runner that names lmx_msg_slots as a SUPPORT
  module to translate and link. That is not an assertion, so those gates are still "unaffected" in the
  assertion sense, but the name has to go from each list with the module, and a missed one reds the gate at
  build. This is the link-time class the S2 list missed once; it is measured here per runner, with the line.
  Two false-positive classes were separated by reading the hit, not the name:
  - run_graph_abi.ps1 names a slot API 11 times (lmx_branch_slot_known, lmx_branch_store_known). That is the
    graph slot API, not LmxMsgRuntime's slot array, and S6-2 does not touch it. graph_abi is listed as
    asserting on its own evidence (531-539 below), not on those 11.
  - lmx_message_exec_selftest.c names InterlockedCompareExchange 174 times. Those are the selftest's own
    cells and its turn counters; the two the ticket removes are the ones inside endp_retain/endp_release in
    lmx_message_exec.c. Counted as refs hits: only the 6 endp_ lines.

  lmx_message_exec_selftest.c, four cases: "exec mail-oom" (6017, 6027, 6030) restates as inbox-still-0 plus a
    liveness check; "exec outbox-gone" (6157, 6172) restates as inbox-0 plus a state check, dropping the refs
    upper bound; "exec pin-oom" and "exec nself-pin" (6204-6624) are WHOLE-CASE deletions, not restatements.
  Why those two cannot be restated, checked here at baa8ec23 rather than taken on faith: both drive
    lmx_msg_test_fail_retain, and that hook lives INSIDE lmx_msg_endp_retain's own body - exec.c:347 opens the
    function and 348-353 is the #if defined(LMX_MSG_EXEC_TEST) block that decrements the counter and returns 0
    to simulate a failed retain. Delete endp_retain and the injection point goes with it: there is nothing left
    to inject into, which is why the cases go whole rather than losing a line each. So S6-2 removes a
    fault-injection hook as well as an API - a consequence neither this list nor b5's inventory stated in those
    terms, and one the lead's allowlist needs, since the selftest sets that variable at 407, 6214, 6620, 6625
    and 6630 too.
  Not to be confused with it: lmx_msg_test_fail_post_dead (exec.c:332) is a sibling hook, read in
    lmx_msg_test_post_dead_fail (exec.c:335-345), OUTSIDE endp_retain. S6-2 does not touch it, and deleting it
    with the family would remove an injection point nothing in this stage requires removing.

== Fixtures reading handoff_ready right after a stop, with no spin on the flag ==

  l2src/tests/lmx_msg_family_handoff_selftest.lm1   3 / 0   EXPOSED
    334 reads lmx_msg_handoff_ready(rt, successful) right after yield_until_stopped(rt, successful); that
    helper (160-163) spins only on lmx_msg_state(rt, who) != LMX_MSG_STATE_STOPPED. 350 reads it after
    lmx_msg_drive, 354 after the c_status stored from yield_until_stopped at 347. None waits on the flag.
    Why that is a race and not a style point: STOPPED is written by the core's closing path
    (lmx_message.lm1:1736 and 1784, mirrored in lmx_message.lm2:1815 and 1863), while handoff_ready is set
    later, in native_leave_addr (lmx_message_exec.c:1762-1763), once the turn's native user leaves. STOPPED
    is therefore observable before the flag, and a state-only spin can return inside that window.
  l2src/lmx_message_exec_selftest.c                12 / 0   NOT exposed, by ordering
    No loop names the flag, but every read follows own_turn (selftest 1206-1228), which spins on
    g_seen_turns; that counter is incremented by the after_turn hook seen_after_turn (1161-1165), which
    lmx_message_exec.c fires at 1769-1770 -- strictly after handoff_ready = 1 at 1762-1763, with the
    comment "after its record is released and its settle is published". The hook is a sound guard; these 12
    reads need no change.
  l2src/tests/lmx_model_family_release_17_selftest.lm1  15 / 8   guarded (while: ... handoff_ready = 0)
  l2src/tests/lmx_model_orphan_mapped_17_selftest.lm1    4 / 2   guarded
