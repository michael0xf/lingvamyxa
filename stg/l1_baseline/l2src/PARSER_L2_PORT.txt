Parser-in-L2 port (branch sonnet/parser-l2)
============================================

Scope
-----
A clean-L2 equivalent of l1src/parser.lm1 (the oracle), built function by
function into l2src/parser.lm2, proven against the existing 620-golden
parity gate (tests/p0_tree_contract). l1src/parser.lm1 itself is never
edited. The 25 existing parser_*.lm2 fragments predate this ticket (built
for a different purpose -- l2trans's own self-hosted scanner, lm_p0_*
named) and are a starting point for logic reuse, not something this port
calls into or modifies. Ported operations are named p0_*, never lm_p0_*
(the translator's reserved adapter family), and never call lm_p0_* either.
Authority: lingvamyxa-e2 assigns and accepts each stage; lingvamyxa-d6 owns
any core l2trans/l1trans fix a stage's own gap needs.

Each stage's own units are written straight from l1src/parser.lm1's body
-- the oracle is the source, not the fragments. A fragment covering the
same functions is read as a cross-check on the logic (and sometimes on
Stage A prototype/predef shape), never copied over the oracle's own
current text; a fragment can predate a change already landed in
parser.lm1 and silently disagree with it. Do not "restore" a unit's body
from its matching fragment on the theory that the fragment is the
original -- re-derive from l1src/parser.lm1 as it currently reads.

Mechanism
---------
Per-stage, l2src/run_port_parser.ps1 builds two p0_meta_dump executables
against the same tests/p0_tree_contract driver and goldens:
  Ref  -- the pristine, tracked lm1/build/parser.lm1.c, untouched.
  Port -- a disposable copy of that same generated C with the stage's
          ported functions' own definitions renamed aside (name ->
          name__l1, left as dead code) and every remaining reference --
          including internal cross-calls between oracle functions, e.g.
          is_field_space calling is_horizontal_space -- redirected via
          -Dname=p0_suffix to the L2 unit's real implementation.

The redirect target's C prototype is captured mechanically from the
renamed function's own original definition line (never hand-typed), so a
signature drift cannot hide behind a stale hand-written declaration;
-Werror=incompatible-pointer-types and -Werror=implicit-function-
declaration are the cross-check.

This replaces an earlier plan (objcopy --redefine-sym / --weaken-symbol
on the compiled oracle object). That does not override on this PE/COFF
toolchain: both the weakened and the strong definition survive as
separate symbols at separate addresses in the linked binary, and internal
call sites keep resolving to the local (un-overridden) one. Confirmed via
a positive falsifier (linking a probe with a printf side effect: the
override fired at the oracle's own internal call sites when source-level
redirect was used, and never fired under the objcopy plan) and a negative
control (the unwired pristine build gives an identical result with zero
override calls). Reported to and accepted by lingvamyxa-e2, 2026-09-14.

Stages landed
-------------
a) parser_text.lm1 primitives -- l2src/parser_text_port.lm2 (commit
   4715eac3). All 15 functions: p0_text_equals, p0_identifier_payload,
   p0_is_horizontal_space, p0_is_line_break, p0_line_break_width_at,
   p0_is_field_space, p0_is_field_separator, p0_is_short_form_separator,
   p0_is_quoted_token_boundary, p0_starts_python_string,
   p0_is_decimal_digit, p0_copy_bytes, p0_text_view_new_cstr,
   p0_text_view_delete, p0_text_from_cstr. 36/36 goldens identical
   (Ref vs Port), including exit codes. p0_text_equals and
   p0_identifier_payload (both take a const array-of-one struct formal)
   were blocked by l2trans's "formal type 4" gap until d6's f29800c4;
   both are ported.
   Falsifier checked before landing: is_horizontal_space temporarily
   forced to always return false produced 34/36 mismatches against the
   same goldens; reverting restored 36/36 with a clean diff against the
   original source.

b) l1src/parser.lm1's own scanning primitives -- l2src/parser_scan_port.lm2
   (commit 7abac716). 11 functions: p0_indent_tab_column,
   p0_scan_indent_column, p0_visual_column_between, p0_count_line_breaks,
   p0_position_in_slice, p0_advance_layout_line, p0_index_is_line_start,
   p0_line_rest_is_horizontal_space, p0_find_physical_line_end,
   p0_scan_layout_prefix, p0_layout_prefix_is_deeper. Ported straight from
   the oracle's own body (not the pre-existing parser_position.lm2/
   parser_visual_column.lm2/parser_line_start.lm2/parser_physical_line.lm2/
   parser_scan_indent.lm2/parser_scan_layout_prefix.lm2 fragments, which
   carry closely related logic under lm_p0_ names for a different
   purpose), using decimal character codes rather than the oracle's
   '\t'/'\r'/'\n'/'.' literal spelling -- a spelling choice only.
   Depends on Stage a's p0_is_horizontal_space/p0_is_line_break/
   p0_line_break_width_at via a predef'd prototype: header
   (parser_scan_port_l2.h.lm1) -- the first cross-stage dependency; see
   "Cumulative stages" below. 36/36 goldens identical.
   The oracle's own `---` while-loop tail cutter (CODING_RULES §7: a
   dedent of two or more levels needs one; 120 occurrences in
   parser.lm1 alone) is kept wherever the oracle uses one; hit it as
   l2trans parse error 13 on the first translate attempt ("source
   level decrease must be one step unless a tail cutter is used") for
   p0_scan_layout_prefix's nested while. Expect it in every later
   stage's own state machines (e2, 2026-09-14).
   Falsifier: p0_position_in_slice temporarily forced to always report
   line=0 produced 34/36 mismatches; reverting restored 36/36.

c) node/structure/frame allocation, partial -- l2src/parser_alloc_port.lm2.
   Only p0_node_kind_class_name and p0_free_node land in this pass; both
   are the whole of parser.lm1's allocation family that don't need
   document\tree_arena. No fragment exists for any of this stage's
   functions. 36/36 goldens identical.
   p0_free_node's formal is renamed nd, not node: "node" is a reserved
   L2 identifier (l2_ident refuses main/fn/int/return/if/else/while/
   for/node -- d6, 2026-09-14, same rule as the oracle-local rename in
   history_owned), so any `@: T node` formal is refused regardless of
   T. p0_node_kind_class_name takes `int: kind`, not the oracle's
   `LmP0NodeKind: kind`: l2trans rejects any not-yet-known `type: X
   int` alias as a formal/return (a different, unnumbered gap from the
   "formal type N" family LmP0TrailerRole etc hit -- on d6's Stage B
   translator list, covers the whole class of type aliases in one
   change). LmP0NodeKind is a bare int alias with no distinct
   representation, so this is behaviorally identical; switch back once
   fixed.
   p0_new_structure, p0_new_frame and p0_new_node are NOT ported yet:
   all three need document\tree_arena, and field access through an
   @: LmP0Document formal is refused entirely ("unknown foreign
   field", any field, any formal name) -- also d6's Stage B: LmP0Text/
   LmP0IndentStack/LmP0Document carry translator built-in formal codes
   (4/5, 14/15, 13) that bypass the foreign-interning path ordinary
   structs like LmP0Frame go through, so `doc\field` never resolves.
   Land those three, plus lm_p0_set_diagnostic/lm_p0_new_text calls
   through a predef'd prototype: header (the Stage A shape for a
   not-yet-ported oracle dependency, confirmed correct by e2,
   2026-09-14), once fixed.
   Falsifier attempted: p0_node_kind_class_name's STRUCTURE case
   mutated to return "frame" produced zero mismatches. Traced, not a
   mechanism gap: nm on the linked Port executable confirms the
   redirect took effect correctly (one p0_node_kind_class_name symbol,
   the oracle's own renamed to __l1, no bare lm_p0_node_kind_class_name
   left) -- the oracle's own caller, lm_p0_dump_node, is simply never
   exercised by p0_meta_dump.c, which has its own independent
   `fprintf(out, "node kind=%s ...")` metadata path (matches run_
   p0_meta.ps1's own comment, "Pretty printTree is not the metadata
   oracle"). Worth flagging for the dump-printer half of this stage:
   the whole lm_p0_dump_* family may be similarly unexercised by these
   goldens, which would mean 36/36 green there proves less than it
   does for the rest of the port -- something to raise with e2 before
   porting that half.

Not observable by the 36 tests/p0_tree_contract goldens
----------------------------------------------------------
A mutation tried as a falsifier that produced zero mismatches. This is
a coverage fact about that golden set, not about the port -- the
oracle and its C are untouched by any of this, and the mismatch check
itself (Ref vs Port, byte-for-byte including exit codes) is otherwise
sound. Not something for this port to fix by adding goldens; the 620
reference and tests/p0_tree_contract are lingvamyxa-d6's lane, and
this list is what he extends from if he wants a golden that closes one
of these.
- p0_index_is_line_start (Stage b): forced to always return 0.
- p0_node_kind_class_name (Stage c): STRUCTURE case forced to return
  "frame". Not a coverage gap in the usual sense -- the oracle
  function that calls it, lm_p0_dump_node, is architecturally
  unreachable from p0_meta_dump.c (see Stage c above); every other
  function on this list is reachable but the specific mutation didn't
  surface.

Cumulative stages
------------------
run_port_parser.ps1's $Stages table lists every unit and oracle name
landed so far at each stage, not just what's new: a later unit's own
calls into an earlier stage's p0_* functions need that earlier unit's
real compiled object linked in, and the oracle-side redirect set has
to cover every ported name so no internal oracle call reaches an
un-redirected body. Each stage links every earlier .lm2 unit alongside
its own.

Build and verification
-----------------------
Run l2src/run_port_parser.ps1 from any directory (it locates itself and
Set-Location's to stg/l1_baseline). It verifies the pinned l1trans hash
against L1_PIN.txt, builds l2trans.exe fresh from l2src/l2trans.lm1 each
run, builds the runtime-trio headers/objects (cached across runs, in
build/port_parser/l2rt_*), then for each stage in its $Stages table:
translates the stage's .lm2 units (their own lm_own_* calls resolve
externally to l1src/own.lm1's real implementation via a predef'd
prototype: header, per d6's 4abf4fba -- no fallback body to strip),
builds the patched oracle copy, links Ref and Port, and diffs every
tests/p0_tree_contract/*.lmx golden's output between them.
Generated sources, objects, executables and per-golden output stay under
build/port_parser (gitignored, not committed).

Out of scope, reported and since fixed
-----------------------------------------
tests/p0_tree_contract/run_p0_meta.ps1 (the standing 620-golden script,
independent of this port's own mechanism) threw on A_compact_f_paren:
the pinned-old-checkout build reported source_len=11 (matching the
tracked .lmx -- 11 bytes, LF, gitattributes eol=lf) but the golden
.meta.txt said source_len=12 -- 17 of the A-G goldens turned out to
have this same CRLF-checkout drift, not just this one. Raised to
lingvamyxa-d6 via e2, 2026-09-14; he regenerated all 17 through
run_p0_meta's own P0_META_WRITE_GOLDEN=1 path and confirmed the diff
touched only lengths/spans. Fixed as of 58314636, run_p0_meta.ps1 is
36/36 again. run_port_parser.ps1 never depended on the old checkout
and was unaffected either way.
