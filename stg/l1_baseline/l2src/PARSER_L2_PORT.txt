Parser-in-L2 port (branch sonnet/parser-l2)
============================================

Scope
-----
A clean-L2 equivalent of l1src/parser.lm1 (the oracle), built function by
function into l2src/parser.lm2, proven against the existing 620-golden
parity gate (tests/p0_tree_contract). l1src/parser.lm1 itself is never
edited. The 25 existing parser_*.lm2 fragments predate this ticket (built
for a different purpose -- l2trans's own self-hosted scanner, lm_p0_*
named) and are a starting point for logic reuse, not something this port
calls into or modifies. Ported operations are named p0_*, never lm_p0_*
(the translator's reserved adapter family), and never call lm_p0_* either.
Authority: lingvamyxa-e2 assigns and accepts each stage; lingvamyxa-d6 owns
any core l2trans/l1trans fix a stage's own gap needs.

Each stage's own units are written straight from l1src/parser.lm1's body
-- the oracle is the source, not the fragments. A fragment covering the
same functions is read as a cross-check on the logic (and sometimes on
Stage A prototype/predef shape), never copied over the oracle's own
current text; a fragment can predate a change already landed in
parser.lm1 and silently disagree with it. Do not "restore" a unit's body
from its matching fragment on the theory that the fragment is the
original -- re-derive from l1src/parser.lm1 as it currently reads.

Mechanism
---------
Per-stage, l2src/run_port_parser.ps1 builds two p0_meta_dump executables
against the same tests/p0_tree_contract driver and goldens:
  Ref  -- the pristine, tracked lm1/build/parser.lm1.c, untouched.
  Port -- a disposable copy of that same generated C with the stage's
          ported functions' own definitions renamed aside (name ->
          name__l1, left as dead code) and every remaining reference --
          including internal cross-calls between oracle functions, e.g.
          is_field_space calling is_horizontal_space -- redirected via
          -Dname=p0_suffix to the L2 unit's real implementation.

The redirect target's C prototype is captured mechanically from the
renamed function's own original definition line (never hand-typed), so a
signature drift cannot hide behind a stale hand-written declaration;
-Werror=incompatible-pointer-types and -Werror=implicit-function-
declaration are the cross-check.

This replaces an earlier plan (objcopy --redefine-sym / --weaken-symbol
on the compiled oracle object). That does not override on this PE/COFF
toolchain: both the weakened and the strong definition survive as
separate symbols at separate addresses in the linked binary, and internal
call sites keep resolving to the local (un-overridden) one. Confirmed via
a positive falsifier (linking a probe with a printf side effect: the
override fired at the oracle's own internal call sites when source-level
redirect was used, and never fired under the objcopy plan) and a negative
control (the unwired pristine build gives an identical result with zero
override calls). Reported to and accepted by lingvamyxa-e2, 2026-09-14.

Two acceptance drivers
------------------------
tests/p0_tree_contract/p0_meta_dump.c never calls l1src/parser.lm1's
own lm_p0_dump_alloc/lm_p0_dump_run/lm_p0_dump_node family (its own
"Pretty printTree is not the metadata oracle" comment says as much) --
so a 36/36 green through it proves compile-and-link for that family,
not behavior. l2src/p0_dump_driver.c (e2, 2026-09-14) is this port's
own second driver, specifically for that family: it parses each
fixture via lm_p0_parse_file the same way p0_meta_dump.c does, then
calls the oracle's own public entry point, lm_p0_dump_alloc, and
prints its result verbatim. run_port_parser.ps1 builds both drivers,
Ref and Port, for every stage and requires 36/36 identical through
each independently (Test-GoldensBetween, called twice per stage).

Which functions each driver actually exercises, so a green run means
what it looks like it means:
- p0_meta_dump.c: parser.lm1's own structural fields directly (node/
  frame/structure/trailer kind, flags, span, text) -- everything
  ported in Stage a and Stage b, and p0_free_node (called nowhere in
  either driver's own reachable graph, but its body is a no-op --
  covered by inspection, not exercised by either driver).
- l2src/p0_dump_driver.c: the lm_p0_dump_* family once it's ported
  (dump_alloc/dump_run/dump_node/dump_append*/dump_push_*/dump_new/
  dump_take_data/dump_delete), and, incidentally, p0_node_kind_class_
  name (called from inside lm_p0_dump_run) -- confirmed by the
  falsifier above; p0_meta_dump.c does not reach it.
Functions in both p0_text_port.lm2 and p0_scan_port.lm2 are exercised
by p0_meta_dump.c only (they don't touch node/dump structures), so
their own falsifiers were checked against that driver alone.

Cumulative stages
------------------
run_port_parser.ps1's $Stages table lists every unit and oracle name
landed so far at each stage, not just what's new: a later unit's own
calls into an earlier stage's p0_* functions need that earlier unit's
real compiled object linked in, and the oracle-side redirect set has
to cover every ported name so no internal oracle call reaches an
un-redirected body. Each stage links every earlier .lm2 unit alongside
its own.

d) stack/stream event machine -- l2src/parser_stack_stream_port.lm2
   (new unit, header l2src/parser_stack_stream_port_l2.h.lm1, no
   `profile: runtime`, l1src/parser.lm1 is the twin, unedited).
   5 slices, accepted by e2 2026-09-14: d1 lifecycle, d2 stack
   geometry, d3 lineage/trailer-attach, d4 trailer-item parse +
   delimiter resolve, d5 event application core. One commit per
   slice. Any not-yet-ported oracle callee is called through this
   unit's own prototype: header (Stage A pattern); removed from the
   header in the same commit that ports the callee.

   Capstone scope, carved OUT of Stage d (e2/d6, 2026-09-14): tracing
   real callees, lm_p0_record_mix_mark (reached from the brace-mark/
   mix-prefix scanning family lm_p0_parse_stream needs) calls
   lm_p0_postprocess_node (Stage f), lm_p0_validate_nonempty_colon_
   frames_in_node (Stage g), and recurses into lm_p0_parse_stream
   itself. So lm_p0_record_mix_mark, the disabled-block-validation
   family (lm_p0_validate_disabled_item_text, lm_p0_disabled_scan_
   next_event, lm_p0_disabled_event_is_tail_cutter, lm_p0_disabled_
   state_accept_event, lm_p0_validate_disabled_block), and
   lm_p0_parse_stream itself are OUT of Stage d's scope -- they land
   as a capstone once Stages e/f/g exist, so every Stage d slice's
   36/36 claim is honestly reachable by both existing drivers today,
   not contingent on later stages.

   d1 (lifecycle, 17 fns) -- l2src/parser_stack_stream_port.lm2:
   p0_stack_free, p0_stack_free_any, p0_stack_new, p0_stack_delete,
   p0_pending_delimiter_new, p0_stream_event_new, p0_stream_event_
   new_copy, p0_stream_event_delete, p0_stream_event_is_tail_cutter,
   p0_pending_delimiter_clear, p0_pending_delimiter_delete,
   p0_pending_mix_new, p0_pending_mix_free, p0_pending_mix_free_any,
   p0_pending_mix_delete, p0_disabled_state_new, p0_disabled_state_

   pure predicate (stream_event_is_tail_cutter) grouped here since it
   has no in-unit dependents. Its own two callees, lm_p0_trailer_role

   called through the header's prototype: block (both resolve to
   their real C symbols, lm_p0_trailer_role and lm_p0_trailer_role_
   is_tail_cutter, until/unless a later stage ports them and adds
   them to a run_port_parser stage's Funcs list).
   36/36 goldens identical, both drivers (stage d_lifecycle). Falsifier:
   p0_stack_new forced to return 0 unconditionally (simulated
   allocation failure) -- measured 71 mismatches across 36 goldens x 2
   drivers (not the full 72): diffing every pair found exactly one

Build and verification
-----------------------
Run l2src/run_port_parser.ps1 from any directory (it locates itself and
Set-Location's to stg/l1_baseline). It verifies the pinned l1trans hash
against L1_PIN.txt, builds l2trans.exe fresh from l2src/l2trans.lm1 each
run, builds the runtime-trio headers/objects (cached across runs, in
build/port_parser/l2rt_*), then for each stage in its $Stages table:
translates the stage's .lm2 units (their own lm_own_* calls resolve
externally to l1src/own.lm1's real implementation via a predef'd
prototype: header, per d6's 4abf4fba -- no fallback body to strip),
builds the patched oracle copy, links Ref and Port, and diffs every
tests/p0_tree_contract/*.lmx golden's output between them.
Also builds, once and cached (build/port_parser/l2rt_objs, alongside
the runtime trio), p0_dump_alloc_counter.o from
l2src/p0_dump_alloc_counter.c -- the leak-balance counter both
p0_dump_driver executables link against; see "Slice 4 (lifecycle)"
above for why it must never be compiled with a stage's own -D
redirects.
Generated sources, objects, executables and per-golden output stay under
build/port_parser (gitignored, not committed).
