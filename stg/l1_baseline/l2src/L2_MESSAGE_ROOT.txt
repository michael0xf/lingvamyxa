Generated unit root binding and owned graph construction
=======================================================

l2trans's graph-unit path emits a synthetic l2_program_entry adapter and an
outer native main. Before constructing the unit, main creates one local Message
runtime and its process root using existing runtime_new/create/find APIs. Once
the unit's initial child block is constructed, set_graph records its exact
address in that Message. No node is rewritten and source-method signatures are
unchanged. The synthetic adapter is not an LMX method or a new implicit owner
parameter. On each ordinary adapter return, including construction failure,
main deletes the runtime and returns the original program status. Runtime/create/
lookup failure paths also release any successfully created runtime once.

run_l2trans links generated Message-using programs against real Message support,
never lmx_poll_stub. The translator and unrelated old harness programs keep the
stub where needed. Headers/modules are translated once and thirteen support
objects compiled once per runner invocation/source snapshot/flags. The same
objects serve compatible subsequent programs. No cross-run stale object cache.
BuildOnly exposes the existing translator build and functions without executing
the large historical suite; OutputDirectory and TranslatorPath allow a private
snapshot runner with the stable compiler kept read-only.

run_l2_message_root uses an immutable core git archive with the five current
owned implementation/driver files overlaid and hashed. It builds one translator,
translates unit_bool_and through L2 -> L1 -> C, links the real Message once, and
uses a test-only L1 driver for runtime-new/create/lookup failures, allocation
failure before and after graph binding, and successful execution with preserved
nonzero return value. Normal program and instrumented driver share support
objects; no compiler self-build or repeated Exec suite is needed.
The historical splice driver now inserts its body inside the synthetic adapter
and preserves the outer main/Message teardown. A focused spliced method call
checks this route and a zero exit using the same already-built support objects.

Owned branch checkpoint, 2026-09-11
---------------------------------
lmx_branch_owned.h.lm1/.lm1 is a separate header/module, leaving the legacy
lmx_branch predef and its standalone link dependencies untouched. Both generated
construction sites (unit children and supported nested for-body children) call
lmx_branch_open_owned(parent, children, &msg->blocks, &msg->ranges). All emitted
closed-unit child accesses use lmx_branch_child_known: null/bounds checks over
the compiler-proven Structure layout, not a global classifier or runtime owner
search. Source-method signatures and dirty-only publication are unchanged.

The constructor requires an empty parent and exclusive owner access. It checks
zero/overflow/null inputs, prepares one nonmoving child allocation containing its
range record, and a separate free-compatible block-list node. The child array
offset is a multiple of sizeof(Lmx), preserving malloc alignment without C11
alignof or flexible-array extensions. Paired storage_move_all admission precedes
publication of parent.data/len. Allocation or admission failure frees temporary
storage and leaves both destination lists and the parent unchanged. New children
are initialized with their actual lexical parent; no existing node is rewritten.
These child blocks have no global registration or dual-registration. Message
cleanup retires their embedded ranges before releasing payloads and block nodes.
Do not pass this storage to the legacy branch_release function.

Owned root and METHOD checkpoint, 2026-09-11
------------------------------------------
lmx_value_owned.h.lm1/.lm1 adds fresh typed construction with existing Lmx and
LmxMethod layouts. lmx_node_new_owned admits a zero-initialized root occurrence;
lmx_method_new_owned admits an initially empty METHOD record, which its caller
fills before publishing into the graph. These are construction APIs under
exclusive owner access, not ways to mutate existing callable records.

Like branch construction, each prepares a nonmoving payload with embedded range
metadata plus a separately free-compatible block node. The payload offset is a
multiple of the concrete type's size. Null owner slots and size overflow reject
before allocation. Allocation/admission failure releases temporary allocations
and preserves both owner list heads. The public header exposes only the two
concrete constructors, not arbitrary runtime type admission.

Generated unit and METHOD construction now use these owner-head APIs instead
of raw malloc/global registration. METHOD publication no longer consults the
global classifier. After an initial branch failure, the outer Message cleanup
releases the already-owned root; no raw free(unit) remains. Ordinary completion
also releases root/METHOD allocations through Message storage. Lexical node and
source-method ABI are unchanged. Stable typed addresses/range metadata travel
together through existing storage_move_all; no owner lookup is introduced.

Owned int and size_t checkpoint, 2026-09-11
-----------------------------------------
The same value module now constructs zero-initialized, unique int and size_t
cells in Message storage with existing PRIMITIVE/INT/SIZE_T tags. Updates retain
the cell address. Known typed read/store helpers guard null and operate on the
compiler-proven live cell type, not on an arbitrary raw address and not through
a global type/owner lookup. These preconditions are explicit in the header.

Both generated field-construction sites, own-cache loads, dirty-only publication
and explicit graph paths use the new primitives. No int/size_t pool initialization
is emitted; ordinary units no longer import the legacy int/size_t pool modules.
Source-method signatures, same-name argument binding, actuals-before-checkpoint,
no-reload and graph-address semantics are unchanged. Interned characters remain
on the legacy intern-by-value path; this is NOT a change to character semantics.

Historical splice bodies are adapted only in the synthetic graph-entry route:
known child/primitive accessors and requested int/size_t construction use owned
storage there. Ordinary legacy standalone routes are not globally rewritten.
The old mandatory global METHOD-classifier assertion and views pool-take assertion
now check owner-local construction. No whole historical suite was rerun here.

Remaining limitations (not fixed or blessed by these checkpoints)
---------------------------------------------------------------
Interned characters and the legacy range catalog still remain; the adapter still
initializes that catalog. P0/foreign predefs can still bring in old definitions.
There is no claim that all remaining generated global state or allocations are
gone. Root/METHOD/CHILDREN/int/size_t owner admission is NOT evidence of complete
graph collectibility, reference-ARRAY admission or full allocation cleanup. These
checkpoints add no owner-link, TLS owner lookup, global registry, arena relocation
or scheduler.
It does not make the generated main a scheduled/bound turn, implement full
delivery/merge, or establish completed L2 self-hosting. The older leaf-adapter
translation path is also separate from graph-unit emission.
