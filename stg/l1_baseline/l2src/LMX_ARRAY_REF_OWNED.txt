Positive reference-array owned storage, 2026-09-11

Boundary agreed in Grok215200 and Codex220400. Public API:
lmx_array_ref_new_positive_owned(type,count,blocks,ranges).
Accepts exactly ARRAY_OF_LMX/DESC/METHOD, count>0. Descriptor {len,data}
has KIND_ARRAY and concrete array ID. Separate contiguous pointer backing
has KIND_REF and T=LMX/DESC/METHOD, stride sizeof(void*), initially null on
the admitted MinGW native target. No per-element headers or owner links.
Multiple arrays of the same T keep separate ranges with the same type IDs.

Descriptor/backing allocations each embed their range metadata and have a
separate block node. Four allocations are prepared on private heads, then
one storage_move_all admits both lists. Invalid inputs/overflow allocate
nothing. OOM or admission failure retires private ranges before freeing
private blocks and preserves caller heads. Positive-only does not choose
the source empty-array representation. This helper neither allocates nor
publishes referents, traces a graph, resizes storage nor integrates a compiler.
The caller remains responsible for same-Message referents and graph roots.
