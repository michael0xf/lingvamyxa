L1 copy-chain operations for Message mailboxes
=============================================

Implementation: lmx_msg_mail_chain.h.lm1 / lmx_msg_mail_chain.lm1.
This is a pure data helper, not a scheduler, router, Message registry or new
ownership model. It sees LmxMsgCopy chains only; no LmxMsg or runtime pointer.
Grok owns the native mailbox lock/unlock and Message wrappers in exec.c.
Including lmx_message.h supplies the existing record type, like slots does.
Consume this helper header after that type is available (for example from
exec.c); do not add it before LmxMsgCopy's definition in lmx_message.h.

API and caller obligations
--------------------------
  int lmx_msg_mail_chain_empty(const LmxMsgCopy *head)
      NULL ->1; any non-NULL head ->0. No traversal or writes.
  int lmx_msg_mail_chain_n(const LmxMsgCopy *head)
      NULL ->0; follows next to count the finite acyclic chain.
      Preserves the existing int count interface: count must be representable
      by int. This helper does not introduce a language queue-length cap or
      change a public count API. Cycles/invalid node pointers are not accepted
      inputs; no extra cycle-detection pass is added to this existing operation.
  void lmx_msg_mail_chain_take(LmxMsgCopy **head, LmxMsgCopy **tail,
                               LmxMsgCopy **out)
      Stores the original *head in *out, then zeros *head and *tail, in O(1).
      Does not visit, allocate, free or copy nodes/payload; next links and all
      addresses are preserved. Empty head also clears a stale tail and output.
      NULL out is a COMPLETE no-op, matching existing mail_*_take wrappers.
      NULL head/tail pointer cells are defensive no-ops; out is not overwritten.

The caller supplies live nodes and exclusive access: normally its existing
Message mailbox lock. No lock or native call is hidden inside the helper.
For take, head/tail/out must be distinct writable pointer cells and out must
not alias any node storage. Any old output reference is the caller's concern;
take overwrites the output just as the existing wrappers do, without freeing it.
The returned chain stays rooted by the caller until consumed or released.

Keep null-Message handling in native wrappers: current take(NULL Message,out)
sets *out=NULL, whereas the low-level helper's missing-cell guard is a no-op.
Do not drop that wrapper branch when integrating. Inbox and outbox use the
same chain operation but remain distinct Message-owned queues. Arena adoption,
delivery completion, running/success and lifetime policy are NOT changed here.
