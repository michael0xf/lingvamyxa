THE BOOTSTRAP QUESTION, stated once for all allocators (branch, value, chars,
array, array_ref): as library units they can never carry the ABI names,
because a unit's open path allocates through them. The redirect proves the L2
SOURCE, not the runtime's bootstrap. Model §20: "the translator builds the
initial graph of the first Message". The load-order answer that follows from
it is that the initial graph of a unit (its callable Structures, METHOD
records, the two root arrays) should be EMITTED as translation-time data,
not built at run time by the allocators it contains; then opening a unit
allocates nothing and the allocators can be real symbols. That is emitter
work on the lead's side, after Stage B; raised 2026-09-14.

Next after this module, in the lead's order: the allocators (lmx_branch_owned,
lmx_value_owned, lmx_chars_owned, lmx_array*), where the bootstrap problem is
squared -- they ARE the allocation -- then lmx_merge_owned,
lmx_message_graph_copy, the lmx_msg_* modules, lmx_message.lm1.

THE ESCAPE-POLL FINDING (the real divergence, 2026-09-14). Measured first by
bisecting the redirect set against the executor suite: all 35 other
direct-call names redirected -> exit 0; msg_complete alone -> exit 1
("complete during turn users=1 n=3 after=1"); complete's generated L1 and the
whole unit are faithful to the oracle (mechanical diff modulo the recorded
spellings: clean). Cause: every generated method polls
c.lmx_msg_poll_escape() after foreign calls and at exits (l2trans.lm1
11992-11996). The poll reads the thread-local lmx_turn_running (the current
turn Message's running flag) and, when it is 0, calls lmx_msg_poll_abort,
which longjmps to the executor's turn root (root.ready = 1 during a turn).
lmx_msg_complete is the primitive that sets success=1 then running=0 for its
OWN turn (model §31); the unit's next poll therefore unwinds the turn as a
cancellation, the executor's setjmp path runs end_turn(addr, 0) (failure) and
the callback never reaches its recording line (the stale after=1 is the
earlier nest-users scenario's value). The native L1 module is never polled.
Confirmed: the same scratch unit compiled against a shadow lmx.h whose
poll_escape returns 0 FOR THE UNIT ONLY (support objects untouched; runner's
-ExtraIncludeDirs come first on the unit's compile line for exactly this)
passes the executor suite on both runs with all 84 names redirected,
including the unit's own exec_ready: evidence
build/port_message/20260914_022358_967 (SCRATCH SOURCE shim4).
Design question put to Mikhail and the lead: the runtime core implements the
running/stop protocol and cannot be its subject; the model (§31) places the
check at entry before loading own, loop back-edges and exit, at safe points
without held internal locks, and the unit polls inside the exec lock as well.
Proposal: units of the runtime profile are emitted without escape polls (a
unit-level profile mark, like the profile-installed lm_own_*); user-profile
units keep them. Sub-question for user code: a method that calls complete
(self) and then polls at exit is unwound as a failure today.

Reading: this is the host binding, the layer the spec keeps behind `C:` as an
isolated last resort (SPEC "low-level programming is not a foreign escape
hatch"; `C:` is not the ordinary way to implement). Threads, events, locks,
TLS and the setjmp turn root have no LMX door and are the substrate the
escape poll runs on. The executor's pure scheduling logic over LmxMsgExec
(bind table, map/ui-map queues, retire list, ready scans, ctx packs) is
data-structure code and portable in the lmx_message shape, but only after
the escape-poll ruling, since that logic is exactly what the poll interrupts.
Recommendation put to Mikhail with the poll question: keep the platform layer
in C behind its existing ABI; port the scheduling logic as a runtime-profile
unit afterwards; do not port the turn root.
