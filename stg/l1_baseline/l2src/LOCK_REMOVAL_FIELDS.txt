The target (coordinator's map section 5.7, main 8c3d06bc). Mikhail, verbatim: "Почему вам не хватает typedef struct
LmxMsg { volatile ... running = 1; volatile ... success = 0; struct LmxRoot *root; } ????". Of the other five types:
"ЧТО ЭТО? Это все на L1 не является корневым Message, и при портировании все алгоритмы записываются на LMX но не
описывают Message". An L3 Thread's record "очевидно может быть сложней и содержать большее число полей так как там
планировщик и так далее".
Message = {running, success, root}. L3 Thread = a Message plus its mailbox (the one synchronized collection of
Messages, the one lock) plus its scheduler and maintenance state as Structure data in its own arena. The C keeps the
native primitives only (the thread, the mailbox's monitor).

The record, now in the documentation (spec section 2, model section 2, main c7f9d375; Mikhail asked for the handoff
flag and confirmed its meaning, "Так"):
  typedef struct LmxMsg { volatile uint_fast8_t running;       1 at launch, 0 written by the parent
                          volatile uint_fast8_t success;       0 at launch, 1 written by the Message itself
                          volatile uint_fast8_t handoff_safe;  1 written by the Message itself when it has left its
                                                               last turn and nothing native uses its arena (19.29.7,
                                                               19.29.8); today's native_users folds into when it is set
                          Lmx *root; }
His sentence beside it: everything else is not Message and ends up in LMX as the inside of a Message.
The inside (spec section 2, main c2b86f16, Mikhail verbatim): written into what root reaches; on L2 the code working
with these Messages; on L1 the code that will be generated, "В точности как имитируется L2 на Си -- функция с
аргументами ,скрытми ргументами и узлом графа." So an L3T, PAR or MBOX row below is a Structure node in the Message's
arena reached from root, not a field of a C record, and its hand-written C takes l2trans's emission form (declared
formals, hidden through-arguments in intern name order, the graph node). The whole C record is the four-field LmxMsg
plus the native primitives (thread handle, thread id, the mailbox's monitor).

Rule for every stage (coordinator, 2026-09-15): a stage's note names, for each field it touches, its owner below or
its deletion. A field with neither is a contradiction, and the stage stops.

Owner codes (the target column names one of: the four fields, the L3 Thread's mailbox, Structure data in the L3
Thread's or its parent's arena, or deletion):
  MSG    one of the four fields: running, success, handoff_safe, root; "MSG.root, inside" is data inside the Message
         reached from root (19.29.2: blocks, ranges, the graph's storage)
  L3T    Structure data in the L3 Thread's own arena (scheduler, maintenance, the capability toward its parent);
         "L3T of R0" is R0's own arena; "L3T native" is the thread's native primitive the C keeps (map 5.7)
  PAR    Structure data in the parent's arena (its child references, their paths, the settle write)
  MBOX   the L3 Thread's mailbox: the synchronized collection of Messages and its monitor
  DEL    deleted, with the ruling or stage that removes it
Basis: "ruled" names the source (map 5.7, census 2.6, a Mikhail quote in the design); "proposed" is the lead's reading
and waits for the coordinator. A proposed line is not a claim.

--- Questions (the coordinator's answers, 2026-09-15; 162f38ec accepted as the table)
Q1. RULED PAR. "Created but not committed" is the spec's reserved child (19.29.7.1: the child does not run before
    the creator's successful end-turn publication; a failed parent turn releases uncommitted children). committed is
    the parent's child entry written at its end-turn; state is derived from running and success plus that entry.
Q2. HELD with Mikhail: whether at-most-once delivery and its done history stay; DEL proposed by analogy with the
    deleted create retry. The done_* rows wait.
Q3. RULED L3T, folded into handoff_safe: the count of admitted native views is the Message's own bookkeeping on its
    own lane, consulted before it sets handoff_safe; no separate MSG field.
Q4. RULED DEL with stage M: a thread's claim on a binding has no meaning once each L3 Thread is its own OS thread.
ready. HELD with Mikhail: his 2026-09-14 sentence names readiness as the child's own flag written by the sender at
    admission, while his final loop makes the mailbox's non-emptiness the readiness; DEL proposed. The row waits.
Everything else in the table may proceed (coordinator).
