LMX_MSG_EXEC_HOST_V0 (experimental)
===================================

Not the accepted ingress pin. V0 host_post/drain remains the
bot-isolated ingress harness. This slice is overlapping execution
of DIFFERENT Messages and is experimental until the lock matrix
and tests below stay green.

Lock / ownership matrix
-----------------------
host_post          any thread     host mutex (ingress queue only)
host_drain steal   owner          host mutex then exec mutex for transport
create/grow/find   turn(parent)   exec mutex (tab/n); serial owner if nworkers=0
send               turn(from)     exec mutex (outbox)
recv               turn(who)      exec mutex (inbox pop)
end_turn           turn(who)      exec mutex (transport, children, close)
pump/admit         owner or any   exec mutex (transport + dest inbox)
                   in-turn
ready/bind         exec mutex
turn_fn            holding latch  NO exec mutex
state/inbox_n      owner or latch exec mutex
set_now/poll/drive owner          exec mutex; drive readies bound
                                  closing msgs instead of out-of-turn
                                  end_turn when workers>0
UI must not touch a worker Message without that Message's latch.

end_turn from a turn also pumps (admits published outbox in the
same scheduling phase). Serial tests still pump explicitly; a
second empty pump is a no-op. Ingress host_drain still pumps.

Owner-serial vs concurrent
--------------------------
nworkers==0: owner is the single lane (recv/fail/drive). UI closer
and post-stop parent-fail tests are owner-serial.
Concurrent: owner fail of a bound live Message is INVALID. Timer
parent-loss is poll+threshold while parent exec_live and the child
turn is held. path/init_copy from that held child is measured
while factory is inside its create phase (synchronized handshake:
first extra created, extra_n=1, factory waits; metadata; then
release to finish extras 2..8). That is held-child metadata during
factory create phase, not extra_n>=1 or factory_n=8 as overlap,
and not simultaneous work inside one mutex. Runnable policy: L1
lmx_msg_exec_is_runnable. Ready take is L1 lmx_msg_exec_take_addr.

Choice
------
Each Message has one arena and one serial turn lane. Different
Messages may run turns at the same time on different OS threads.
There is no source-language worker-count or depth cap; the host
starts a small worker pool (test uses 2).

UI/OS-affine Messages run only on the UI/owner thread (the thread
that called runtime_new). ANY-affinity Messages run on workers.
host_post remains callable from foreign callbacks.

What a turn may call
--------------------
recv/send/end_turn for Message M require M's turn latch, including
the UI/creator thread. The creator must not touch a worker Message's
inbox/outbox/arena without that latch. UI runs its own affinity lane
concurrently; it does not bypass another Message's latch.

create/stop/admit/ready-queue use a narrow runtime mutex, never
held across user work. That mutex is not a global handler lock.

Not this
--------
A global mutex around whole handlers (that serializes all Messages).
Removing owner checks. App C locks. One dispatcher thread for all
handlers. Concurrent turns of the SAME Message. Graph-copy 19.29.7.2.

Scheduling / transport
----------------------
Runtime mutex: ready queue, admit, create, state, stop flags.
Per-Message turn latch: at most one turn.
Workers wait on the ready queue, take one Message, run one bound
turn function, publish outbox via end_turn, enqueue destinations.
Selection/bind/held is L1 lmx_msg_exec_take_addr (C take_ready
calls it under the exec mutex). Function-pointer/TLS invoke stays
a thin native primitive. UI thread: host_drain + UI-affine turns.
A busy ANY worker must not block UI_step or another Message's
worker. Owner send/end_turn while nworkers>0 still requires that
sender's turn latch; host_post+host_drain is the owner inject
path (host_post remains any-thread).

Stable storage
--------------
Message objects are individually allocated. Growing the runtime
table reallocates a pointer array only; live LmxMsg addresses stay
valid. Handlers must not cache table slots across create/growth.
Lookup is by LmxMsgAddr under the runtime mutex.

Lifetime
--------
Do not free a Message arena while its turn latch is held.
Phase order (no deadlock with posters that wait on shutdown):
  1. stop admitting new callbacks
  2. runtime_shutdown (host_post -> STOPPED)
  3. join/quiesce posters (they observe STOPPED; they must not
     wait for a later exec_stop)
  4. exec_stop: stop workers, wait latches clear, join workers
  5. runtime_delete
exec_stop is before delete and after poster quiescence.

Bind
----
lmx_msg_exec_bind(rt, addr, turn, ctx, affinity)
  affinity 0 = ANY (worker), 1 = UI (owner thread)
lmx_msg_exec_start(rt, nworkers)
lmx_msg_exec_ui_step(rt)
lmx_msg_exec_stop(rt)

App fragments stay isolated: they implement turn() and host_post
adapters only. This slice is experimental; it is not an app pin.
Do not copy these sources over mixa_manager/vendor while app
agents are compiling. Promotion is a coordinated copy of the
accepted experimental files after review, not a live overwrite.

last_status
-----------
lmx_msg_exec_last_status is the last run_one return stored on the
binding. A later success overwrites a prior failure. It is not
per-request supervisor delivery and is not the Message
result/error contract (send/recv/end_turn returns, KIND_CANCELLED
as ordinary result data).
