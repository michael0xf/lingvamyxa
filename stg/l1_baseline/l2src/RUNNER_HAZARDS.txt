RUNNER HAZARDS: build reuse keyed on presence or time, and Start-Process -Wait launches, in every l2src runner (0c, 2026-09-14)
SURVEY COMPLETE on d925e600 (run_port_parser re-timed on ee35e67a (d7835dc7 + runner-only fixes; run_port_parser.ps1 identical to d7835dc7: True)); fixes land per runner through the lead.

Why
  run_port_parser taught two hazards (l2src/PORT_PARSER_TIMING.txt; 4b3f8d9c, 49e5db6d):
  - a runner that skips a build step because its output already exists links whatever tree first built
    that output: a warm build\port_parser linked a pre-e64c8083 lmx_message_exec.o ("undefined
    reference to `lmx_msg_run_entry_turn'"), and after a core change it would report the old core's
    result as the new one's;
  - PS 5.1 Start-Process -Wait costs about 1 s per launch however fast the child is (1758 of 1845 s were
    launches); Start-Process -PassThru without reading $p.Handle first returns an empty ExitCode, so an
    exit compare can pass silently.
  e2's ticket: survey every other runner under l2src first (this table), then fix per runner in gate
  weight order, each fix a runner-only commit with its falsifier.

Survey method (on d925e600)
  Static: every .ps1 under stg/l1_baseline/l2src (48 files: 47 run_*.ps1 and l2units_build.ps1), every
  Test-Path, LastWriteTime/CreationTime, Get-FileHash/SHA256 and Start-Process line with two lines of
  context, and every dot-sourced builder (a runner inherits its builder's hazards). Each Test-Path site
  classified as reuse (skips a build step when an output exists), input check (throws on a missing
  source or tool), cleanup/evidence, or optional input.
  Output directory per runner: fixed (the same path every run, so reuse can cross runs and branches in
  one worktree) or stamped (a new directory per run, so nothing on disk is reused).
  Cold runs: every runner once, sequentially, in a fresh private worktree on d925e600 (claude-0c/
  runner-hazards) whose fixed output dirs did not exist; wall time, exit, last line, and the number of
  stdout files written during the run (a launch proxy).

(a) Reuse keyed on presence or time
  Only three runners write to a fixed output directory; every other runner writes to
  build/<name>/<stamp> or build/codex/<name>/<runId> and reuses nothing across runs.
  run_lmx.ps1 (fixed build\l2\targeted\<gen>\<Suite>, or build\l2 for Full)
    L431-433: l2trans.exe is rebuilt only when absent or when l2src\l2trans.lm1 is newer than it
      (LastWriteTime). The exe can come from any earlier run in that worktree, of any branch; a change
      to an input l2trans.lm1 predefs or includes (l1src/parser.lm1, lm1/build headers) without touching
      l2trans.lm1 itself is not seen, and a checkout that gives l2trans.lm1 an older mtime than the exe
      reuses the exe. HAZARD.
    L190-227 Get-LmxObject: objects keyed on a content hash (source SHA256, gcc path and SHA256, options,
      SHA256 of every header under l2src, lm1/build and the generated include dir), in an in-run
      hashtable (L186 $objectCache = @{}) with the key in the object's file name. Not a hazard.
  run_port_parser.ps1 (fixed build\port_parser)

      runtime-trio checks and missed this one. Its source l2src/p0_dump_alloc_counter.c changes rarely,

  Tripwires, pinning the runtime's own bookkeeping as an absolute number on purpose, each cause named:
    run_port_msg_path_storage [14s red] pre-test wrapped allocations = 3 (the process Message, R0 at d1, the UI lane
      at d2; 2c43c21f) and run_port_msg_blocks [15s red] pre-test frees = 1 (the entry turn's bind-wait record since
      e64c8083; c373fd04). A pre-test count with its cause named measures what the runtime creates and frees
      at open; a warm-up that clears without pinning would stop noticing (6f's ruling).

  step that changes a pinned count updates the pin in the same commit and names the new cause, as the slot
