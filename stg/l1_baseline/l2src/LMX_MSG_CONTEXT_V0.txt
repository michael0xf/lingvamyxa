LMX_MSG_CONTEXT_V0
==================

Accepted per-context Message ownership. Not an app pin.
LMX_MSG_EXEC_HOST_V0 remains prototype evidence of overlapping
turns; it is not the language-level architecture and must not be
copied over mixa_manager/vendor as the design.

User constraint (032700 / 033000)
---------------------------------
Each L3 Thread / live Message context owns:

  - its mailbox (FIFO inbox; staging outbox)
  - its parent capability (or none, if a root)
  - its direct-child list

Supervision is local: a parent knows only its direct children.
Grandchildren are the child's problem. Incoming payload is not a
new execution thread. Explicit launch creates a child with its own
arena. Arbitrary explicit send is allowed: parent/child are
supervision relations, not the only recipients.

What is forbidden
-----------------
- Process-wide shared mutable Message registry used as the
  ownership/supervision/lookup model (rt->tab scans for children,
  global find-by-integer, workers mutating a shared table as the
  family tree).
- A non-Message C scheduler/router/worker-pool policy as a
  language-level coordinator (including hiding the same table
  behind a Message facade while workers keep direct shared access).
- One global lock around handler execution.
- Private application C concurrency frameworks.
- Promoting EXEC_HOST_V0 to the app.

What remains native (not a language scheduler)
----------------------------------------------
OS thread start/join, and narrow wait/wake/mutex around mailbox
admission and a per-Message turn latch. Those are substrate, like
malloc. They are not "an actor in a worker pool" and not a
process-wide registry.

Erlang/OTP, Akka, Pony (orientation only)
-----------------------------------------
Borrow: isolated process/actor state; mailbox; parent manages a
local child list; supervision is itself a process; one-at-a-time
behavior per actor; concurrent independent actors.
Do not import: BEAM global process lookup, selective receive,
link/exit, automatic restart, Akka dispatchers/executors, Pony
scheduler threads as LMX rules.
Child->parent timer polling and cooperative end-turn close stay
as previously agreed. "A scheduler must itself be a Message" is
an LMX user constraint, not something those languages prove.

Ownership / protocol
--------------------
Identity
  A live Message is a capability: the object itself (stable heap
  address for this prototype). Mix placement path remains
  parent-counter+append (19.29.7.1) and is not the mailbox slot
  and not a global lookup key. Guessing an integer must not grant
  access. Send uses a capability the sender already holds
  (argument, reply_to, stored handle). No table scan to resolve
  dest.

Mailbox
  Per-context FIFO. Concurrent posters linearized at that
  mailbox's admission lock (native mutex+wake). host_post of a
  number/bytes envelope copies under the destination mailbox lock
  (or a UI host-queue that then admits into the UI Message's
  mailbox). It does not look up dest in a process table.

Parent / children
  parent_msg points to the parent object (0 for a root).
  first_child / next_sibling are the direct-child list, mutated
  only in the parent's turn or at create/rollback under the
  parent's latch. request_children_close walks that list only.
  Failed-create / failed-turn rollback unlinks uncommitted
  direct children from that list; no process scan.

Turns
  At most one turn per context. Different contexts may run at
  the same time. UI-affine context: owner thread. Other
  contexts: OS wait on that mailbox, or a Scheduler Message
  (ordinary Message, private state, message protocol) if a
  language-level coordinator is actually needed. No C worker
  pool picking from a global ready array of all Messages.

Lifetime
  One arena per live context. Do not release the arena while the
  turn latch is held or while the mailbox may still accept a
  copy from an in-flight host_post. Close is cooperative:
  parent end_turn sets closing on direct children; they close
  at their end-turn; cascade is child-local. Child polls
  parent_msg for liveness (timer); it does not scan a table.
  Dead capability: the endpoint object remains as closed-handle
  control state (DEAD/STOPPED/RELEASED) until runtime_delete.
  Addr is monotonic; it is not recycled. Send/admit that find
  DEAD/STOPPED/RELEASED drop the copy (GONE). No bounce to
  reply_to. host_post still STAGED (no dest lookup); drain/admit
  is the linearization that drops. Do not free-then-deref, do
  not use a generation field as the only UAF guard, and do not
  treat "join known posters" as proof every held capability is
  gone — the closed object is the control state.

Send to non-child
  Legal. The sender must hold the dest capability. There is no
  directory. If dest is dead, send fails. Routing, if any, is
  another Message you send to; it does not inspect others'
  private data.

Current deviations (EXEC / mailbox prototype)
---------------------------------------------
Do not claim the previous global-table runtime complied.

  D1. Allocation is LmxMsgRuntime.slots (linked list), not a
      growable pointer table. slots is storage, not the scheduler.
      tab_n_locked / tab_addr_locked still enumerate that list by
      index (transitional D1 helper). Integer find remains for send
      into another family. send dest prefers the sender subtree
      and parent_msg before forest find. Integer lookup uses
      turn_self when it already is that Message
      (lmx_msg_self_or_find), else forest find.
      recv still pops mail via turn_self without exec first.
      See LMX_MSG_ARENA_SPLIT.txt for Codex block-list module
      and LMX_OWNED_RANGES.txt for the owner-local classifier.
      Mailbox/init bytes are not auto-registered as graph domains.
  D2. request_children_close walks the direct-child list.
      poll(0) and drive walk the forest, not slots.
  D3. Per-context ANY wait-threads (`lmx_msg_exec_start_contexts`)
      are the active concurrent path. The shared nworkers pool
      (`lmx_msg_exec_start`) is retired; measurements remain in
      LMX_MSG_EXEC_HOST_V0.txt only. UI stays on the owner thread
      via exec_ui_step. scan_ready walks bind[] (held skipped),
      not rt->slots. take_addr(want_ui) consumes ui_map_ready.
      ANY context threads take_this(addr). bind kicks exec_ready
      if already runnable. Unbound direct children enqueue on the
      PARENT sched_ready list. live_check parent-turn does not
      write mapped child control fields. bind[] remains the
      temporary mapped-set / OS-handle table.
  D4. LmxMsgAddr is a process-wide unsigned, not a capability.
      Visibility is not arena ownership (174300 / 182300):
      independent is lexical isolation (node=0 root), not a ban
      on dynamic/through caller inputs. node is lexical ancestry
      and is not rewritten by adopt/merge. Dynamic values come
      from the caller. No owner-link / fourth Lmx word.
  D5. host_drain dest lookup on owner (ingress V0 still copies
      under host mutex; dest table walk is later).
  D6. 19.29.6 / 19.28.R2.2 text that permitted worker-pool
      actors and migration between host workers.
  D7. Shared exec mutex still around find/bind/ready. Inbox and
      outbox q_push/take take dest mail_lock nested under exec
      (exec then mail; never the reverse). state/inbox_n/path_n/
      path_seg/child_n/child_at skip exec when turn_self already
      is that Message. take_addr holds exec across scan/consume;
      is_runnable_locked is used when the lock is already held.
      Not yet a replacement of exec lock.
  D8. Independent child-arena reclaim inside one family is
      prototype-only: RELEASED frees copy slices; the LmxMsg
      object stays until runtime_delete. Not proven across
      family lifetimes.

This slice (preparation, not a facade)
--------------------------------------
Direct-child list on LmxMsg; create links; close/rollback walk
the list. Parent-owned sequential step (`lmx_msg_sched_step`)
walks that parent's first_child only (never grandchildren) and
runs one ready unmapped child's whole turn on the caller's
thread. Initial selection policy: first ready direct child in
list order, one turn, not drain-to-empty and not language-wide
fairness. `lmx_msg_map_child` is a parent-owned mapping of one
direct child onto a native wait-thread. Mix placement path is
growable (PATH_CHUNK), not depth 16. Send stores dest_msg on the
staged copy; admit prefers that capability. Integer find remains
D1 for other-family send. EXEC pool / start_contexts remain
prototype.
Child query/parent-reply is experimental, not a language KIND.
KIND_PROGRESS numbers 0x4C560001/0x4C560002 plus correlation
(implementation profile). Ordinary PROGRESS 1/2 does not ack.
live_query_id/at is the child's own published wait (clock taken
at successful end_turn, not STAGED). child_heard_at is the
parent's own record of that child, set on first commit and on
authenticated child query only. Parent live_check does not
inspect the child's live_query_id. A mapped child applies its
own wait on its wait-thread timeout. exec_bind retains the endpoint.
exec_stop does not drop that retain (restart/last_status).
runtime_delete: stop, drop_binds, drain with no_retire, free slots;
detach does not stop again. Nested unbind of a live worker sets gone
and wakes; it does not join while the exec lock is nested.
mail_lock helpers cover inbox and outbox; find/bind/ready still use
the shared exec lock (D7). send_cap same-runtime check is a prototype
boundary, not a language ban. Integer find still uses the runtime list
(D1). scan_ready does not treat slots as a process-wide ready set.

Not yet
-------
Capability LmxMsgAddr; slots remaining as an allocation list (not a
Scheduler Message); per-Message child scheduling replacing bind[] scan;
per-mailbox native lock replacing exec mutex for send/recv;
independent child arena reclaim (D8); mixa_manager pin.
Shared pool `lmx_msg_exec_start` is removed from the runtime;
`lmx_msg_exec_start_contexts` is the concurrent entry.
History-only measurements stay in LMX_MSG_EXEC_HOST_V0.txt.
Old ingress pin LMX_MSG_HOST_INGRESS_V0 stays until consumers
switch. Do not overwrite a pin under a build.

Linearization (19.29.7.1)
-------------------------
create: parent turn; returns child handle + path (counter append).
  No directory. Never-introduced dests are not looked up.
send: copies into the sender outbox (STAGED). Not admission.
end_turn success: publishes outbox onto transport.
pump/admit: if dest is missing, DEAD, STOPPED, RELEASED, or
  uncommitted INACTIVE, drop the transport copy (GONE). No
  automatic bounce to reply_to. host_post STAGED is not admit;
  host_drain then pump is admit. host_post to a live dest that
  dies before drain is the same drop at admit.
fail of dest: DEAD notice to parent is a separate message, not
  a bounce of dropped payload.

Unresolved (ASK, not guessed)
-----------------------------
A1. DECIDED 034300 / 19.29.7.1: drop staged copies if dest
    disappears before admission; no reply_to bounce. Closed
    handle = live object in DEAD/STOPPED/RELEASED until
    runtime_delete; addr not reused.
A2. DECIDED 035400 / 040530: ANY-affinity uses one OS wait-thread
    per bound context (`lmx_msg_exec_start_contexts`). UI-affine
    stays on the owner thread (`exec_ui_step`). Not a worker pool.
    A Scheduler Message is not added for this prototype.
    Restart after stop is valid. Child ANY bind after start
    launches that context's thread. Rebind ANY->UI (owner, not
    held) retires the wait-thread; UI work then runs on ui_step.
    Topology is not frozen at start_contexts. Failed bind does
    not publish: non-owner ANY->UI is rejected with the binding
    unchanged; UI->ANY launch failure restores the previous
    affinity; a failed new bind unbinds that slot even if it is
    no longer last. POSIX compilation of bind does not mention
    Win32 worker handles. Slang/green-thread notes are not an
    architecture change.
    Launch owns a reference on the captured wait generation.
    Unbind/reap must not destroy that wait while launch_n>0 or a
    native worker still exists. Wait serial is per LmxMsgExec,
    assigned under that runtime's exec lock. Outer launch
    rollback (UI->ANY affinity restore, new-bind unbind, map_child
    mapped-clear) is conditioned on the same wait pointer+gen, so
    a stale launcher cannot mutate a same-addr replacement.
Arena vs control block: RELEASED frees init/inbox/outbox (the
copy-slice arena). STOPPED/DEAD stay closed-handle control state
until runtime_delete (not auto-RELEASED). D8 prototype: a
RELEASED endpoint with refs==0, empty queues and no parent link
may unlink via try_retire (called from final endp_release, not
only recv/release_slot). That C predicate/list scan is not the
permanent retirement policy; lifecycle stays in LMX (L1).
Independent families still reclaim at runtime_delete.

Windows measured first. POSIX primitives in EXEC/ingress were
written earlier and are not claimed run here.

100200 local lifecycle (invariants, not accepted yet)
-----------------------------------------------------
Supervision vs delivery (133800 / 67f1ec2 / 175700)
  parent_msg is the supervisor. Adopt/transfer move handoff-safe
  non-executing storage (blocks/ranges) into the receiver arena.
  They do not reparent a running Message, rewrite Lmx.node, merge
  lexical trees, or create an implicit link from B's root.
  After adopt A->B both trees can live in B's one arena; arena
  membership is not a GC root. Application retains graph refs.
  Delivery-only assignment ends active parent tracking;
  historical identity and control LmxMsg remain until
  runtime_delete. Byte-envelope send is not arena delivery.

Template / immutable (135500 / fd8683d)
  No separate immutable Message as a core prerequisite. No
  cross-Message immutable sharing. Create merges the chosen
  template settings plus explicit additions; it does not copy
  the parent's live program/context or look up parent settings.

Who may move payload
  Only the parent of a handoff-ready child, via adopt_failed
  (child success==0) or transfer_adopted (explicit result to
  that parent), and only while that parent is not disposed.
  Caller must hold the parent's turn, or be the host owner
  with no turn held. Source must have native_users==0,
  running==0, handoff_ready. Every direct child of the source
  must already be disposed. Destination is the parent
  endpoint (not DEAD/RELEASED, not disposed). No remaining
  source aliases into moved blocks. exec lock here is
  transitional D7, not the mailbox.

End-turn collection (19.29.4 / 180000 / 181500)
  lmx_msg_end_turn calls lmx_msg_arena_collect after outbox
  publish/discard. LmxMsg.graph is the Message graph unit
  (l2trans synthetic entry set_graph). Collect traces from graph
  through Lmx, CHILDREN, ARRAY descriptor/backing and METHOD
  records, plus owner-local explicit roots (LmxMsg.roots).
  Root attach admits a pointer already in this Message's ARRAY
  or CHILDREN range; release drops retention only. Duplicate
  attach is set membership (LMX_MSG_DUPLICATE), not a second
  lease. graph==0 with no explicit roots: ranged storage is
  unrooted. Opaque blocks with no range stay live. Visit OOM
  still skips sweep. Own-field C frames are gone at this boundary.
  Storage handoff moves blocks/ranges only; source roots whose
  addresses no longer classify are dropped (not transferred).
  Dest does not inherit them. adopt_failed is the one wired history
  site (19.29.8): required HISTORY roots (child graph plus src roots
  that already carry LMX_MSG_ROOT_HISTORY) are allocated before any
  storage move, then committed with the move. Ordinary RETAIN roots
  are not copied. One address may hold both roles; release drops only
  RETAIN. OOM returns NOMEM with both owners unchanged. Nested
  P<-C<-G keeps both graphs when they are not one lexical tree.
  transfer_adopted still does not attach. complete() never frees and
  does not attach. Ordinary graph-owned fields and the adopted arena
  as a whole are not blanket-rooted.

  adopt_failed init-block push after a successful move_all is not a
  live recoverable partial-failure: can_move already proved distinct
  live acyclic lists; prepared is a fresh detached calloc node with
  non-null init base; exclusive ownership is held; blocks_push does
  not allocate. Failure there is not constructed from admitted state.

Who may free
  Parent dispose_child of a SUCCESSFUL handoff-ready child
  after every direct child's arena is already adopted or
  disposed (child.disposed). Failed payload must not be
  freed here: adopt_failed first, or dispose_child INVALID.
  complete() never frees. slot_free frees only what that
  slot still owns.

What stays rooted
  Control LmxMsg until runtime_delete. Transferred adopted
  blocks are rooted on the destination Message. Failure
  history lives on the adopting parent until that parent is
  itself adopted or successfully disposed.

When children are disposed
  Direct children only. A child is settled iff disposed==1
  (successful dispose_child) or its failed payload was
  adopt_failed (also sets disposed). Stopped/exited is not
  settled.

When native resources are settled
  native_users==0 and running==0 and handoff_ready after the
  last run_one leave. External OS resources are not yet
  tracked; do not claim full handoff-safe.

Exactly-once
  adopt_failed / dispose_child no-op INVALID if already
  disposed or empty failed payload already moved.

Open (not this slice)
  Per-mailbox lock; no tab/find; no global exec lock;
  registered range blocks; mixa pin. send_owned transfers a
  free()-compatible independent allocation (not an interior
  arena pointer). Invalid kind / n>0 with NULL bytes reject
  before steal. Staging failure restores caller ownership.
  Recv hands the same pointer to env; env_release frees once.
  parent_settle walks the full direct-child list (growable,
  no 32 cap). Final graph delivery still needs block
  metadata/deleters, not raw free.
