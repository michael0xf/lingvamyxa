L2 foreign allocation adapter
=============================

Grok confirmed the exact helper/compiler/test paths in inbox/outbox213700.
Graph-unit l2_need_own now imports l2_foreign_alloc.lm1 instead of all of
l1src/own.lm1. It exports only the four already-admitted signatures:
lm_own_new_zero, lm_own_resize, lm_own_copy_bytes, lm_own_delete.

Default behavior is preserved: calloc(1,size), realloc for nonzero resize,
free-and-null for resize-zero, overflow rejection before length+1, independent
zero-filled copy with terminating NUL, null delete skipping the destructor,
and destructor-before-free for a nonnull object. Zero-size new retains the
underlying C allocator's behavior. Realloc failure leaves the old allocation
owned by its caller. Callback and pointer lifetimes are unchanged.

These are explicitly managed FOREIGN allocations. They are not admitted to
Message blocks/ranges and cannot be treated as LMX-owned graph storage. This
adapter introduces no owner ABI, registry or implicit garbage collection.
L1 own/parser source and its three fault-injection globals remain untouched
for the original L1 test path. Generated graph units no longer import those
counters or the unused pointer-stack/absorb machinery.
