Representation and API
----------------------
Lmx is Structure-only: Lmx *node; int len; void *data. len is child count,
data addresses void * slots. A stored child value points directly to the
appropriate typed target; the address of its slot does not give child type.

lmx_branch_slot_known(parent, i)  -> void **, address of the slot
lmx_branch_child_known(parent, i) -> void *, current target (ABI changed)
lmx_branch_store_known(parent, i, value) -> stores the new target
lmx_branch_struct_known(parent, i) -> Lmx *, compiler-proven Structure only
lmx_node_new_owned(...) -> root Structure, STRUCT kind/type
lmx_struct_new_owned(parent, ...) -> nested Structure initialized with parent
lmx_charptr_* -> typed char * cell, directly pointing to a C string

Slot storage is CHILDREN/BRANCH, stride sizeof(void *). Structure headers
are STRUCT/STRUCT. Primitives, Array records and method records have no Lmx
wrapper. The emitter constructs nested headers separately and uses slots
for field access, caches and checkpoint publication.

Codex corrected stale COMMENTS in lmx.h and the two API headers only:
there is no node-freeze rule. Used-graph copying rewrites destination node
and ordinary references; shared method-descriptor pointers stay unchanged.
No implementation or test expectation was changed by that correction.

API (SPEC 2.3, ABI 8.2, user decisions 2026-09-12):
  fn: lmx_graph_copy_owned (@: Lmx source; @: LmxOwnedRange src_ranges;
      @: char dst_chars; @@: LmxMsgBlock dst_blocks;
      @@: LmxOwnedRange dst_ranges; @@: Lmx out) int
  0 OK, 1 INVALID, 2 NOMEM, 3 UNSUPPORTED.

Traversal. Seed the source and its lexical chain to node = 0; each queued
Structure gets a destination header registered in the operation-local map
BEFORE its edges are followed; processing copies every slot and queues the
lexical parent, so the whole reachable lexical tree is copied (this is the
conservative whole-tree reading of "used"; independent bounds it with its
zero root). Per child value, classified by src_ranges: STRUCT -> copied
Structure (and its own lexical chain); INT/SIZE_T/CHAR_PTR cells -> new cells
with equal values, once per source address (aliases preserved); interned
CHAR -> the same byte in dst_chars, or the source cell when dst_chars is 0
(same-Message copy); METHOD -> the same descriptor pointer (methods are
shared); Array record -> new record plus new backing (memcpy for CHAR/INT
backing; element-wise copy for LMX/DESC/METHOD reference arrays, registered
before following elements so cycles terminate); a value not classified by
src_ranges is kept as is (not language-owned storage of the source). After
processing, every copied Structure's node is rewritten to the copy of its
lexical parent or zero. All destination storage is prepared under private
heads and admitted with one storage_move_all; on any failure the prepared
storage is disposed, the destination heads and the source are untouched,
and out stays null.

Selftest (44 checks): source graph r0 -> s1 -> s2 plus an independent root

slot, a node link and a reference array, a back-reference cycle s2 -> s1,

owner with its own char table: r0/s1/s2/i0 copied, node links point at the
copies, the root's node is zero, i0's copy keeps node zero, cells and Array
backing are new with equal contents, the interned char maps into the
destination table, the METHOD pointer is identical, the shared int cell has

Settled merge and eternal-sharing model - 2026-09-12, consolidated 12:10
------------------------------------------------------------------------
Replaces two duplicated and partly overbroad blocks that stood here, at the
request of Codex 114154. The superseded wording said the result of merge shares
NOTHING except methods; that omitted the admitted eternal branches, which is an
exception I had myself preserved elsewhere. Nothing below is appended as a
correction under an older rule: this is the current rule.

WHAT MERGE DOES

1. merge copies the COMPLETE USED graph down to node = 0, exactly as creating a
   Message does. The only optimisation is pruning branches that are not used.
2. The result is a THIRD INDEPENDENT structure. It overlaps the operands and
   their ancestors in exactly two things and nothing else:
     - METHOD descriptor addresses, and
     - admitted eternal branch references, that is branches qualified
       independent: const: immutable and retained by the first Message.
   Both are copy TERMINALS: the copy substitutes the existing admitted address
   and stops there. Merge and Message creation never append to either root
   array, and holding one entry gives no access to the array itself
   (SPEC 7196, 7198).
3. The operands are NOT destroyed or altered. Two structures existed, now there
   are three. Each operand keeps its own layout and its own calls keep working.
   What does not exist is a sub-container inside the result that is a copy of an
   operand root retaining that operand layout.
4. Ordinary mutable state is fully copied and independent: a cell in the result
   is a distinct cell, and a write to it does not reach the source.
5. Reachability decides, not the word independent. If the used graph genuinely
   refers to an operand root, whether by self-reference or lexical dependency,
   the map still gives that root a destination and every reference resolves to
   it. Independence is from SOURCE STORAGE, not a prohibition on copying a
   reachable node. Pinned by selftest block 2b, where one root is reached both
   as another root lexical parent and as a child slot, and gets one destination.
6. Copied internal child order is preserved. merge reorders the top level of
   the result; it never renumbers the inside of a node it copies.

WHAT FOLLOWS FOR THIS LANE

- The copier is correct as it stands: METHOD shared by pointer, eternal ranges
  as terminals, everything else copied, unclassified raw targets refused.
- Eternal metadata stays the explicit eternal_ranges argument for this stage,
  per Codex 115917, derived from the translator-built qualified first-Message
  graph and passed as trusted internal copy metadata. It must match the actual
  fixed qualified storage. A pointer does not become eternal because a caller
  guessed it. Not to be replaced by a recognisable array node so a generic
  copier can rediscover global state.
- Descriptor placement in the emitter is CORRECT: process_message is the first
  Message. See FABLE_CALLABLE_NODE_AND_MERGE.txt part 5 for the withdrawal of
  the gap I wrongly reported here.
- Open frontend work, in Codex order: per-callable Structure first (115036),
  then the two dedicated const: immutable arrays with qualifier emission.

Named Structures: char, nested and reference fields (2026-09-13, 73576eb1)
--------------------------------------------------------------------------
Option (a) declarations carry four field kinds, all in the existing graph
representation, no new language surface:

  0 size_t literal    a size_t cell
  1 char literal      a POINTER CELL into the Message char table. Not a
                      string descriptor, not inline storage in the parent.
  2 inline nested     (): name ... end: name, built in place as a child of
                      its parent with node = the parent
  3 reference         Name: field, sharing the pointer of an earlier
                      COMPLETED unit-level declaration, WITHOUT reparenting

Only unit-level declarations are children of the unit. A nested entry is a
child of its parent and nothing else. Source field order and the fixed child
count are preserved. Emission builds every entry through a generated
l2_nsp[] array, parents before children, then wires reference fields in a
second pass.

The field table is FLAT and interleaved: a nested body pushes its fields in
between its parent's, so a per-entry range is NOT contiguous. Every walk
selects by the l2_nsf_owner column. l2_ns_first/l2_ns_count are still the
declaration order, not a slice.

A reference may only name a COMPLETED earlier unit-level declaration.
l2_ns_push registers an entry BEFORE reading its fields, so without the
l2_ns_done flag an entry could name itself or an enclosing one and close a
cycle through the unit graph.

Three defects this shape exposed, all invisible to the previous fixtures:

1. A MISSING PROTOTYPE SILENTLY TRUNCATES A POINTER. The char table was
   created but predef "l2src/lmx_chars_owned.h.lm1" was gated only on
   l2_has_own_ty(1), so a named Structure's char field reached
   lmx_chars_new_owned with no declaration in scope. C took the return as
   int and cut the upper 32 bits. The symptom appeared three layers away,
   as LMX_MERGE_UNSUPPORTED, because lmx_owned_ranges_find could not
   classify the cell. Diagnosis: print the pointer next to the registered
   range; table=0x000000001afd6748 against lo=0x000002891afd6748 is the
   whole answer. Any time a generated program emits a call, the predef that
   declares it must be emitted under the SAME condition.

2. READ BEFORE WRITE IN THE MERGE WIDTH LOOP. The operand lookup
   ni: l2_ns_find(...) sat at the BOTTOM of the loop, so every named
   operand contributed the PREVIOUS operand's width and literals. Two
   operands of 2 and 4 predicted 4 instead of 6. Also "bfirst = 0U" was
   used as a not-set-yet marker, which is wrong for a literal zero; the
   first end is now taken at k = 0.

3. AN END HAS A KIND. The result-content checks compared every end through
   lmx_size_value_known. A char end is now checked through
   lmx_char_value_known instead, and an end that is a nested Structure or a
   reference is left UNPINNED rather than compared against a value it does

CORRECTION (2026-09-13, ceb911bc): references admit aliases and cycles
----------------------------------------------------------------------
The completed-only/source-order restriction described above was MY
implementation gap, not an L2 rule. Codex corrected it the same night. The
graph model permits aliases and cycles and the copier preserves them through
one operation-local map, so a reference field may name:

  - a declaration that appears LATER in the source (forward)
  - its own declaration (self)
  - a declaration that names it back (mutual cycle)
  - a NESTED declaration

Construction is two-phase. The collector records only the NAME; the whole unit
is read first and l2_ns_resolve_refs then resolves every reference field.
Unknown and ambiguous names stay errors, with distinct causes. l2_ns_done is
gone.

The node check had to be generalised with this: a nested target hangs under
its own parent, not the unit, so the generated program checks the target
against the lexical parent it was built with. A reference never reparents its
target in either case.

Merge proves the aliases survive. Where field j of an operand names an entry
which in turn names an entry the operand ALSO names at slot j2, one map means
both paths must arrive at the SAME copy, and the generated program checks
exactly that. unit_named_alias.lm2 emits three such checks.

Lesson worth keeping: when a shape is awkward to build, the refusal I reach
for is an implementation convenience, and I should say so out loud rather than
ship it as if it were a rule. The two-phase construction that lifts the
restriction was no harder than the restriction was.

Source field paths (2026-09-13, 60ed1f16)
------------------------------------------
Two spellings, both already produced by the parser, checked with printTree:

  R\x: 5U          UPDATE: the whole path is ONE frame head text
  v: R\x           VALUE:  atoms around separator atoms in the body

They are joined into one byte span and resolved identically, which is why the
path helpers take (data, length) rather than an LmP0Text: a value-position
path has no single text to point at, and an LmP0Text cannot be declared as a
local in L1 (unknown type name).

Resolution is entirely at translation:
  - a declaration's field is matched by the name it was DECLARED with
    (l2_nsf_fname), and the slot index is its position among that owner's
    fields in the flat table;
  - a merged result has NO names of its own. Its slots are resolved through
    the field that CONTRIBUTED each slot: l2_mrs_* is a per-result slot map
    built while the merge is lowered, from each operand in order and then the
    body fields. A qualified-branch operand contributes one anonymous row.
Nothing is looked up by name at run time and no runtime name table exists.

Primitive semantics, as the ticket pinned them:
  size_t   lmx_size_store_known on the addressed cell, IN PLACE
  char     lmx_char_rebind_known on the field's POINTER CELL. The table bytes
           are never written and no new cell is allocated. Emitting
           lmx_char_cell_known here would also be observably correct but is
           the wrong operation: rebinding is what a char assignment is.

SCOPE, stated rather than hidden: a path is lowered where the unit is
addressable. Inside a method the unit is not reachable -- the executing
Message arrives as a dynamic input that is not lowered in this emitter yet --
so a path inside a method is refused with its own cause, the same boundary
the merge site already carries. Lifting it is the same work as lifting the
merge-in-method refusal.

Two mistakes worth remembering:

1. The dispatcher first took ANY head with two or more segments. That
   swallowed out_payload\data in parser_text_views.lm2, an ordinary out
   parameter field, and only the HISTORICAL gate caught it -- the graph ABI
   gate was green. A new statement form must be recognized by what its root
   RESOLVES to, never by its shape alone.

2. l2_join_path validated the alternation with the flag inverted, so every
   well-formed path was rejected and the error surfaced as "unresolved name"
   on the first atom, far from the cause.

Merge result names are now reserved in l2_parse_unit, before any statement is
checked: a path rooted at a bound result is otherwise an unknown head when the
unsupported-body guard runs. The scan is idempotent.

Field paths inside methods (2026-09-13, b6165de8)
--------------------------------------------------
The refusal recorded above is withdrawn. Inside a method the root of a unit
declaration or a bound merge result is the callable's LEXICAL PARENT, spelled
through l2_unit_ref, which is already "unit" at the entry and node\node in a
method body. Own and callable fields keep using node. One walk serves both
places; there is no second category and the Message is never derived from
node. None of these paths allocate, so none of them needs the Message.

Three real defects this exposed, and the first is the instructive one:

1. THE RESERVED UNIT-CHILD BASES WERE COMPUTED TOO LATE.
   l2_mres_base and l2_ns_base were derived while the ENTRY's child count was
   assembled -- after every method body had already been written. In a method
   both were still zero, so a declaration and a bound result both resolved to
   child 0 of the unit.

   The fixture PASSED anyway. Seven independence checks, all green, on a
   program where A and R addressed the same Structure. I only caught it by
   reading the emitted roots and noticing every one of them said 0U. Write the
   assertion that would have caught it: the runner now pins that in-method
   paths reach two DISTINCT roots and that none of them is child 0.

   General form: a value that is a LAYOUT DECISION must be computed before the
   first thing that spells it, and a test that only checks end values cannot
   see two names collapsing onto one slot.

2. The result-slot map was built during merge LOWERING, so a method emitted
   before main could not resolve a field of a result whose merge statement
   lives in main. It is built in the PRE-SCAN now, beside the name reservation.

3. l2_scan_ident turned the root atom of a value-position path into an untyped
   dynamic input, and l2_dyn_typed then refused the method. A unit-level
   declaration and a bound merge result are names IN SCOPE reached through the
   unit; they are not free names.

A path load inside a method writes an OWN field -- cached value plus dirty
flag, published at the next checkpoint like any other own-field assignment.
A resolved-but-missing slot leaves a method through l2_emit_path_bail:
checkpoint first, then that method's own return shape, rather than the
int-only code the entry uses.

Callable fields and calls through a path (2026-09-13, 43ca961a)
---------------------------------------------------------------
A declaration holds a CALLABLE FIELD spelled with the reserved head:

    A:
        fn: M          # field named M, value = M's own Structure
        size_t: tag 1U
    end: A

The value stored is the unit child at l2_unit_base + mi, whose slot 0 holds
the shared METHOD descriptor. Nothing about it is special to merge: the copier
sees an ordinary Structure, copies it, and keeps the descriptor as a terminal
because it is classified by method_ranges. Field kind 4; resolved with the
reference fields after the whole unit is read, since M may come later.
l2_ns_field_mi is deliberately separate from l2_ns_field_ref -- one indexes
methods, the other declarations, and confusing them emitted unit child
4294967295.

A call through a path is the SAME call: same method, same signature, same
typed actuals, same throw closure. Only the reserved argument differs -- the
occurrence the path selected (l2_pst), never the unit child and never the
enclosing result. l2_head_method answers "which method does this head name"
for the checker, the statement dispatcher and the emitter, so all three agree;
they used to disagree, and the disagreement showed up as "unsupported body".

WHERE THE GRAMMAR DOES NOT DECIDE.
printTree, on the same file:

    A\x: 5U      ->  frame head="A\x" body=structure fields=1  atom "5U"
    A\x(5U)      ->  frame head="A\x" body=structure fields=1  atom "5U"
    A\x()        ->  frame head="A\x" body=structure fields=0

The first two are INDISTINGUISHABLE. So the spelling alone cannot separate an
update from a one-argument call, and only two things can:
  - the path ends at a CALLABLE field, which an update could never target;
  - the argument list is EMPTY, which an update could never be.
Everything else with a path head is an update. This is why the precise call
diagnostics exist only for those two shapes -- anywhere else, claiming a call
was meant would be guessing.

WHAT THE GENERATED PROGRAM PROVES (addresses, not values):
  77  the copy inside the result is a DIFFERENT occurrence
  78  its child 0 is the SAME descriptor terminal, never cloned
  79  its first own cell is a DIFFERENT address
Each was inverted once to confirm it fails: 77, 78, 79 respectively.

Lexical lookup through a copied M was TESTED, not assumed. M reads B\y through
its own node; for the copy, node is the copied unit, and the declaration is
still at the same child index, so the read succeeds. A copy that could not see
B would return 0 and fail the fixture. Do not weaken that read: it is the only
thing holding the remapped-node contract down.

Qualified branches: the full immutable body (2026-09-13, 772e147f)
-------------------------------------------------------------------
The qualification is unchanged; only the BODY generalised. It is now the
ordinary named-Structure field model -- size_t and char pointer-cell leaves,
inline nested Structures, translation-known references -- which is the whole
point: QUALIFICATION DECIDES STORAGE ADMISSION AND IMMUTABILITY, NOT SHAPE.
l2_take_eternal therefore calls l2_take_ns_body, and the emitter grew one
column (l2_ns_eternal) instead of a second emitter.

A qualified entry differs from an ordinary declaration in exactly three ways:
  1. its ROOT is lmx_node_new_owned -- node = 0, not a child of the unit;
  2. it is bound at its own reserved unit child, not among the declarations,
     which is why l2_ns_rank and l2_ns_top_count skip it;
  3. every owned typed range inside it is admitted through the Message
     classifier: the root, each nested Structure, each leaf cell.
Nested Structures keep ordinary internal node links. Only the root has none.

Enforcement, all at translation:
  - an update whose resolved target lies inside a branch is refused at any
    depth (l2_path_in_eternal walks the whole path, not just the root);
  - a reference out of a branch into ordinary mutable storage is refused --
    qualification admits an address range, it cannot make a mutable target
    eternal;
  - a callable field inside a branch is refused outright: a method's own
    fields ARE mutable storage.

merge and the admitted branch:
  - a branch is reached as an OPERAND through its qualified index, NEVER as an
    ordinary declaration. It is a terminal, so its direct children appear in
    the result at the SAME ADDRESSES (code 80), and the copy-map alias walk
    must not run over it -- it demanded copies merge correctly refuses to make.
  - an ORDINARY Structure holding a reference to a branch IS copied, and the
    reference must still point at the same branch (code 80 again), while a
    neighbouring mutable size_t cell comes out at a DIFFERENT address (code
    90). Those two together are the whole value of an eternal branch.
  - a char child is deliberately NOT checked for distinctness: the copier
    returns the same table cell when the destination keeps that table, so its
    address is equal by design rather than by accident.

Two defects this exposed:
  - the reference node check asserted "node = unit" for every unit-level
    target. False for a qualified root, which has no lexical parent at all.
  - putting branches in the shared declaration table made l2_ns_find succeed
    for them, which silently changed the collision cause and let the alias
    walk in. Sharing a table means auditing every reader of it, not just the
    writer.

Array fields (2026-09-13, 85680bae)
------------------------------------
The core plan's remaining frontend item, taken without a ticket under Codex's
standing instruction. The spelling is the one L2 already uses for an own
array, unchanged:

    []: int xs 3
    []: char cs 2

head "[]", then element type, name, count. Field kind 5. The count is the
value; the ELEMENT TYPE rides in the ref column and is read ONLY through

A record and its backing are TWO owned ranges. Inside a qualified branch both
are admitted: the rule is every owned range reachable inside the branch, and

The predef gate was widened in the SAME edit as the emitted call. This is the
char-table lesson applied before it could bite: an emitted constructor without

  91  an ORDINARY operand's array child is copied -- new record, new backing,
      declared length preserved
  80  an ADMITTED branch's array child keeps its exact address
Mutating the expected copied length fails with 91.

The lexical unit rule, generalised (2026-09-13, e2a01e96)
---------------------------------------------------------
Codex hit this in integration and I folded the fix back into the lane.

RULE: anything the emitter writes that reaches a UNIT-OWNED object must spell
the root through l2_unit_ref, never "unit" and never an entry-local binding.
l2_unit_ref is "unit" at the entry and node\node inside a method; a method has
neither the name nor the locals of the entry.

That covers, in the merge lowering: the operand array, the admitted-branch
child identity checks, the held-reference identity check, the callable copy
proofs and the ordinary copy proofs. A qualified branch is addressed at its
reserved unit child (l2_unit_base + l2_m_n + 2 + k), not through l2_ebrN.
The comparison temporaries l2_mxp / l2_myp / l2_malias are declared in method
bodies as well as the entry.

WHY MY GATE COULD NOT SEE IT: this lane still refuses merge inside a method,
so no fixture here could reach the broken spelling. Only the combined branch,
where that refusal is lifted, compiled it. A green gate proves what the gate
can reach, and a refusal I still carry is a hole in my own coverage -- when a
refusal is lifted downstream, everything written under it must be re-read.

Same shape as the "layout decision computed too late" note above: both are
cases where the thing that was wrong could not be exercised locally.

The Message dynamic input and the throw call side (2026-09-13, ef006bbe)
-------------------------------------------------------------------------
THE MESSAGE. l2_m_msg marks every method that merges, then closes over the
call graph: a caller of a Message-dependent method is Message-dependent. It is
a COMPILER-SELECTED dynamic input -- not a source name, never from node, never
global -- and it travels as the LAST hidden input:

    fn: l2_m0 (@: Lmx node; @: LmxMsg process_message; @: int l2_out_result; @@: Lmx l2_out_throw) int

The interned METHOD signature carries a column for it, so two methods that
differ only by this dependency cannot share a descriptor signature. That
column is a full parallel column of the intern -- grown, copied, freed and
reset beside l2_it_dyn -- because the alternative was encoding it into an
existing number, which is the kind of overloading that already cost me one
defect.

THE CALL SIDE OF THE DECLARED-THROW ABI, unfinished since df097919:

    status = fn(M, explicit..., hidden..., message, @ result, @ throw)

The caller branches on the status BEFORE the normal result is read. On a
nonzero status only the FAILURE GRAPH travels: a throwing caller forwards it
through its own out_throw, the entry stops with a distinguished code, and in
neither case is the ordinary result read or published -- on failure it does
not exist. That ordering is what the runner pins, not just the presence of a
branch.

MERGE INSIDE A METHOD is lowered; the refusal and its negative are withdrawn.
The merge allocates in that Message and takes the method's LEXICAL unit as its
container (node\node). The FULL merge local set is declared in method bodies,
not only the comparison temporaries -- I had declared only the temporaries
when preserving Codex's fix, and the operand array and result were still
missing.

Three gaps this exposed, all in name resolution rather than emission:
  - a merge result bound inside a METHOD must be reserved before any name is
    resolved, not at emission time, or the result name reads as a free name;
  - the free-name scan must skip a merge statement ENTIRELY: its head binds a
    result, its operands are declarations already in scope, and its body
    fields are new. None of it is a dynamic input;
  - the merge container and the result binding were still spelled "unit",
    which the lexical unit rule above should have caught and did not, because
    no fixture could reach them while merge-in-method was refused. Exactly the
    hole the previous note describes.

A failure has to go somewhere (2026-09-13, 109ac7db)
-----------------------------------------------------
Found by re-reading my own call-side lowering an hour after landing it. No
gate caught it, because no fixture had a non-throwing caller of a throwing
method.

The defect: a method that merely CALLS a throwing method did not carry the
throw ABI, so on a nonzero status the branch emitted "return: 0" in it. A
caller declared int then reported 0 on failure -- indistinguishable from a
legitimate success -- and the failure graph was dropped. "Propagate only the
failure graph" is not satisfiable when there is no channel to propagate
through.

RULE: the throw dependency is TRANSITIVE, like the Message dependency beside
it. A caller of a throwing method is itself throwing; both fixed points run
together over the same call graph. The entry has no channel and stops with its
distinguished code.

The branch that used to return 0 is now a translator assertion. Unreachable by
construction, and an assertion rather than a silent return PRECISELY BECAUSE
the silent return was the bug: if the invariant ever breaks, it must fail
loudly where it broke.

Consequence worth remembering separately: l2_merge_max was reset AFTER the
per-method scans had measured it, so a method that merged while main did not
got no operand array. The operand array is a local of EVERY body that merges,
not only the entry -- the comment saying otherwise was written when only the
entry could merge, and stayed true-looking after that stopped being so.

Pattern, now three times in this series: the dangerous code is the code my own
fixtures cannot reach. Here it was a shape no fixture had; before it was code
behind a refusal; before that a layout value computed too late. Reading new
code against shapes the fixtures do NOT contain is not optional.

Argument-as-own bind (2026-09-13, 780c58c1)
--------------------------------------------
Model section 11. An explicit argument is a private activation value until an
executed same-name bind; the bind keeps the SAME variable, does not preload
the graph slot over the incoming value, becomes dirty at the executed write,
and publishes at the checkpoint. It never writes back to the caller.

WHAT WAS ACTUALLY MISSING: almost nothing. l2_collect_asgn_body already bound
an assigned formal, and the emitter already did every part above. The gap was
one type guard -- int was excluded while char and size_t were admitted -- and
the model's own example is an int.

I started by writing a SECOND implementation in l2_collect_decls before
noticing the first. It duplicated the mechanism and reordered the own table,
which broke a historical assertion. Look for the existing mechanism before
building a parallel one: the reorder was the only visible symptom, and it
would have been an invisible layout change in a less tested area.

TWO BIND POINTS, AND WHICH WINS. An explicit same-name DECLARATION is the bind
point, and writes before it stay activation-local:

    fn: bind32 (char: n32) int
        n32: 3          # activation-local: the declaration below is the bind
        char: n32       # bind point
        n32: n32        # published

unit_own32_pub in the historical gate encodes exactly this, and it is what
caught my first attempt. When there is no declaration, the assignment is the
bind, as in the model's example.

l2_param_ty RETURNS 0 FOR BOTH "int" AND "NOT A PARAMETER". Admitting int on
the type alone bound every ordinary own field too. Membership is a separate
question from type and now has l2_param_is. This is the third time in this
series that two meanings shared one number and cost a defect -- the ref column
was the first, the entry-local bindings the second.

Limitation: an own declaration inside a nested if body is still unsupported,
so a bind introduced only there is unavailable. A conditional ARGUMENT bind
does work, and publishes only in the taken branch.

Callable recursion (2026-09-13, 94e7e9af)
------------------------------------------
The refusal was a whole-call-graph DFS in the frontend ("unsupported
recursion"). Lifting it was the entire change: recursion was already correct
underneath, and that is the finding worth keeping.

WHY NOTHING ELSE NEEDED CHANGING:
  - the own cache and its dirty flag are C LOCALS of the generated function,
    so every activation has its own without any extra machinery;
  - the published fields of the one callable Structure are shared, so the last
    executed dirty store wins -- which is what the model says publication
    means;
  - there is no post-call reload, so an outer activation keeps its own value;
  - the dynamic-input, Message and throw propagations are all FIXED POINTS, so
    they converge over cycles. Had any of them been a single pass, a cycle
    would have silently under-propagated.

The recursive call passes the SELECTED occurrence: node\node + index for a
direct self-call, l2_pst for one reached through a path. M.node stays the
lexical parent; slot 0 stays the shared descriptor.

HOW THE FIXTURE PROVES SEPARATE ACTIVATIONS: each method returns its OWN
activation's value while the recursion overwrites the shared published field.
Injecting a post-call reload into the generated L1 -- exactly what a shared
cache would look like -- makes it exit 81. A fixture that only checked the
final answer would pass either way.

THREE HISTORICAL EXPECTATIONS THIS RETIRES, in run_l2trans.ps1, which is NOT
in my boundary: unit_rec (direct), unit_cycle (mutual), unit_cycle32 (a
32-method cycle). All three assert the refusal. I verified on a throwaway copy
that retiring exactly those three leaves the historical gate green, then
deleted the copy. Reporting a conflict with the evidence of its extent beats
either editing someone else's gate or claiming green.


================================================================================
POINTER LOCALS INSIDE A METHOD BODY: A SEPARATE COMPILE-TIME TABLE
================================================================================

The entry's local table (l2_loc_*) is the entry activation's namespace. A
method body cannot share it. Two reasons, and both are about the model rather
than about convenience:

  - the same spelling names different things in different methods. `scratch`
    is an unsigned* in one and a void* in another, and neither method can see
    the other's declaration, so one flat table would have to reject the second
    one as a duplicate;
  - recursion needs one storage per activation. A method local is a C local of
    the generated function, which gives that for free; a shared table would
    suggest a shared name, and a shared name is exactly the thing recursion
    must not have.

So method bodies get their own table, l2_ml_*, and the entry's is untouched:
its array kinds, its slot kinds, its duplicate rule, all unchanged. The two
tables never merge and never consult each other.

THE TABLE IS SCRATCH. l2_ml_rebuild clears it and collects one method body,
and it is called immediately before each of the three phases that walk that
body -- scan, check, emit. No phase inherits what another left behind, so no
phase can see a name another does not. This is the shape the earlier attempt
got wrong: one table filled once and read by two phases meant the emitter was
reading the checker's leftovers, and the entry regressed.

WHAT THE TABLE DOES NOT CLAIM. `@: char`, `@: LmP0Text`, `@: size_t` and
`@: LmP0IndentStack` in a method body are the 11.2.1 ADDRESS SLOT form, not
activation locals: the method preamble declares them and l2_slot_find resolves
reads of them. l2_ml_collect skips anything l2_slot_decl_ty claims, so those
keep their existing meaning exactly. The first version of this slice did not,
and the generated method declared `scratch` twice -- once as its slot
`l2_s1_0` and once as a local -- while the read still resolved to the slot.
The fixture's second method was rewritten from `@: char` to `@: void` for
this reason: `@: char` was never in question, it was already a slot.

THE THREE PHASES:

  - scan: a name the body declares is a name IN SCOPE of its own activation,
    so it is not a free name and must not be inferred as a dynamic input.
    l2_scan_ident returns 0 for it, next to the formals and the slots. The
    exemption is method-only for free, because l2_scan_ident returns at the
    top when mi < 0;
  - check: for mi >= 0 the declaration is accepted (the table already holds
    it) and an assignment whose head the table knows is checked as an ordinary
    assignment. Both are separate branches from the entry's, which keep their
    mi < 0 gate;
  - emit: in a method body exactly two shapes are admitted -- the pointer-local
    declaration whose name the table owns, and an assignment to a name the
    table owns. Everything else below that guard is entry-only and stays gated
    on mi < 0: the array local, the array-element assignment, the immutable
    block, the const local, and the l2_loc_find assignment path.

Reads need no emitter work at all: l2_prep's atom fallback is l2_tok_text, the
name verbatim, which is what the declaration spells. Only the CHECKER had to
learn the name, which is where the first run failed -- "unresolved name" on
`if: scratch != 0`, three lines after a declaration the emitter would have
been happy to print.

FIXTURE unit_ptr_local_scope.lm2 pins all four cases in one unit: two methods
declaring the same name at different pointer types, a recursive method with a
pointer local, and the entry declaring the same name again. The assertions
check each method body separately -- the span between `fn: l2_mN (` and
`end: l2_mN` -- so a leak in either direction fails: neither method may
contain the other's type, and the count of scratch declarations must be
exactly four, each indented inside its own body, none at column 0.

Gates: run_graph_abi.ps1 122/122 (the new fixture tripwired first, to prove
its assertion block executes rather than trusting the count). run_l2trans.ps1
green end to end EXCEPT the three stale "unsupported recursion" negatives
already reported -- unit_rec, unit_cycle, unit_cycle32 -- which HEAD's own
translator also translates with exit 0. They are stale against the landed
recursion support, not a regression from this slice; run_l2trans.ps1 is not
in my boundary, so they stay for its owner to retire.


================================================================================
FIRST RUNTIME MODULE IN L2: lmx_msg_storage
================================================================================

The module is two operations over four owner head slots: a preflight that asks
whether a paired move is legal, and a move that re-asks and then performs it.
It allocates nothing, owns nothing and decides nothing about lifecycle. That
is why it goes first: the port is about the SOURCE PATH, not about inventing
behaviour, and this module has the least behaviour to get wrong.

WHAT L2 WAS MISSING: the four list operations themselves. The module is
nothing but calls to lmx_msg_blocks_can_move / move_all and
lmx_owned_ranges_can_move / move_all, and unknown c.* is rejected -- correctly.
So the smallest frontend support is those four names, admitted by NAME and by
SHAPE: two owner head slots in, a status out, nothing else. A neighbouring
real operation of the same lists -- lmx_msg_blocks_remove, say -- is still an
unknown method, which negative msg_bad_call pins.

No predef was needed. l2src/lmx_message.h already includes the blocks and
ranges headers, and every generated program includes lmx_message.h, so the
prototypes are in scope wherever the emitter can put a call. I checked this
rather than assuming it: a missing generated declaration is how a pointer got
truncated to int two slices ago, and the symptom landed layers away.

THE STATUS LITERALS. L2 has no define form, so the .lm2 spells 0 and 1 where
the L1 module spells LMX_MSG_STORAGE_OK and LMX_MSG_STORAGE_INVALID. They are
those defines -- OK is 0 and INVALID is 1 in all three headers -- but the
source no longer says so, and a comment is not a guarantee. What guarantees it
is the parity runner, twice over: it drives the module's OWN selftest, which
spells the names, against the generated implementation -- and it reads the
three headers and asserts the six defines still are 0 and 1. The selftest
alone would not catch a header renumbered under a source file that can no
longer refer to it. I renumbered one and watched the runner say which literal
had drifted.

PARITY WITHOUT A MODULE EMISSION MODE. The emitter produces closed programs:
methods are l2_m{i} and the entry builds the unit graph, so there are no
exported source symbols to link against. Codex settled that observable parity
through the existing mangled-entry/splice-drive mechanism is the acceptance
method for this slice, and that a reusable module emission mode is a later
self-build boundary.

The runner therefore:
  - builds the same support object set the graph gate links;
  - runs the existing selftest against the handwritten module. That is the
    REFERENCE: exit and stdout;
  - translates l2src/lmx_msg_storage.lm2 with the translator built from THIS
    checkout, splices the generated entry to publish the two selected
    callables, and compiles the selftest a second time with its two call sites
    redirected by -D onto wrappers over l2_m0 and l2_m1;
  - requires the parity run to match the reference exactly, twice.

ONE THING THAT DOES NOT WORK, AND WHY. The obvious move -- export the real
symbols from the wrappers and let everything call the generated code --
deadlocks. Building the unit graph is itself a storage move: lmx_branch_owned,
lmx_value_owned, lmx_chars_owned and the array modules all call
lmx_msg_storage_move_all while allocating. So the wrappers would be called
before the entry had published the callables they select, the construction
would fail, and the program would exit before printing anything. That is
exactly what the first version did: exit 1, no output. The graph construction
keeps the handwritten module; only the selftest's own call sites are
redirected. The port is what the TEST exercises, not what the runtime
bootstraps on -- which is the honest scope of this slice anyway.

A redirection that silently did not happen would pass every check and prove
nothing, so the driven entry counts the calls that actually reached the
generated methods and the runner pins that count at 31. I also armed two
tripwires and watched them fire: dropping the ranges preflight call (caught
statically, by the lowering assertions) and keeping the call but inverting its
verdict (caught dynamically -- the parity binary crashed where the reference
exits 0).

ALLOCATION FAILURE: there is none to exercise here. Neither operation
allocates, which the runner asserts of the generated C rather than taking on
trust. The allocation-failure behaviour of the storage lists lives in
lmx_msg_blocks and lmx_owned_ranges, which this slice does not touch.

TWO DIFFERENCES BETWEEN THE GENERATED AND THE HANDWRITTEN MODULE, both from
the standard method prologue rather than from the port:
  - a generated method begins with `if: node = 0 / return: 0`, and 0 is OK.
    The handwritten module has no such guard. It cannot fire here, because the
    wrapper passes a callable the entry has already checked, but it is a
    difference in the emitted contract worth recording;
  - every return is preceded by an escape poll that returns 0 on escape,
    which is again OK. Same reasoning, same note.
Neither is mine to change in this slice; both are properties of every method
the emitter has ever produced.

================================================================================
SECOND RUNTIME MODULE IN L2: lmx_msg_slots
================================================================================

Two read-only operations over the runtime's slot list: a count that is the
owner's cached n, never a traversal, and an enumeration that follows alloc_next
and nothing else. The four adapter fields it needs -- rt\n, rt\slots,
m\alloc_next, m\addr -- were the ones approved for the staged adapter and had
already landed, so this port needed vocabulary rather than mechanism.

WHAT L2 WAS MISSING, four things, each small:

  1. LmxMsgAddr as a RETURN type. It is a typedef of unsigned, so its zero is
     0U and it shares every "the zero of this return type is unsigned"
     decision with size_t. Rather than copy fourteen conditions, the two now
     ask l2_ret_uns(mi), which says yes for both; they part company only where
     the type itself is printed, in three places.
  2. A const pointer local of a foreign type: const: @(LmxMsg m), the cursor
     an enumeration walks with. Const pointee, mutable pointer, exactly as the
     handwritten module declares it.
  3. That const local had to become an activation local rather than an entry
     one, which is the method-local table from the previous slice, extended to
     collect const declarations as well as pointer ones.
  4. A const declaration is not a reference. The free-name scan read the TYPE
     atom of const: @(LmxMsg m) as a name, inferred "LmxMsg" as an untyped
     dynamic input, and refused the method as an "unresolved name" that names
     nothing the source wrote. This is the same defect link 5 fixed for
     pointer-local declarations, in the branch next door. I found it the same
     way: by printing the offending name's length rather than reasoning about
     it. Length 6 is LmxMsg, not m.

ONE PLACE THE LOWERING CANNOT SPELL THE TYPE. A call result lands in a
generated temp, and L1's LOCAL type vocabulary is its own: "LmxMsgAddr: l2_t1"
is an unknown type name there. The temp is therefore the underlying unsigned.
That is not a workaround -- it is why the handwritten module spells LmxMsgAddr
only in a return position too. The gate asserts the unsigned temp, so the
assertion says what the lowering does rather than what I first assumed it
would.

A REAL DIFFERENCE FROM THE HANDWRITTEN MODULE, and it is the model, not a
defect. In L2 a method's ordinary declarations ARE fields of its callable, so
there is no such thing as a scratch int that lives nowhere. The enumeration
decrements its index argument, and a write inside an executable body publishes
into that body's host: the generated method therefore takes a slot and a dirty
flag for the counter and checkpoints it. The handwritten module keeps the same
counter in a register. Nothing observable to the caller changes -- the
selftest's checks on the fixture's own memory and on every returned address
pass identically -- but the generated version does write its own callable
Structure while enumerating, and a reader of the two sources should know that
before concluding they are the same program. Any counter would cost this; the
alternative is not a cheaper lowering but a different model.

PARITY IS STRONGER HERE THAN FOR STORAGE. Nothing in the runtime calls these
two while a graph is being built -- the only non-test callers are two
forwarders in lmx_message_exec.c -- so the wrappers EXPORT THE REAL SYMBOLS
and the selftest links against lmx_msg_slots_n and lmx_msg_slots_at by name,
exactly as any other caller would. No -D redirection, no edited test. The
storage module could not do this: building the unit graph is itself a storage
move, so its wrappers would have run before the entry published the callables
they select.

I did not want that to be a belief. The wrappers count their calls AND count
separately any call arriving before publication; the runner pins 279 calls and
requires zero early ones. If this module ever acquires the bootstrap problem,
the runner says so in those words instead of quietly returning zeros.

Tripwire: an off-by-one in the traversal (i >= 0 instead of i > 0), which
leaves every signature, every field access and every lowering assertion intact
and changes only the answer. The parity run failed on "allocation order
independent of address, state and graph", which is the selftest's own words.

ALLOCATION FAILURE: none to exercise. Neither operation allocates, which the
runner asserts of the generated output rather than taking on trust.

Gates: run_port_msg_slots.ps1 PASS, 278 checks, 0 failures, both runs

124/124 with 41 negatives, the new assertion block tripwired first.

================================================================================
THIRD RUNTIME MODULE IN L2: lmx_msg_path_storage
================================================================================

One function, and the only one of the three that allocates. It grows a PRIVATE
placement-path buffer the owner holds in two slots: an unsigned** for the
buffer and an int* for its capacity. The header is explicit that this is never
graph or arena storage, which is the whole reason it may use realloc at all.

FIVE CONSTRUCTS, all of them decided by Codex rather than guessed by me:

  1. READ AND WRITE THROUGH AN OUT-PARAMETER, with ordinary C pointer
     semantics. Reading (path_cap[0] >= need) and storing a non-literal
     (path_cap[0]: cap) already worked; what did not was doing either through
     an unsigned** owner slot, because l2_index_head admitted only the int,
     size_t and char out-parameter kinds. An unsigned** owner slot is the same
     kind of out-parameter, one indirection wider.
  2. c.realloc, as a foreign door FOR THIS BUFFER ONLY. It is not exposed as a
     graph-storage operation: it is one admitted name emitted as itself, and
     negative bad_alloc_door pins that c.malloc next door is still an unknown
     method.
  3. c.sizeof of the machine unsigned.
  4. cast, as an ordinary C-style low-level conversion, with the target type
     VALIDATED against a closed list: size_t and unsigned*. Negative
     cast_bad_type pins that a target outside the pair is "unknown cast type",
     not a hole.
  5. The chunk size pinned to the header. The parity runner reads
     lmx_msg_path_storage.h.lm1 and asserts all four defines before it builds
     anything -- and this one matters more than a status code does, because a
     status is observable through the selftest and a chunk size is not. I
     renumbered LMX_MSG_PATH_STORAGE_CHUNK to 8 and watched the runner name the
     literal that had drifted.

TWO THINGS THE PARSER DECIDES, NOT ME:

  - c.sizeof(unsigned) collapses into a SINGLE ATOM, because "unsigned" is a
     reserved word; c.sizeof(c.Foo) does not. So the L2 source spells
     c.sizeof(c.unsigned), which reaches the translator as a call, and the
     emitted L1 is the bare c.sizeof(unsigned) that L1 itself spells. Both
     halves are asserted: the L2 spelling must not leak into L1.
  - -1 is one atom when glued to the minus and two when spaced. l2_num refused
     any leading minus, so (cast: (size_t) -1) -- the largest size_t, and how
     the handwritten guard is written -- was not a number. A glued leading
     minus is part of the literal; l2_digits, and therefore l2_int_fits, is
     untouched, so nothing that measures an int literal changed.

A CAST IS NOT A REFERENCE. Same defect as link 5 and the const-local one, third
occurrence: the free-name scan read the word "cast" and the type it names as
identifiers. A cast scans only its operand now. Three branches of the same
mistake have now been fixed one at a time; if a fourth declaration form appears
it will have it too, and that is worth saying out loud rather than fixing
quietly again.

THE BOOTSTRAP PROBLEM, MEASURED BEFORE WRITING THE RUNNER rather than found as
a crash: lmx_msg_assign_path calls lmx_msg_path_grow from inside
lmx_msg_create, so the runtime grows a placement path while creating the very
Message whose graph the generated callable lives in. Exporting the real symbol
would call the generated method before the entry published it -- the storage
module's failure exactly. So the selftest's one call site is redirected by -D
and the runtime keeps the handwritten module. lmx_msg_slots remains the only
one of the three that can export its real symbols.

That redirection has a consequence worth naming: the runtime's own path_grow
during Message creation goes through the selftest's __wrap_realloc, so it would
shift every absolute allocation count in the test. The drive takes and clears
the counters immediately before the test and REPORTS what it took, on stderr;
the runner requires that number to be exactly 1. A reset that silently
swallowed the count would hide the day the runtime starts growing two.

ALLOCATION FAILURE IS THE POINT HERE, unlike the other two modules. The
selftest injects failures through --wrap=realloc; the runner requires at least
eleven wrapped allocations, so a link that lost the wrap fails loudly instead
of quietly skipping the entire NOMEM half of the test.

FAILURE ATOMICITY is asserted twice over. Statically: the publication of the
buffer must be the last thing in the method, with no refusal reachable after
it. Dynamically: I moved the capacity publication ahead of the realloc -- which
leaves every signature, guard and lowering assertion intact -- and the parity
run failed on "failed initial allocation leaves empty owner", the selftest's
own words.

Gates: run_port_msg_path_storage.ps1 PASS, 541 checks, 0 failures, 11 wrapped
allocations, 0 size-guard checks (this is a 64-bit run; the selftest documents
why the 32-bit byte-size branch is unreachable here and refuses to pretend

MODULES FOUR AND FIVE, DONE: WHAT THE LIBRARY UNIT CHANGED, AND ONE AMBIGUITY
================================================================================

All five runtime modules now have clean-L2 sources with parity against their L1
oracles. The last two arrived after Codex's compiler slice (7d7ec87c), and the
slice changed the shape of the work rather than just unblocking it.

LIBRARY EMISSION REPLACED THE SPLICE. A .lm2 with no entry is a library unit:
module-unique internals plus public wrappers carrying the source signatures. The
first three runners had to splice the generated entry, publish selected
callables into file-scope pointers and hand-write wrappers; these two do none of
that. That was the boundary I had asked about, and it is gone.

WHAT IT DID NOT SOLVE, AND WHY. A library unit cannot take the exported ABI
names of a module the runtime calls while allocating. l2_library_open builds the
unit's graph on first use, allocating; every arena allocation calls
lmx_msg_storage_move_all, which calls lmx_msg_blocks_can_move and
lmx_owned_ranges_can_move. So those two units name their operations blocks_*
and ranges_*, the selftests are redirected onto those names, and the runtime
keeps the handwritten modules -- which is also what lets l2_library_open work at
all. Measured for all five now: only lmx_msg_slots is free of it.

ONE REAL AMBIGUITY, and the reason it did not become a grammar extension.
"d: value" and "d(value)" are the SAME parse tree: a frame with a head and a
body. For a method the name registry decides which it is. For a
function-pointer local there is no registry, so the language cannot express
both spellings for one name -- and lmx_msg_blocks needs both, because it reads
a disposer out of a node and then calls it.

I did not extend the grammar. The disposer is declared WITH its value, the form
the language already has for pointer locals, and the head then only ever
appears as a call. Before that the emitter read the call as an assignment and
produced "disposer: item\baseitem\n" -- two operands glued together, which is
not even the wrong operation.

Worth stating plainly: this is the first thing in five modules that was a
LANGUAGE surface rather than a missing spelling. Everything else on the list --
casts over field reads, modulo, an address prefix, the address of a method
local, the adapter types in a public signature -- was L2 already meaning
something it could not yet say.

FOURTH OCCURRENCE OF ONE DEFECT. A declaration is a TYPE and a name, and
neither is a reference. The free-name scan has now read the type of a pointer
local (bc1d2fa0), a const local (cae0097e), a cast (f5a399f9) and a
function-pointer local as identifiers, each time refusing the whole method as
an "unresolved name" that names nothing the source wrote. Four branches, four
fixes, one rule. A fifth declaration form will have it too.

A GAP WITH NO DIAGNOSTIC, which cost more than the gap. A library unit whose
formal was @@: LmxOwnedRange failed with exit 1 and no output at all, because
l2_emit_public_sig had no case for the four staged adapter types. It now
handles them and SAYS which type it cannot spell if another appears. A silent
return is a worse defect than a missing case: the missing case takes minutes,
the silence took an hour and a bisect.

AND ONE CORRECTION TO MY OWN TOOLING: a probe that reported "translates" by
checking whether stderr was empty, while the exit code was 1. It told me
owned_ranges was done when it was not. Check the exit code, not the noise.

Evidence: blocks 143 checks, 0 failures, 147 frees, 2 disposer callbacks;
ranges 439 checks, 0 failures; both agree with their oracles on two runs.
run_graph_abi.ps1 134/134 with 41 negatives. run_l2trans.ps1 "l2trans gen2 ok"

- l2_quoted_has_function decides "declared C function" by text: the name,

A FAILED LIBRARY OPEN IS REPORTED, 2026-09-14

Found by e2: a generated public wrapper answered a failed l2_library_open with
`return`, `return: 0U` or `return: 0`. For a status ABI such as
lmx_graph_copy_owned, where 0 means OK, an open failure read as success.

Ruling (e2, reported to Mikhail as reversible): this is the settled checkpoint
rule applied to a new site, not a new rule. It follows SPEC 21.6 / 21.13.3 and
ABI 14.23, and the same route as a failed checkpoint publication. Every failed

`if: c.lmx_msg_poll_abort() != 0` -> `c.abort()`. Without abort it returns the

status ABI that needs one declares it (model §14, no process-static throw
channel). l2_library_open already retries when the runtime is 0, so the report
repeats on every call. The rule is also recorded in model §14.

FOREIGN C IS c.name; THE TRANSLATOR READS NO C HEADER TEXT (STAGE A), 2026-09-14

Mikhail's rulings, through e2 and to this chat directly:
- Delete the checks of whether a c.name is declared: "Уберите из кода всю эту
  паранойю".
- Require c. for every foreign C call ("Требовать c. для всех C"). A C function
  called without c. is a namespace bug.
- Standing rule: if the spec does not require a check, delete it with its
  diagnostics and write the deletion down.

Rule, from spec 6.6.6 and 20.2.2:
- `c.name(args)` and `c.NAME` are the foreign door. They are emitted as written;
  the C compiler checks the declaration and the ABI.
- A bare `name(args)` is an L2 call, resolved only against unit methods and
  parsed `prototype:` fn/sub declarations of predef'd .h.lm1. An unresolved one
  gets the unresolved-method diagnostic, never a trip to gcc.
- Whether a callee takes c. is decided by where it is IMPLEMENTED, not where it
  is declared (e2):
  - libc, Win32, and the hand-written lmx_message_exec.c / lmx_message_host.c /
    lmx_poll_stub.c / lmx_dec.c / mixa_console_window.c take c.;
  - L1/L2-implemented functions (mixa_*, lmx_msg_*, runtime modules) take a
    prototype: declaration, never c..

Deleted:
- l2_include_has_function: its text scan of quoted include files for `name(`.
- l2_quoted_has_function: the same scan per header, with the keyword guard
  f95125d4 added to it.
- l2_c_header_chain_has_function, and the function half of l2_c_header_walk.
  The typedef half stays until Stage B.
- The include: branch of l2_predef_file_has_function, which followed a .h.lm1
  into C header text.
- l2_predef_has_function's second loop, a verbatim duplicate of the first
  pass's prototype parse.
- The closed known-name lists in l2_is_known, including the bare C names getenv,
  system, strcmp, strlen, memcpy, fopen, fclose, fread, fwrite, ferror.
- The same closed lists at the expression C-call door and the statement C-call
  door.
- The generated-unit comment "Known C: ... Unknown c.* is rejected".

- Include flags a name implies (c.malloc and kin -> <stdlib.h>, c.strcmp and kin
  -> <string.h>, lm_p0_* / c.lm_p0_set_diagnostic -> the p0 adapter). They are
  emission needs and fail open: an unknown c. name gets no include and no

THE ULONG OWNED DOMAIN (TRANSLATOR HALF), 2026-09-14

Ruling (e2, reported to Mikhail as reversible): a by-value local of a
language numeric type is a Message-owned typed cell, like int (spec 21.5.1 makes
every executable body part of the graph; 6.6 lists ulong, u8..i64, float and
double as language numeric types). The four runtime types before this were the
implemented subset, not the value model. Foreign C aggregates (the type-41
struct local) stay activation-local substrate, as spec 20.2.1 keeps raw
substrate out of the Lmx model. The runtime half is 6e846894.

Codes: a `ulong: x` local is own code 36 (cell); `[]: ulong x N` is own code 37
(Array). Both are unused in every type space. Code 9 was free among own codes
but is the formal code of `@: size_t`, and l2_bind_own compares formal and own
codes for a same-named argument; reusing it would give one number two meanings.

What changed, each a twin of the existing unsigned (code 3/6) path:
- Recognition: "ulong" -> 36 in l2_own_decl_ty; "ulong" as an own-Array element
  -> 37; l2_own_is_array takes 37; "ulong" joins the two statement-shape filters
  that name the primitive declaration heads.
- The four lists of numeric own codes and the one exclusion list take 36.
- Every unsigned emission branch (12) has a ulong twin: cache declaration and
  preload at entry, graph load, cast, the two checkpoint stores, the two direct
  stores, unit-slot construction and initial store, and body-slot construction.
  lmx_unsigned_* becomes lmx_ulong_* and the declared C type becomes ulong. They
  were generated from the unsigned lines, so no path was written by hand.
- The Array pointer and element-load spelling take "ulong" for 37. The two
  Array constructions emit LMX_TYPE_ARRAY_OF_ULONG. Element store goes through
  the same typed data pointer.
- A unit-level ulong field takes a literal initialiser.

Loud refusal: l2_unimpl_numeric names a by-value float, double, long, llong,
ullong, uint, u8..u64, i8..i64 or wchar_t local and refuses it with
"by-value <type> local not yet implemented", in both body checks (method and

ULONG IN THE SIGNATURE, 2026-09-14

Landed after the locals: 38cc44dc. A ulong formal and a ulong return use code
36 in l2_ft and l2_m_ret. That is the ulong own code, and it is chosen on
purpose: l2_bind_own compares a formal's code with the own code of the field
the formal becomes, so a written ulong formal binds to a ulong own field with
nothing to translate.

The formal becomes an own field when it is written: an executed `v: ...` makes
the argument an own field from that point (SPEC 11.3.1, 21.5.1). int, char and
size_t formals already did this; 36 joins that list. Its checkpoint is the
existing `lmx_ulong_store_known(l2_qN_from[0], l2_pM_K)`.

Sites, each an unsigned (34 / 33) twin:
- l2_int_formal head and l2_typed_formal: 36;
- the return atom and its "incompatible entry signature" exclusion;
- l2_ret_uns, so a failed or null-node return is 0U;
- a formal naming an index;
- the call-result temporary `ulong: l2_tN`;
- l2_emit_sig formal, the throw ABI `@: ulong l2_out_result`, `) ulong`;
- l2_emit_public_sig formal, its spellable-code list, `) ulong`.

Fixtures:

  the int range and `v` is written;
- library_ulong: the public signature `ulong_value (ulong: value) ulong`.

THREE STOPS FROM THE RUNTIME PORTS: CAST @ INT, @ ULONG, C.SIZEOF, 2026-09-14

e2 reported all three from lmx_value_owned and lmx_array_owned, with 9-line
repros (runtime-l2 scratch_mail fx5/fx6).

1. `(cast: (@: int) v)` failed with "unsupported cast type". Both pointer
   branches of l2_cast_type require l2_ident on the pointee, and l2_ident
   reserves `int`. `@: char`, `@: size_t` and `@: unsigned` passed only because
   they are identifiers. `int` is now admitted there too.

2. A `@: ulong` local failed with "unsupported body, frame=@". The pointer
   types knew unsigned and not ulong, so ulong fell into l2_foreign_intern,
   which returns -2. New codes follow unsigned (25/24): 38 is `@: ulong` and 39
   is `@@: ulong`. They are added to:
   - both pointer-declarator parsers;
   - l2_pointer_depth;
   - the raw pointer spelling and the own-pointer cache declaration;
   - the local declaration;
   - the typed formals and the index formal list;
   - l2_emit_sig, l2_emit_public_sig and the entry formal emitter.
   `(cast: (@: ulong) v)` already passed; it was only hidden behind the
   declaration.

3. `c.sizeof(<variable>)` reached C under its source name. The parser returns
   `c.sizeof(...)` as a single C surface atom, so l2_prep's atom branch copied
   it with l2_tok_text, and the checker admits every `c.` atom. The c.sizeof
   frame branches in l2_check_primary and l2_prep were never reached for it.
   The defect was wider than own fields. `c.sizeof(nonexistent)` translated,
   and `c.sizeof(v)` on a formal came out as `v` instead of l2_p0_0.
   l2_prep_sizeof_name now runs first in the atom branch and looks at an
   operand that is a single name:
   - a formal becomes `c.sizeof(l2_pM_K)`;
   - an own scalar field (int, char, size_t, unsigned, ulong), resolved in
     l2_own_find's order, becomes a zero temporary of its declared type, then
     `c.sizeof(l2_tN)`. sizeof does not evaluate, so nothing is loaded from the
     graph, and a field used only inside sizeof needs no working local;
   - any other own field type is refused by name;
   - any other operand (a type such as c.int, a foreign name, an expression)
     stays foreign C as written.
   Why a temporary and not a type name: L1 copies `c.sizeof(ulong)` literally,
   giving `sizeof(ulong)`, which is not C. L1 also refuses a nested cast inside
   a compact c. call. Both were probed in scratch.

Fixtures, each built and run: unit_cast_ptr_int, unit_ulong_ptr_local (the

Landed c926fb11. A fourth shape followed from e2's lmx_msg_visit:
`c.sizeof(s\v[0])`, the element stride. This one arrives as a c.sizeof frame,
not the surface atom, and its body holds several fields (s, \, v, [0]). Both
c.sizeof branches accepted only one atom or a `@: T` frame, so even a plain
`c.sizeof(s\v)` was "unknown foreign type". Passing it as written would reach
C as `s`, and `s` is an L2 variable (here the formal l2_p0_0). An operand of
several fields is therefore an L2 expression: l2_check_primary checks it with

A FOREIGN C CALL WITH NO ARGUMENTS, 2026-09-14

e2 found that `v: c.rand()`, `if: c.rand() < 0` and `c.abort()` as a
statement were all "unsupported body". lmx_message needs five of them
(lmx_msg_slot_new(), the test fault hooks). A one-argument call to an
undeclared name translated, so the name was not the problem. The parser gives
an empty call an empty body. The known-call branch of l2_check_primary passed
its 0 fields to l2_check_fields, which refuses n <= 0 as "unsupported body".
l2_emit_ccall also returned 1 when the frame had no body.

Now a generic C call (l2_c_stmt_door, so still not c.sizeof, c.puts or c.array)
with no body or an empty one is a zero-argument call. l2_emit_ccall treats a
missing body as no actuals and emits the call as written. L1 already lowers
`c.rand()` to `rand()` and `c.abort()` to `abort();`; that was probed in
scratch before the change. Fixture unit_c_empty_call is built and run with all
three positions, and the runner checks that the generated L1 keeps the calls
as written.

The first graph gate on this fixture was red: "generated L1 has 11 abort(s)
but 10 diagnostic-root escapes". The gate counted every `c.abort()` line as a
checkpoint abort. The eleventh was the fixture's own `c.abort()` statement,
which is foreign C the program wrote, not a checkpoint policy site. The gate
keeps SPEC 19.13's invariant for generated code. Each
`if: c.lmx_msg_poll_abort() != 0` must guard an abort directly, and the aborts
in the L1 beyond those the L2 source spells must equal the escapes. After

TWO MISCOMPILES FROM LMX_MESSAGE, 2026-09-14

Found by e2. Fixtures are e2's (038aae34): l2_and_foreign_call_own_local and
l2_index_store_reassigned_formal. Both produced C that does not compile.

1. A boxed C-call actual renamed the condition temporary. In
   `if: a != 0U && c.lmx_msg_exec_bind_held_locked(rt, i) = 0`, `i` is an own
   int. l2_emit_ccall boxes such an actual into a temporary, and took its
   name through the shared l2_tok buffer, which was also the destination the
   && evaluation had just named. The condition temp became the box temp, so the
   call received its own result, `l2_t4: (c.f(l2_p0_0, l2_t4) = 0) != 0`, and
   the `if:` read a name declared one block in. The box name now has its own
   buffer in l2_emit_ccall. The condition temp `l2_t3` is declared and read in
   one block, and the call gets `l2_t4`, declared and assigned `l2_q0` (own
   field `i`).

2. An index token ignored the formal binding. In `out[n]: m\addr` followed by
   `n: n + 1`, the write makes `n` an own field bound to the formal
   (l2_bind_own, l2_m_alias). Such a field has no working local; the formal
   is its storage, and its checkpoint stores `l2_p0_3`. l2_index_token (plain
   index and index expression) and the prefix-path token still spelled it
   l2_q0, which is never declared. They now spell an aliased own field as its
   formal, as the atom path already did: `l2_p0_1[l2_p0_3]: l2_p0_0\addr`.

STAGE B, STEP 1: A FOREIGN POINTER TYPE IS SPELLED AS WRITTEN, 2026-09-14

Mikhail's ruling: foreign types are spelled as written, and a check the spec
does not require is deleted together with its diagnostic. l2_foreign_intern
