Representation and API
----------------------
Lmx is Structure-only: Lmx *node; int len; void *data. len is child count,
data addresses void * slots. A stored child value points directly to the
appropriate typed target; the address of its slot does not give child type.

lmx_branch_slot_known(parent, i)  -> void **, address of the slot
lmx_branch_child_known(parent, i) -> void *, current target (ABI changed)
lmx_branch_store_known(parent, i, value) -> stores the new target
lmx_branch_struct_known(parent, i) -> Lmx *, compiler-proven Structure only
lmx_node_new_owned(...) -> root Structure, STRUCT kind/type
lmx_struct_new_owned(parent, ...) -> nested Structure initialized with parent
lmx_charptr_* -> typed char * cell, directly pointing to a C string

Slot storage is CHILDREN/BRANCH, stride sizeof(void *). Structure headers
are STRUCT/STRUCT. Primitives, Array records and method records have no Lmx
wrapper. The emitter constructs nested headers separately and uses slots
for field access, caches and checkpoint publication.

Codex corrected stale COMMENTS in lmx.h and the two API headers only:
there is no node-freeze rule. Used-graph copying rewrites destination node
and ordinary references; shared method-descriptor pointers stay unchanged.
No implementation or test expectation was changed by that correction.

Used-graph copier checkpoint (Fable) — 2026-09-12 10:43
------------------------------------------------------
New files, branch fable/graph-copy from codex/fable-abi-review e06966ee:
  l2src/lmx_graph_copy_owned.h.lm1, l2src/lmx_graph_copy_owned.lm1,
  l2src/tests/lmx_graph_copy_selftest.lm1; run_graph_abi.ps1 gained the
  module and a copy-selftest stage. No runtime, emitter or Grok file changed.

API (SPEC 2.3, ABI 8.2, user decisions 2026-09-12):
  fn: lmx_graph_copy_owned (@: Lmx source; @: LmxOwnedRange src_ranges;
      @: char dst_chars; @@: LmxMsgBlock dst_blocks;
      @@: LmxOwnedRange dst_ranges; @@: Lmx out) int
  0 OK, 1 INVALID, 2 NOMEM, 3 UNSUPPORTED.

Traversal. Seed the source and its lexical chain to node = 0; each queued
Structure gets a destination header registered in the operation-local map
BEFORE its edges are followed; processing copies every slot and queues the
lexical parent, so the whole reachable lexical tree is copied (this is the
conservative whole-tree reading of "used"; independent bounds it with its
zero root). Per child value, classified by src_ranges: STRUCT -> copied
Structure (and its own lexical chain); INT/SIZE_T/CHAR_PTR cells -> new cells
with equal values, once per source address (aliases preserved); interned
CHAR -> the same byte in dst_chars, or the source cell when dst_chars is 0
(same-Message copy); METHOD -> the same descriptor pointer (methods are
shared); Array record -> new record plus new backing (memcpy for CHAR/INT
backing; element-wise copy for LMX/DESC/METHOD reference arrays, registered
before following elements so cycles terminate); a value not classified by
src_ranges is kept as is (not language-owned storage of the source). After
processing, every copied Structure's node is rewritten to the copy of its
lexical parent or zero. All destination storage is prepared under private
heads and admitted with one storage_move_all; on any failure the prepared
storage is disposed, the destination heads and the source are untouched,
and out stays null.

Selftest (44 checks): source graph r0 -> s1 -> s2 plus an independent root
i0, with an int cell reached from two slots, a Structure reached through a
slot, a node link and a reference array, a back-reference cycle s2 -> s1,
an int Array, a char* cell and a size_t cell. Copy from s2 into another
owner with its own char table: r0/s1/s2/i0 copied, node links point at the
copies, the root's node is zero, i0's copy keeps node zero, cells and Array
backing are new with equal contents, the interned char maps into the
destination table, the METHOD pointer is identical, the shared int cell has
exactly one copy, writing the copy leaves the source at 7, source nodes and
slots unchanged. Same-owner copy shares the interned char cell and the
METHOD pointer while cells are new. Null arguments rejected. Allocation
failure injected at every allocation position (per-object -Dmalloc/-Dfree
substitution of the graph-lane objects; the selftest prints the number of
positions exercised): each returns NOMEM, out null, destination heads still
empty, live-allocation count unchanged; the first non-failing attempt
succeeds. Teardown releases every counted allocation.

Limits and obligations, explicit:
- Not integrated: Message creation still copies bytes only; no merge
  lowering in l2trans.lm1 yet. Grok wires create/set_graph to this API;
  merge lowering follows in the frontend (result root + ordered slots
  addressing the destination copies of operand fields).
- "Used" is the whole reachable lexical tree; no static narrowing yet.
- Zero-length Arrays are UNSUPPORTED (empty representation, ABI 14.3).
- A child value not in src_ranges is kept as a raw reference (foreign or
  unowned storage); nothing validates it.
- Shared METHOD descriptors currently live in Message-owned storage

  pointer is correct under the shared-method rule, but a copy that
  outlives its source Message must not dangle: the integration acceptance
  must include source teardown followed by invocation through the
  surviving copy, resolved within the shared-method model (static or
  otherwise longer-lived descriptor placement is the user's optional
  arrangement). Recorded from Codex 103916; not addressed by this
  checkpoint.
- lmx_message.lm1's collector walk is Grok's; the copier does not touch it.


Copier refinement (Fable) — 2026-09-12 10:55, after Codex 104635/104850
----------------------------------------------------------------------
API now:
  fn: lmx_graph_copy_many_owned (@@: Lmx sources; size_t: count;
      @: LmxOwnedRange src_ranges; @: LmxOwnedRange eternal_ranges;
      @: char dst_chars; @@: LmxMsgBlock dst_blocks;
      @@: LmxOwnedRange dst_ranges; @@: Lmx outs) int
  fn: lmx_graph_copy_owned (source, src_ranges, eternal_ranges, dst_chars,
      dst_blocks, dst_ranges, out) int      (count = 1 wrapper)

- One map spans the whole operation across all roots (merge with several
  operands): a Structure or cell reachable from two roots is copied once and
  both outputs refer to that one copy; outs[i] is the copy of sources[i].
- Eternal branches (user decision: independent: const: immutable published
  branches retained by the process root) are copy terminals. The caller
  supplies the root's retention ranges as eternal_ranges; any value found
  there, reached through a slot, an array element or a lexical chain, is kept
  by address, never traversed, cloned or node-rewritten; a copied Structure
  whose lexical parent is eternal gets that parent's own address as node. An
  eternal root itself is refused as a copy source (INVALID). The root
  retention array is never discovered or traversed by the copier.
- A child value classified by neither src_ranges nor eternal_ranges is no
  longer kept silently: the copy reports UNSUPPORTED and admits nothing.
  Explicit foreign-handle domains, when an L2 profile defines them, will need
  their own terminal rule; there is none yet. METHOD descriptors remain the
  one shared-by-pointer exception.
- Selftest now 55 checks: adds an eternal branch reached from the
  independent root (same pointer in the copy, node still zero, cell untouched,
  not classified in the destination), a two-root copy (s1, s2) with one map
  (copies linked, shared cell copied once, eternal terminal reached through
  both), refusals for an eternal root, for an unadmitted branch reference
  when no eternal ranges are given, and for a raw C address in a slot; the
  37-position allocation-failure sweep still passes.
- merge lowering is deliberately NOT started: the user asked to wait for
  Codex's comprehensive core/Message document, and the settled throw carrier
  (throws merge(args), status plus typed out-parameters) is not lowered yet;
  a source-visible merge failure will not be emitted as return 0.


Checkpoint publication failure (Fable) - 2026-09-12 11:16
---------------------------------------------------------
SPEC 21.6 / ABI 14.23, and Codex 111428 answering the open half of the
question: a failure to publish an already-bound dirty own field is CHECKPOINT
failure and takes the diagnostic assert route. Entry admission of a missing
field is a separate case and is untouched here.

l2_emit_checkpoint now emits, inside each field's "if dirty" block:
  - a guard for a null slot pointer: diagnostic line on stderr, then c.abort();
  - for char, a verification that the rebind produced a live cell, same route;
  - for int and size_t, the store-failure branch aborts instead of the previous
    silent "return: 0".
Nothing on the success path changed, so the graph is left exactly as it was
before a failed store. The previous lowering could return a normal result after
losing a published field; that is the behaviour this removes.

Still legacy at entry: the prologue's slot lookup emits "return: 0" when a
required own field is absent. That is admission, not checkpoint, and waits for
the typed result/throw carrier rather than being turned into an abort here.

Legacy Core units (same stage): lmx_branch/lmx_own/lmx_ref and their three
selftests are migrated to slots and pass. lmx_cell_init in lmx_range.lm1 still
builds a leaf Lmx with a payload; its callers are the range/pool selftests and
