mixa_audio_panel -- clean L2 port notes
==========================================

Ticket 20260913-232000/231500 Part 2, module 7 of 8.

Scope
-----
mixa_audio_panel.lm1 is the MP3 composed nested panel: a real nested
same-app window (mixa_app_window's own stack/frame/save-restore
mechanism, unmodified) showing the seven reference controls -- prevFile,
prev, pause/play, next, nextFile, random, repeat, in that exact order
with those exact stable labels -- as a real button panel, each wired to
its matching mixa_audio_action_* from mixa_audio_button. A real hit
dispatches exactly one matching action and preserves its exact status.
Below the controls, a redrawn progress/timer line shows play state,
position/duration, and the random/repeat flags, refreshed on every
mixa_audio_panel_poll call. Hitting the underlying window's own OK
button dismisses the whole panel and releases every owned allocation.
Ownership: MixaAudio itself is NOT owned by this panel (the caller
supplies and keeps it); only the MixaAudioButtonCtx wrapper and the
button panel belong to this struct. Scope is explicitly bounded: a
test-owned MixaAudio configured through mixa_audio_set_list only, no
directory/file-manager enumeration dependency (that is mixa_audio_scan/
mixa_audio_launch/mixa_audio_mp3's own separate stage).

The real mixa_audio_panel.lm1 predefs the full bodies of mixa_audio_
button.lm1 and mixa_app_window.lm1 directly (embedded into the same
translation unit), so neither side of this harness needs a separate
real dependency object.

mixa_audio_panel.lm1 and mixa_audio_panel.h.lm1 are the parity oracle
and were NOT modified. The chain it predefs (mixa_audio_button, mixa_
app_window) is a real, unmodified dependency, embedded unchanged.

L2 header (mixa_audio_panel_l2.h.lm1)
-----------------------------------------
Predefs mixa_audio_panel.h.lm1 directly, unmodified, the same way the
real .lm1 already does. Total distinct predef'd files: 1 (transitively
several more via the real header's own chain).

L2 body (mixa_audio_panel.lm2)
----------------------------------
Verbatim body copy of the real .lm1 (254 body lines, confirmed byte-
identical via diff), with only the FIRST predef line swapped for the L2
header; the body-level predefs of mixa_audio_button.lm1 and mixa_app_
window.lm1 (real, unmodified) are kept exactly as the real file has
them.

Barrier confirmed
------------------
Attempting the complete .lm2 translation with a scratch build of l2trans
fails with:

    l2trans error: mixa_manager/mixa_audio_panel.lm2:6:28: unknown foreign type

Line 6 is `fn: mixa_audio_panel_init (@: MixaAudioPanel p) int` -- column
28 is the start of `@: MixaAudioPanel p`, a custom struct in a plain
(non-const) `@:` parameter position. CONFIRMS-MATCHES the original,
most common closed-type-allowlist barrier shape -- not a new construct.

Oracle-side verification -- no filesystem, purely in-memory
------------------------------------------------------------------------
The parity harness (tests/mixa_audio_panel_parity_harness.lm1) reuses
the existing accepted mixa_audio_panel_selftest.lm1 verbatim: the real
MixaAudioPanel driven by a test-owned MixaAudio over a deterministic
fake device, with the progress line verified cell-by-cell against the
real rendered text rect (mixa_cell_at_const), never string-matched
output alone. No filesystem fixture of any kind (unlike this ticket's
own app_panel/app_win32 fixture-sharing bug discovered and fixed
earlier in this same ticket, this module has none to share). Covers:
opening pushes exactly one window with the exact expected progress
line, computed against this module's own documented geometry math;
nextFile/prevFile real track stepping vs. next/prev's own reference
+-1000ms bump (explicitly no track change); pause/play toggle gated by
real is_playing() with the progress line's own state word following;
random/repeat as real toggles with the progress line's own R:/L: words
following the controller state; a genuine miss inside the window
disturbing nothing; zero/unavailable duration rendering ".../--"; a
device-reported STOPPED mode driving a real end-of-track advance
through the same mixa_audio_poll mechanism as mixa_audio_selftest.lm1's
own T14; three independent backend-failure injections (position,
duration, mode) each propagating ERR_BACKEND WITHOUT corrupting the
last successfully drawn progress line (verified against a captured
snapshot of the exact prior line); dismiss through the real OK button;
width and height geometry exhaustion rejected before opening/painting
anything; and a reopen with a DIFFERENT MixaAudio instance showing no
stale ctx/status/progress carried over from the first instance's own
accumulated toggles and position.

Both real (oracle-side) verification runs completed and matched
