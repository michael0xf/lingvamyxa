mixa_copy L2 port (copy-chain ticket 20260913-185600, module 1 of 4:
mixa_copy, mixa_fm_copy, mixa_pump, mixa_process_win32)
==========================================================================

Scope
-----
Clean-L2 port of mixa_copy, the natural counterpart of the remove
chain: drives mixa_selection_walk over the accepted MixaSelection and
copies real file content through mixa_fileio into a destination tree.
Copy-only, no overwrite. Real failure modes covered: a destination
that already exists (file refused via real CREATE_NEW, directory
merged into silently), a destination inside the source refused up
front (structural NESTED failure, always stops descent regardless of
sink return), a real mid-file I/O fault (partial bytes cleaned up via
the deterministic MixaFioFaultVTable seam), and cancellation between
roots with the selection state left exactly where it can be retried.
1 public function (mixa_copy_run) plus 10 internal helpers, 356-line
real body.

No dedicated ABI probe pair
------------------------------
Like every prior "predef the real header directly" module this
segment, this port declares no L2-only struct of its own --
MixaCopySink/MixaCopyState are reached via the REAL mixa_copy.h.lm1
predef'd directly, identically on both the real oracle and this L2
port. No second struct layout exists to diff.

Barrier (current main) -- a GENUINELY NEW trigger shape
------------------------------------------------------------
l2trans error: mixa_manager\mixa_copy.lm2:19:1: incompatible entry
signature

Line 19 is mixa_copy_basename's own signature line: `fn: mixa_copy_
basename (const: @(char path)) const: @(char)` -- a plain function
taking a const char* parameter (a shape used without issue by dozens
of already-ported functions this whole session) and returning a
CONST-QUALIFIED pointer (`const: @(char)`). Isolated with a minimal
two-function fixture (no predef, no custom struct anywhere):

    fn: probe_plain_ret (const: @(char path)) @: char
    return: 0

    fn: probe_const_ret (const: @(char path)) const: @(char)
    return: 0

probe_plain_ret (non-const `@: char` return) translates cleanly.
probe_const_ret (const-qualified `const: @(char)` return) reproduces
the IDENTICAL diagnostic shape ("incompatible entry signature") on its
own signature line. This confirms the trigger is the const-qualified
POINTER RETURN TYPE itself, independent of any struct or fnptr
involvement.

This is diagnostically the SAME error text ("incompatible entry
signature") already cataloged for mixa_remove's bare fnptr-typedef
PARAMETER (ticket 20260913-171800), but the TRIGGERING CONSTRUCT is
different: a const-qualified pointer RETURN type versus a bare fnptr-
typedef PARAMETER. Recorded here as a fourth distinct barrier trigger
shape this whole session (after: custom-struct parameter; void-pointer
return; fnptr-typedef parameter), reported explicitly since it was not
yet cataloged. Confirmed identically across TWO separate runs of the
dedicated runner (byte-identical diagnostic, same line/column, both
runs) plus the standalone minimal-fixture reproduction above.
