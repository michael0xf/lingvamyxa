mixa_fileio_win32 L2 port (dependency-order continuation after mixa_
dir_win32)
==========================================================================

Scope
-----
Clean-L2 port of mixa_fileio_win32, the Win32 file content seam:
CreateFileW/ReadFile/WriteFile/CloseHandle, UTF-8<->wide conversion,
open-for-read, open-for-write (CREATE_NEW only, no overwrite -- the
first copy stage is explicitly without overwrite, refused by
CreateFileW itself via ERROR_FILE_EXISTS), and a deterministic
per-call fault-hook seam (MixaFioFaultVTable) that makes partial-write/
partial-read cleanup checks reproducible without racy OS conditions.
8 functions, 173-line real body.

No dedicated ABI probe pair
------------------------------
Like mixa_dir_win32 before it, this module declares no L2-only struct
of its own -- MixaFio and MixaFioFaultVTable are reached via the REAL
mixa_fileio_win32.h.lm1/mixa_fileio.h.lm1 predef'd directly,
identically on both the real oracle and this L2 port. No second struct
layout exists to diff.

Files (new)
-------------
- mixa_manager/mixa_fileio_win32_l2.h.lm1
    L2 ABI header. Predefs the REAL, unmodified mixa_fileio_win32.h.
    lm1 and mixa_fileio.h.lm1 directly -- mirrors the real oracle's own
    two predef lines exactly. Gives real MixaFio (handle/is_open) and
    real MixaFioFaultVTable/MixaFioFaultFn/MixaFioStatus plus every
    mixa_fio_*'s own real prototype. Total distinct predef'd files:
    mixa_fileio_win32.h.lm1, mixa_fileio.h.lm1 -- 2, nowhere near the
    pinned baseline's measured 16-file import-table cap.
- mixa_manager/mixa_fileio_win32.lm2
    The real 173-line body copied unchanged; all 8 functions preserved
    verbatim (mixa_fio_utf8_to_wide, mixa_fio_map_gle,
    mixa_fio_open_read, mixa_fio_open_write_new, mixa_fio_read,
    mixa_fio_write, mixa_fio_close).
- mixa_manager/tests/mixa_fileio_win32_parity_harness.lm1
    Real L1-vs-L2 harness (one source, compiled/linked twice, "declare
    then link"). All scenarios drawn directly from the existing,
    already-accepted mixa_fileio_selftest.lm1: write then read gives
    back the exact content; a second read at real EOF returns OK with
    0 bytes; an existing destination is refused under CREATE_NEW (real
    ERROR_FILE_EXISTS -> ERR_EXISTS); a missing source reports
    ERR_MISSING; a real chunked multi-read (64-byte buffer over a
    4000-byte file) reassembles the content correctly; the
    deterministic fault hook fires BEFORE each real I/O call with the
    real byte offset, its refusal is returned verbatim with no real
    I/O attempted for that call, and everything written before the
    fault is REALLY on disk (verified by reopening and reading it
    back); the same fault-hook shape on a real read; and argument
    negatives (null out/path/handle on every entry point) plus
    close(0)/double-close safety. 27 checks.
- mixa_manager/run_mixa_fileio_win32_l2_parity.ps1
    Dedicated runner. mixa_fileio_win32.lm1 predefs ONLY its own real
    header plus mixa_fileio.h.lm1 (both header-only, no bodies) -- this
    module sits at the bottom of the dependency stack (windows.h direct
    Win32 calls), so BOTH the oracle side and the L2 side compile a
    single real/generated object with no separate real dependency
    objects needed at all.
