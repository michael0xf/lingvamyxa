Scope
-----
Clean-L2 port of mixa_share_action: the Selection/Send button glue
(ClearShell "Send e-mail" reference: FSync.popSelectedListFroEmail,
ClearShell.sendEmail). Pops individually-selected FILES out of a
MixaSelection (deselecting each on success), leaves individually-
selected DIRECTORY entries untouched and still selected, then drives
exactly one MixaShareRequest through the given backend over those
files plus caller text. 1 public function (mixa_share_action_send)
plus 1 internal helper, 184-line real body.

No dedicated ABI probe pair, and no L1 header unit of its own
-------------------------------------------------------------------------
mixa_share_action.lm1 has no .h.lm1 counterpart anywhere in this
codebase -- its single public function is declared nowhere except by
direct forward-declare in whatever calls it (the same "declare then
link" pattern every harness this segment already uses). The L2 header
predefs the REAL mixa_share.h.lm1 directly (for MixaShareVTable/
MixaShareRequest) and reaches MixaSelection via a plain `include:` of
mixa_selection.h, proven safe by the established "`\` defers to gcc"
finding from ticket 20260913-151000 (mixa_app_controller) -- this
module's own real body dereferences sel\is_open/sel\selected_count/
sel\selected directly with no L1-level struct: declaration for
MixaSelection anywhere.
