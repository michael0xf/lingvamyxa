mixa_fm_copy L2 port (copy-chain ticket 20260913-185600, module 2 of 4:
mixa_copy done, mixa_fm_copy this module, mixa_pump and mixa_process_

==========================================================================

Scope
-----
Clean-L2 port of mixa_fm_copy: wires the accepted mixa_copy_run to the
file-manager view (mixa_fm_copy_selection, a thin call over the FM's
own borrowed MixaSelection, refreshing the FM's view only when the
destination is the directory currently being looked at); Copy Here (a
real button-shaped action, mixa_fm_copy_here_action/_hit, taking an
OWNED copy of the current directory before calling into the copy path
-- proven load-bearing by a real use-after-free regression, not just
documented); a Ctrl+V key-event trigger recognizing both accepted
spellings; a top-level pump-drain/dispatch unit; and a bounded native-
loop foundation (MixaAppLoop: open/step/running/close) that owns a
real backend+pump+fm+selection+ctx and drains at most one event per
tick, terminating on CLOSE. 10 public functions, 247-line real body.

No dedicated ABI probe pair
------------------------------
Like every prior "predef the real header directly" module this
segment, this port declares no L2-only struct of its own --
MixaFmCopyHereCtx/MixaAppLoop are reached via the REAL mixa_fm_copy.h.
lm1 predef'd directly, identically on both the real oracle and this L2
port. No second struct layout exists to diff.
