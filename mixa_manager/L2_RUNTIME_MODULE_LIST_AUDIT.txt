--- lmx_root_record: why it is not a list entry (this commit,
    sonnet/mixa-module-list, follow-up ticket)

The follow-up ticket read as "add lmx_root_record to the six lists,
nothing else." Checked first, before editing: l2src/lmx_root_record.lm1
does not exist (direct file test) -- only l2src/lmx_root_record.lm2 and
lmx_root_record.h.lm1 do. Every one of the six lists is consumed by an
l1trans-only loop (lib_l2_runtime_support.ps1:99-105 for headers,
:117-122 for modules -- l1trans invoked directly on l2src\<name>.lm1 for
each entry; the other five files' own list-copies follow the identical
shape). Adding the bare name as a plain list entry would make that loop
call l1trans on a file that is not there, throwing "L2 runtime module
lmx_root_record translation failed" before compile or link -- a THROW
again, not the "past link" this ticket's own part (2) expects.
run_port_message.ps1 itself never names lmx_root_record (grep -n
lmx_root_record on it prints nothing) -- the "support order" the ticket
pointed at is not literally in that file. Reported to lingvamyxa-6f
rather than guessed (this session's own stop-on-contradiction rule);
ruling: (b) -- wire the L2-native build step into lib_l2_runtime_
support.ps1, not a list entry.

The actual mechanism, found by dot-source search across l2src (grep -rl
Build-L2RuntimeUnits l2src/*.ps1): l2src/l2units_build.ps1's
Build-L2RuntimeUnits, already used by run_port_message.ps1:176-179 and
26 other l2src runners. It discovers L2-native runtime units itself (no
name list needed) -- every l2src/lmx_*.lm2 whose first line is "profile:
runtime" and has no sibling .lm1 -- and builds each through the L2
pipeline: l2trans.lm1->l2trans.exe once, then per unit: header via
l1trans (if a .h.lm1 exists), .lm2->generated .lm1 via l2trans.exe,
library/no-escape-poll checks, generated .lm1->.c via l1trans, gcc -c.
Confirmed directly (Build-L2RuntimeUnits' own discovery predicate, run
cold against this tree): exactly one unit qualifies today,
lmx_root_record.lm2 -- matching the ticket's own subject exactly, not a
broader set.
