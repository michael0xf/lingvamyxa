Note on this ticket's own scope description
------------------------------------------------
This ticket's own instruction 1 asks for coverage of "Windows drive
roots, separators, dot/dot-dot normalization" -- but the real, accepted
mixa_app_path.h's own header comment is explicit: "NO path policy of
any kind lives here: no normalization, no separator rewriting, no
MAX_PATH opinion, no Win32 long-path prefixing. Bytes in are bytes
out." This module is exact byte concatenation (memcpy of a then b),
nothing more. The parity harness below therefore exercises drive-root-
shaped and separator-shaped strings as opaque DATA (proving they pass
through completely unmodified, including a trailing separator, embedded
quotes, and non-ASCII bytes) rather than inventing normalization
behavior the real, accepted implementation does not have -- reported
here explicitly rather than silently porting something different from
what the oracle actually does.
