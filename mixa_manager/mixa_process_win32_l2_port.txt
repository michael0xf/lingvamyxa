mixa_process_win32 L2 port (copy-chain ticket 20260913-185600, module
4 of 4 -- the LAST module in the standing list)
==========================================================================

Scope
-----
Clean-L2 port of mixa_process_win32: the concrete Win32 owner-local
process seam behind the portable mixa_process.h API (PROCESS_SEAM.txt
section 3). Merged stdout+stderr via one pipe; shell delegation
(spawn() wraps the caller's command as `cmd.exe /c "<command>"`, so an
unknown command is an ordinary started shell child, not a spawn
failure); a real stdin pipe in BOTH modes (disabled mode closes our
own write end right after spawn so the child sees genuine pipe EOF,
never an invalid handle); a Job Object with JOB_OBJECT_LIMIT_KILL_ON_
JOB_CLOSE so kill()/close() terminate the whole descendant tree, not
just the direct child. 6 public functions (spawn/read/write/status/
kill/close) plus internal helpers, 455-line real body.

No dedicated ABI probe pair, and NO L1 header unit to predef at all
-------------------------------------------------------------------------
Like mixa_pump.h immediately before it, mixa_process_win32.h has no L1
.h.lm1 counterpart anywhere in this codebase -- real, plain, hand-
written C. MixaProcess is fully opaque to every caller: the real body
never dereferences a field of it from outside mixa_process_win32.lm1
itself, so this port does not even need the established `\`-defers-
to-gcc pattern -- callers only ever hold and pass the pointer. 0
distinct predef'd files.
